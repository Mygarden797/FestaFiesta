# 유료 프로그램 예약 시스템 — 설계 초안과 후속 작업

- 작성일: 2026-08-06
- 상태: **규칙은 사용자 확정, 구현 미착수.** 아래 "결정된 규칙"은 확정이고 "설계 판단"은 초안이다.
- 배경: 팀 시설 네이밍 규칙 페이지의 태그 목록에 `예약 필요`가 있다. 지금 Utility AI는 이 태그를 모르고, NPC가 예약 없이 사전예약 시설에 그냥 들어간다.
- 관련: `facility_naming_convention.md` 5.4, `utility_ai_spec.md` §2·§9, `crowdai_handoff_note.md`

## 1. 결정된 규칙 (사용자 확정, 2026-08-06)

1. **플레이어가 시설을 세울 때 타임테이블 작업으로 유료 프로그램을 산다.**
2. **프로그램을 사면 예약이 자동으로 꽉 찬다.** 정원만큼의 예약이 즉시 확정된다 — 플레이어가 개별 NPC를 배정하지 않는다.
3. **정원만큼의 NPC는 프로그램 시작 시각 전에 반드시 월드에 있어야 한다.** 예약자가 아직 입장하지 않아 정원이 비는 상황은 없다.
4. **예약 NPC 외에는 그 시설에 들어갈 수 없다.**
5. **정원만큼의 NPC는 프로그램 진행 시간 동안 그 장소에 계속 있어야 한다.** 중간에 다른 곳으로 가지 않는다.

## 2. 이 규칙이 기존 구조에 만드는 충돌

규칙 자체는 단순한데, 지금 구조의 **세 가지 전제를 깬다.** 구현 전에 이걸 알고 있어야 한다.

### 2.1 "NPC는 매 재평가마다 자유롭게 목적지를 고른다"가 깨진다

규칙 5는 예약자가 프로그램 시간 동안 **재평가를 하지 않아야** 한다는 뜻이다. 지금 `ShouldReevaluate`는 대기·밀집·주기·개폐 변화를 보고 true를 돌려주는데, 예약자에게는 그 전부를 무시해야 한다.

**더 깊은 문제**: `no_choice → Leave`가 예약자에게 발동하면 프로그램 중에 퇴장한다. 리더가 퇴장하면 그룹 전체가 퇴장하므로(`population_group_generation_spec.md` 3절 항목 8), **예약자 한 명 때문에 정원이 여러 명 비는 것도 가능하다.**

→ 예약자에게는 `ShouldReevaluate`와 `ResolveNoChoiceAction` 둘 다 우회하는 **잠금 상태(lock)**가 필요하다.

### 2.2 "체류시간이 다 되면 퇴장한다"와 충돌한다

`remaining_stay`가 프로그램 종료 전에 0이 되면 규칙 5(끝까지 있어야 함)와 규칙에 없는 퇴장 규칙이 정면 충돌한다. 둘 중 하나가 이겨야 한다.

### 2.3 "그룹은 통째로 움직인다"와 예약 단위가 안 맞는다

그룹은 1~6인이고 통째로 입장·이동·퇴장한다. 정원이 10명인 프로그램에 3인 그룹을 배정하면 9명이 되고, 4인 그룹을 넣으면 13명으로 초과한다. **정원을 정확히 채우는 것과 그룹을 쪼개지 않는 것이 동시에 성립하지 않을 수 있다.**

### 2.4 유입 곡선 제약이 된다

규칙 3은 "이 시각 전에 반드시 N명 입장"이라는 **하드 제약**이다. 지금 유입 곡선(`visitor_arrival_curve_v0`)은 비율 목표일 뿐이고 crowdAI가 자유롭게 타이밍을 정한다. 예약이 생기면 그 자유도가 줄어든다 — 프로그램이 여러 개면 제약이 여러 개 걸린다.

## 3. 설계 판단 (초안 — 확정 아님)

### 3.1 예약 단위는 **그룹**으로 한다

이유: 개인 단위로 하면 4인 가족 중 1명만 예약자가 되어 나머지 3명이 프로그램 시간 동안 밖에서 기다린다. 그룹은 통째로 움직이는 것이 전제(`spawn_group_together`, 리더 상속, 통째 퇴장)이므로 예약도 그룹 단위가 일관된다.

**대가**: 정원을 정확히 못 채운다. 2.3의 문제다. → **정원 이하로 채우고 남는 자리는 비운다**를 제안한다. 초과하는 것보다 낫다(시설 정원은 안전 제약이기도 하다).

### 3.2 예약은 "슬롯"이 먼저 생기고 그룹이 배정된다

프로그램을 사는 시점(Setup 단계)에는 NPC가 아직 스폰되지 않았을 수 있다. 그래서 예약을 개체에 붙이지 않고 **슬롯 목록**으로 먼저 만든다.

```text
FFF_ProgramReservation {
    FacilityInstanceId       어느 시설
    StartMinutes / EndMinutes   Live 경과분 기준 (절대 시각 아님 — 유입 곡선과 같은 규칙)
    Capacity                 정원
    AssignedGroupIds         배정된 그룹 (정원 이하)
    AssignedHeadcount        실제 배정 인원
}
```

`StartMinutes`를 Live 경과분으로 두는 이유: `visitor_arrival_curve_spec.md`가 절대 시각 대신 진행도를 쓰는 것과 같다 — Live 길이가 바뀌면 절대 시각은 틀린 값이 된다.

### 3.3 배정은 결정적이어야 한다

같은 Seed면 항상 같은 그룹이 예약자가 되어야 한다(`FMath::Rand()` 금지 — 이 프로젝트 전역 규칙). 배정 기준 후보:

- 취향 일치도 순 (`craft_experience` 선호가 높은 그룹이 웰니스 체험을 예약) — 그럴듯하고 데이터가 이미 있다
- 입장 순서 순 — 가장 단순
- 아키타입 필터 (아동 있는 그룹은 성인 전용 프로그램 제외)

**취향 일치도 순을 제안한다.** `preference_vector`가 이미 있고, "이 프로그램을 살 만한 사람이 예약한다"가 자연스럽다.

### 3.4 잠금 상태를 `EFF_NoChoiceAction`과 같은 층에 둔다

예약자는 프로그램 시간 동안 목적지 선택 자체를 하지 않는다. `Choose()`를 부르기 전에 호출부가 걸러야 한다 — selector에 예약 개념을 넣으면 순수 함수성이 깨진다(지금 selector는 `bIsOpen` 하나로 폐쇄 이유를 모르는 것과 같은 원칙).

```text
if (Party has active reservation at now) → 목적지 = 그 시설, 재평가 없음, 이동 명령 없음
else → 기존 흐름 (ShouldReevaluate → BuildCandidates → Choose)
```

## 4. 후속 작업 (todo)

### 4.1 김시리 담당 — 지금 착수 가능

- [ ] **`FFF_ProgramReservation` 구조체 + 예약 배정 순수 함수** — 프로그램 목록(시설·시작·종료·정원)과 그룹 목록을 받아 결정적으로 배정. `FFF_VisitorDistributionBuilder`와 같은 스타일(순수 함수 + 테스트)
- [ ] **`BuildCandidates`에 예약 필터 추가** — `예약 필요` 시설은 그 Party가 예약을 갖고 있지 않으면 후보에서 제외. `bIsOpen`과 같은 자리에서 처리
- [ ] **잠금 경로** — 예약이 활성인 Party는 `ShouldReevaluate`/`Choose`/`ResolveNoChoiceAction`을 아예 건너뛴다. 이건 L3 런타임 층의 일이라 그 층 설계에 포함
- [ ] **`no_choice → Leave`가 예약자에게 발동하지 않게 막기** — 2.1의 문제. 리더 퇴장이 그룹 전체 퇴장이라 정원이 여러 명 비는 것을 막아야 한다
- [ ] **경제 연동** — 프로그램 구매가 Gold를 소모하고 매출을 만든다. `무료/유료` 태그와 같은 대상. 경제 파트 착수 시 같이 설계

### 4.2 합의 필요 — 다른 파트

- [ ] **유입 곡선에 "하드 제약" 개념 추가** (이정원) — "프로그램 시작 전까지 이 그룹들은 반드시 입장" 제약을 곡선 위에 얹어야 한다. 프로그램이 여러 개면 제약도 여러 개다. 곡선 누적 오차 허용 폭과 충돌할 수 있다
- [ ] **`예약 필요` 태그를 어디서 읽는가** (한광훈) — `UFFZSFacilityDefinition`의 필드인가, 별도 DataTable인가. `GetServiceRatePerMinute`처럼 Asset Manager 조회가 되는가
- [ ] **정원의 의미** (한광훈) — 시설의 `Capacity`(동시 수용)와 프로그램 정원이 같은 값인가 다른 값인가. 다르면 어느 쪽이 예약 정원인가
- [ ] **타임테이블 UI** (백종태) — 플레이어가 프로그램을 사는 화면. 예약 현황·정원·시간을 보여줘야 한다
- [ ] **Queue와의 관계** (장원재) — 예약 시설은 줄을 서지 않는다(예약자만 들어가므로). `대기열 필요` 태그와 같은 문제다

### 2번 결정됨 (사용자 확정, 2026-08-10) — ③ 체류시간 연장

예약이 확정되는 시점에 체류시간을 늘린다:

```
RemainingStayMinutes = max(RemainingStayMinutes, (프로그램 종료시각 - 현재시각) + 이탈버퍼)
```

**왜 ③인가**
- ②(중간 퇴장)는 정원이 비고, 그룹 단위라 최대 6명이 한꺼번에 빠진다 → **매출 계산이 비결정적이 된다.** 경제 파트가 이 값을 입력으로 쓰므로 탈락
- ①(프로그램 우선)은 "체류시간은 끝났지만 아직 잡혀 있음" 상태 플래그가 추가로 필요하고, 프로그램이 끝난 뒤 그 NPC가 즉시 퇴장인지 재평가인지를 또 정해야 한다
- ③은 숫자 하나만 늘리면 끝이고, **현실 행동과도 맞는다** — 공연을 예매한 사람은 실제로 그때까지 머문다

**부작용과 대응**: 예약자만 체류시간 분포가 길어진다. "예약으로 연장된 분"을 따로 집계해 로그에 남기면 나중에 분포 왜곡을 진단할 수 있다.

`이탈버퍼` 기본값은 아직 정하지 않았다(`draft_assumption`). 프로그램 종료 직후 바로 사라지면 부자연스러워서 두는 값이다.
