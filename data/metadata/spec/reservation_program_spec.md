## 2. 자료구조와 순수 함수 (구현 완료)

`FF_ProgramReservation.h` — 상태를 갖지 않고, 같은 입력이면 항상 같은 결과다.
예약 목록을 들고 구매 흐름을 태우는 것은 `UFF_FestivalProgressionSubsystem` 이다(§5).

```text
FFF_ProgramReservation          시설·시작·종료·정원 + 배정 결과(AssignedGroupIds·인원·빈자리)
FFF_ReservationCandidateGroup   GroupId · MemberCount · PreferenceScore

Assign(InOut, Candidates)       정원에 그룹을 배정한다
IsLockedAt(Reservation, Now)    목적지 선택을 건너뛰어야 하는가
IsExitBlockedAt(Reservation, Now)  퇴장이 금지되는가
ApplyExitGrace(Current, Grace)  종료 시 체류 예산 유예
```

**배정 결과를 예약 안에 넣은 이유**: 처음에는 별 구조체로 뺐는데, 그러면 런타임이
**"이 그룹이 지금 예약 있나?"를 물을 방법이 없다.** 테스트만 통과하고 실제로는 못 쓰는 API 였다.

**시각은 전부 Live 경과분**이다. 절대 시각으로 두면 Live 길이가 바뀔 때 틀린 값이 된다
(`visitor_arrival_curve_spec.md` 와 같은 규칙).

### 2.1 정원 채우기는 greedy 가 아니라 유계 배낭 DP

greedy 는 **정원을 정확히 채우지 못한다.** 정원 8 에 후보가 5·4·4 뿐이면 5 를 먼저 담고
4 가 안 들어가 3 자리를 남기지만 정답은 4+4 다. 규칙 5가 확정이므로 이 실패를 받아들일 수 없다.

그룹 크기(1~6)별로 묶으면 상태 공간이 `정원 × 6` 으로 작아서 후보 수에 지수로 늘지 않는다.
개체 단위 subset-sum 이 비싼 것이고 **크기별로 묶으면 싸진다.**

- 목표는 취향 합 최대화. 각 크기 안에서는 취향 내림차순으로 앞에서부터 쓴다
- 같은 점수면 먼저 계산된 조합을 유지해 결정성을 보장한다(갱신 조건이 `>`)
- 정확히 채우는 조합이 없으면 가장 많이 채우고 `UnfilledSeats` 가 0 보다 커진다.
  호출부가 로그를 남긴다 — 조용히 넘기면 플레이어가 산 정원보다 적게 받은 것을 아무도 모른다

⚠️ **`GroupId` 가 실행마다 같아야 한다.** 정렬 타이브레이커라서, 스폰 순서처럼 프로세스마다
달라지면 **같은 시드인데 예약자가 바뀐다**(8/10 `MakeTraitSeed` 버그와 같은 종류).
v0 은 `PreferenceScore` 가 전부 0 이라 **순서가 전적으로 이 값으로 결정된다.**

## 3. 잠금과 퇴장 금지는 구간이 다르다

**이 둘을 같은 것으로 취급하면 버그다.** 초안이 그래서 자유 행동 구간의 퇴장을 못 막았다.

| 구간                            | 재평가        | 퇴장     | 체류 예산 드레인 | Need 증가 |
| ----------------------------- | ---------- | ------ | --------- | ------- |
| 확정 ~ `StartMinutes`           | 한다 (자유 행동) | **금지** | 돈다        | 쌓인다     |
| `StartMinutes` ~ `EndMinutes` | 안 한다 (잠금)  | 금지     | **멈춘다**   | 쌓인다     |
| `EndMinutes` 이후               | 한다         | 가능     | 돈다        | 쌓인다     |

**왜 자유 행동 구간이 위험한가** — 그 구간에는 드레인이 계속 돌아서 체류 예산이 시작 전에
마를 수 있다:

```text
예약 확정 10분, 프로그램 100~160분, 체류 예산 150분
자유 행동 90분 동안 배수 2.0 으로 한계 Need 유지 → 180분 소모
  → 시각 85분에 예산 0 → 퇴장 금지가 없으면 시작 전에 나가고 정원이 빈다
```

막는 대상은 **퇴장 판정 두 경로 전부**다 — 체류 예산 소진과 연속 `no_choice`.
예산은 0 에서 멈춘다(음수면 종료 직후 즉시 사라진다). 종료 후 남는 시간은 `ApplyExitGrace` 가
만든다 — **그래서 이탈유예가 실질적 의미를 갖는다.** 기본값 0 이면 예산이 마른 예약자는
종료 시각에 곧바로 퇴장한다.

**잠금 중 드레인을 멈추는 대가**(사용자 확정): 1~2시간 화장실을 못 간 개체가 종료 시점에
Need 한계인데도 예산이 멀쩡해서 한참 더 머문다. 규칙 9(Need 는 계속 쌓임)와 합쳐지면
**종료 직후 화장실·식음료 쏠림이 커진다** — 관측하고 판단하기로 한 사항이다.

**잠금 상태는 selector 밖에 둔다.** `Choose()` 를 부르기 전에 호출부가 거른다 —
selector 에 예약 개념을 넣으면 순수 함수성이 깨진다(지금 selector 가 `bIsOpen` 하나로
폐쇄 이유를 모르는 것과 같은 원칙).

## 4. 귀환 안전장치 — **v0 범위 밖 (파킹)**

시작 전 자유 행동 중 너무 멀리 갔다가 시간을 못 맞추는 것을 막는 장치다.
강제 순간이동은 쓰지 않는다 — 관찰 게임에서 NPC 가 사라졌다 나타나는 것은 눈에 보이는 사고다.

**1차 (파킹)** — `FFF_ProgramReservationReturnTrip::Evaluate`, 별 파일 + 테스트 6개.

```text
필요 분 = (현재 → 후보 이동) + 대기 + 이용 + (후보 → 예약 시설 이동)
가용 분 = (시작 시각 - 현재) - 귀환 여유
후보 유지 = 필요 분 <= 가용 분
```

**켤 수 없는 이유는 하나뿐**이다: `EstimatedWaitMinutes` 가 0 이라(Queue 어댑터 결선 전)
"줄이 없다"로 계산된다. **켜면 "금방 다녀올 수 있다"고 통과시켜 놓고 실제로는 줄에 걸려
늦으므로, 켜는 것이 오히려 지각을 늘린다.**

판정 불가(예약 없음 / 속도 0)일 때는 **후보를 남긴다(fail-open).** 대기열 어댑터의
fail-closed 와 반대인데 이유가 다르다 — 후보를 전부 닫으면 `no_choice` 2회 → `Leave` 이고,
리더가 나가면 그룹 전체가 나가 정원이 여러 명 빈다. **지각보다 퇴장이 나쁘다.**

거리→시간 환산에 쓰는 보행 속도는 crowdAI 의 `FUnitData::Speed`(150 cm/s = 1.5 m/s)를
그대로 옮긴 값이다(계수 `npc_walk_speed_mps`). 내가 만든 상수가 아니다.

### 🔴 켤 때 같은 커밋에 넣어야 하는 것

1차 필터는 시작 시각이 가까워지면 `가용 분`이 0 으로 수렴해 **후보를 전부 비운다.**
후보 0개는 `no_choice` 이고 2회면 `Leave` 다 — **안전장치가 그 자체로 사고를 만드는 경로다.**

그래서 **"판정은 했는데 통과 후보가 0개"면 그 즉시 잠금으로 넘긴다.**
시각 기준(`StartMinutes - 버퍼`)으로 잡으면 버퍼 기본값이 0 이라 방어가 되지 않는다.
원인 자체를 보는 조건이라야 계수와 무관하게 성립한다.

**2차 (하드 데드라인)** — 잠금이 걸리면 예약 시설로 향한다. 위치를 덮어쓰지 않는 정상 이동이고,
늦게 도착하면 늦게 참여한다.

## 5. 아직 안 만든 것

### 5.1 배선 — `UFF_FestivalProgressionSubsystem` (경제 S8)

구매가 Gold 차감이고 기획서 §7 이 경제·진행을 한 소유자로 두므로,
**차감과 배정이 한 트랜잭션**이어야 한다.

| 만들 API                                                              | 쓰는 쪽                   |
| ------------------------------------------------------------------- | ---------------------- |
| `TryPurchaseProgram(Program, CostGold, Candidates, OutReservation)` | 타임테이블 UI               |
| `GetReservations()` + `OnReservationsChanged`                       | 타임테이블 UI               |
| `IsGroupLockedAt(GroupId, Now)`                                     | L3 — 매 재평가             |
| `IsGroupExitBlockedAt(GroupId, Now)`                                | L3 — 퇴장 판정 **두 경로 모두** |
| `GetLockedFacilityForGroup(GroupId, Now)`                           | L3 — 잠금 중 목적지 고정       |
| `ClearReservations()`                                               | 새 축제·새 날               |

**차감 순서**(기획서 §6.1): 검증 → 잔액 확인 → 배정 → 성공 시 1회 차감 → 등록.
배정이 0명이면 Gold 를 건드리지 않는다(AT-003·AT-004).
구매 실패는 이유를 구분해야 한다(정원 무효 / 잔액 부족 / 슬롯 중복 / 배정 가능 그룹 없음) —
UI 가 "왜 못 샀는지"를 표시해야 해서 bool 하나로는 못 한다.

### 5.2 나머지

- **`BuildCandidates` 에 예약 필터** — `예약 필요` 시설은 그 Party 가 예약을 갖고 있지 않으면
  제외한다. 태그 출처(한광훈)가 정해지면 카테고리·상태 필터 옆에 붙인다
- **L3 잠금 경로** — 예약 활성 Party 는 `ShouldReevaluate`/`Choose`/`ResolveNoChoiceAction` 을
  건너뛴다. L3 설계에 포함
- **`no_choice → Leave` 를 예약자에게 막기** — §4 의 "후보 0개 → 잠금"과 별개다.
  이건 다른 이유로 `no_choice` 가 났을 때의 그물이다
