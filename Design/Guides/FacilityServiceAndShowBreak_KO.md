# 시설 이용시간과 공연 전 운영 중지

2026-09-29 적용 규칙

- 일반 시설 이용시간은 팀당 5초다. 시설 정의의 `QueueRules.ServiceDurationSeconds`는 5, 강화 단계의 `ServiceDurationMultiplier`는 1이다. 동시 이용 1팀 시설의 처리량은 분당 12팀이며, 운영 패널은 실제 이용시간을 `팀당 5초`로 표시한다. 프로그램 편성의 개최 시간·참가비는 별도다.
- 게임 화면 시계 기준 메인 공연 3분 전부터 공연 종료까지 일반 시설 대기열에 새로 들어갈 수 없다. 20:00 공연이면 19:57부터 적용한다. 현재 시간 변환은 Stage 경과 1초 = 화면 시계 1분이다.
- 중지 시점에 서비스가 시작된 팀은 이용 완료로 처리하고 기존 매출 공식으로 한 번 정산한다. 아직 기다리거나 자리로 이동 중인 팀은 과금 없이 취소한다.
- 완료·취소 이벤트를 먼저 전달한 뒤 관객의 공연장 이동을 처리한다. 프로그램 예약 우선순위와 실제 보행은 유지한다.
- 공연 종료 시 임시 대기열 중지가 풀린다. 별도로 폐쇄된 시설은 계속 닫혀 있다. 배속 잠금 시점은 이 중지 시점과 다르다.
- 대기열 자리와 공연 관람석은 배정된 좌표의 5cm 안까지 직접 걸어간다. 자리 주변에서는 감속 거리를 줄이고, 서로 겹치지 않는 자리를 배정받은 NPC 사이의 개인 공간 반발만 완화한다. 신체 접촉·벽·일반 통행자 회피는 유지한다.
- 시설 벽 옆의 유효한 자리도 끝까지 접근할 수 있다. 현재 위치에서 목표까지 몸체와 도착 오차를 포함한 공간이 확보된 구간에 한해서 벽의 개인 공간 반발을 완화한다. 벽 너머 목표와 실제 접촉에는 이 예외를 적용하지 않는다.
- 좁은 U자 대기열에서는 리더의 저작 좌표를 유지하고 동행만 정해진 범위 안의 겹치지 않는 위치를 사용한다. 새 팀이 들어와도 기존 팀의 배정 위치는 바뀌지 않는다. 현재 자리부터 앞쪽 이용 자리까지 팀 전원이 설 수 있어야 입장하며, 공간이 부족한 팀은 입장을 보류한다.
- 공연 관람석은 리더와 동행 모두 개별 좌표·무대 방향을 사용한다. 전원이 자기 좌석에 도착해야 대기·관람 상태로 전환한다. 좌석에서 수 미터 떨어진 곳을 도착으로 처리하지 않는다.
- 좌석 배정 시 이전 경로를 지우며, 해당 공연에 도착할 수 없어 좌석이 회수된 파티를 같은 공연에 반복 배정하지 않는다. 다음 공연에는 다시 참여할 수 있다.

2026-10-09 추가 규칙

- 메인 공연 휴지 구간(3분 전~종료) 동안 흐른 시간은 줄 인내 판정의 대기 시간에서 뺀다(`QueueBreakSimSeconds`/`QueueBreakSecondsAtEnter`). 공연 때문에 멈춘 줄에서 손님이 인내 초과로 이탈하지 않는다.
- `UFF_QueueSubsystem::Tick`은 축제 실효 배속(`GetEffectiveTimeScale`)을 따른다. 위 `팀당 5초`는 배속과 관계없이 Stage 시간 기준이다. 전에는 실제 시간으로만 흘러 4배속에서 서비스가 손님 기준 4배 느렸다.
- 손님 보행 속도 배수 `GuestWalkSpeedScale`은 1.6이다(150cm/s × 1.6 = 2.4m/s).

시설 데이터 변경 도구: `Tools/facilities/migrate_facility_service_duration.py`.
기본 실행은 감사이며 `-FFApplyFiveSecondFacilityServices` 지정 시 저장한다. 원본 백업, 이전·이후 이용시간, 그 밖의 시설 속성 보존 결과는 `Saved/FacilityServiceDuration5Seconds`에 기록한다.
