# 메인 공연장 조명 수정 가이드

작성일: 2026-09-10 · 대상: FestaFiesta 메인 공연장 제작자

공연장을 설치하면 실제 조명이 함께 켜지도록 연결했습니다. 램프 하나의 배치는 Blueprint에서, 새 공연장의 전체 기본 밝기는 PDA에서, 이미 설치한 공연장의 조명은 게임 안 시설 정보창에서 변경할 수 있습니다. 화면은 실제 UMG Widget Blueprint로 제작되어 Designer에서 수정할 수 있습니다.

## 무엇을 어디에서 바꾸나요?

공연장의 모양, 실제로 비추는 빛, 화면의 조작 버튼은 서로 다른 파일에 들어 있습니다. 바꾸려는 내용에 맞는 파일 하나를 열면 됩니다.

| 바꾸려는 내용 | 여는 파일 | 역할 |
|---|---|---|
| 공연장 외형 | `SM_MainStage_Grand` | 무대·지붕·스피커·조명 기구의 3D 모양입니다. |
| 램프 하나의 위치·방향·밝기·색 | `BP_MainStage_Grand_Lighting` | 실제 빛을 내는 조명들을 담은 묶음입니다. |
| 새로 설치할 공연장의 기본 전체 밝기 | `PDA_FFZS_Performance_MainStage_SunsetMainStage` | 시설 종류의 기본 설정표입니다. |
| 이미 설치한 공연장 한 개의 조명 | 게임 안의 시설 정보창 → 조명 설정 | 선택한 공연장에만 적용하는 설정입니다. |
| 조명 설정창의 글자·색·크기·배치 | `WBP_FF_FacilityLightingControls` | UMG Designer에서 편집하는 화면입니다. |

`SM`은 3D 모양, `BP`는 기능을 가진 Blueprint, `PDA`는 기본 설정표, `WBP`는 화면용 Blueprint를 뜻합니다. 파일 이름을 외울 필요는 없습니다. 콘텐츠 브라우저의 검색 칸에 위 이름을 붙여 넣으면 찾을 수 있습니다.

## 먼저 알아둘 기본값과 개별 설정의 차이

PDA의 기본값은 새 공연장을 설치할 때 사용하는 출발점입니다. 게임에서 밝기를 변경하는 것은 선택한 공연장의 설정을 변경하는 일입니다. 여러 공연장을 같은 색과 밝기로 시작시키려면 PDA를 편집하고, 공연장 한 개만 다르게 하고 싶으면 게임의 조명 설정창을 사용합니다.

시설 상태를 저장하는 데이터에는 설치 당시 시설 설정이 들어 있습니다. PDA를 바꾼 뒤 이전 시설 상태를 복원하는 것과 새 공연장을 설치하는 것은 결과가 다를 수 있습니다. 기본값 변경을 확인할 때는 새 설치로 먼저 확인하세요. 게임의 초기화 버튼은 그 공연장을 설치할 때의 기본값으로 되돌립니다. 나중에 편집한 PDA 값을 기존 공연장에 덮어쓰는 기능은 아닙니다.

## 1. 설치했을 때 자동으로 조명이 켜지게 하기

1. 언리얼 에디터에서 콘텐츠 브라우저를 엽니다.
2. `PDA_FFZS_Performance_MainStage_SunsetMainStage`를 검색해 더블클릭합니다.
3. `Facility Specification` 안의 `Visual Mesh`가 `SM_MainStage_Grand`인지 확인합니다.
4. `Facility Lighting`을 펼칩니다. `Lighting Rig Class`에 조명 Blueprint를 지정하고, `Lighting Enabled`를 켭니다.
5. `Brightness Multiplier`를 기본값인 `1.0`으로 두고 저장합니다. `Override Color`를 끄면 각 램프의 고유 색을 유지합니다.
6. 게임을 실행해 새 공연장을 설치합니다. 바닥과 무대 표면에 빛이 보이는지 확인합니다.

빛이 잘 보이지 않으면 어두운 시간대 또는 그늘에서 확인해 보세요. 밝은 낮에는 정상적으로 켜진 조명도 차이가 작게 보일 수 있습니다.

## 2. 전체 밝기를 한 번에 바꾸기

PDA의 `Brightness Multiplier`는 각 램프의 원래 밝기에 곱하는 배수입니다. 범위는 `0.0~5.0`이며, 게임에서는 `0~500%`로 표시합니다.

| 전체 밝기 배수 | 의미 |
|---:|---|
| `0.0` | 빛의 밝기를 0으로 만듭니다. |
| `0.5` | 원래 밝기의 절반입니다. |
| `1.0` | Blueprint에서 정한 원래 밝기입니다. |
| `2.0` | 원래 밝기의 두 배입니다. |

예를 들어 Blueprint의 램프가 10,000이고 전체 밝기 배수가 `0.5`라면, 게임에서 적용되는 밝기는 5,000입니다. 공연장 전체가 너무 밝을 때는 모든 램프를 하나씩 고칠 필요 없이 전체 밝기부터 낮추면 됩니다.

## 3. 램프 하나를 직접 수정하기

1. 콘텐츠 브라우저에서 `BP_MainStage_Grand_Lighting`을 엽니다. 위치는 `Content/Asset/FacilitiesAsset_HKH/Performance/MainStage_Grand_20260909`입니다.
2. 왼쪽 `Components` 목록에서 수정할 `Spot Light`를 선택합니다.
3. 가운데 `Viewport`에서 위치와 빛의 방향을 확인합니다.
4. 오른쪽 `Details`에서 필요한 값만 수정합니다.
5. 상단의 `Compile`을 누른 다음 `Save`를 누릅니다.
6. 게임을 다시 실행해 실제 설치한 공연장에서 확인합니다.

| 설정 이름 | 쉽게 설명하면 | 사용할 때 |
|---|---|---|
| `Location` | 램프의 위치 | 지붕 아래 또는 무대 가장자리로 옮길 때 |
| `Rotation` | 빛을 향하게 할 방향 | 관객 쪽, 무대 중앙, 바닥을 비출 때 |
| `Light Color` | 빛의 색 | 청록·주황·흰색 등으로 바꿀 때 |
| `Intensity` | 램프 하나의 원래 밝기 | 특정 램프만 밝거나 어두울 때 |
| `Outer Cone Angle` | 빛이 퍼지는 각도 | 좁게 집중시키거나 넓게 비출 때 |
| `Inner Cone Angle` | 밝은 중심 부분의 각도 | 중심과 가장자리의 차이를 조절할 때 |
| `Attenuation Radius` | 빛이 닿는 거리 | 빛이 너무 짧거나 멀리까지 닿을 때 |

`Inner Cone Angle`은 `Outer Cone Angle`보다 작거나 같게 설정합니다. 위치와 거리는 언리얼의 cm 단위입니다. 예를 들어 1,000cm는 10m입니다.

광원의 방향을 돌리면 빛의 방향이 바뀝니다. 무대 메시 안에 들어 있는 조명 기구의 모양까지 자동으로 움직이는 것은 아닙니다. 움직이는 조명 기구 자체를 만들려면 해당 3D 부품을 별도 메시로 분리하는 작업이 필요합니다.

조명 Blueprint의 `PreviewStageMesh`는 조명 위치를 맞추기 위해 에디터에서 보는 무대 모형입니다. `Editor Only`와 `Hidden in Game`이 설정되어 있습니다. 게임에서는 PDA의 `Visual Mesh`가 무대를 표시하므로, 조명 Blueprint에 런타임용 무대 메시를 추가할 필요가 없습니다.

현재 실제 광원은 10개입니다. `Overhead_*` 6개는 지붕 아래, `DeckSpot_*` 2개는 무대, `RunwaySpot_*` 2개는 돌출 무대의 조명입니다. Components 검색 칸에 이 이름 일부를 넣으면 원하는 조명을 빨리 찾을 수 있습니다.

## 4. 게임에서 공연장 한 개의 조명을 바꾸기

게임에서 공연장을 선택해 시설 정보창을 엽니다. 정보창의 내용을 아래로 스크롤하면 `무대 조명` 카드가 나타납니다. 배치 화면과 운영 화면에서 사용할 수 있으며, 조명 Blueprint가 연결된 시설에 표시됩니다. 조명 설정은 선택한 공연장에 적용합니다. 다른 공연장을 선택하면 그 공연장의 현재 설정을 보여 줍니다.

- `켜짐 · 끄기` 또는 `꺼짐 · 켜기`: 전체 광원을 끄거나 켭니다.
- 밝기 슬라이더: 선택한 공연장의 밝기를 `0~500%` 사이에서 변경합니다.
- 원래 색상: Blueprint에서 지정한 각 조명의 고유 색을 사용합니다.
- 청록·노을·보라: 모든 광원에 선택한 프리셋 색을 적용합니다.
- 색상 입력: `#56DCE7`처럼 여섯 자리 색상 코드를 입력하고 Enter를 누릅니다. 잘못된 형식이면 안내가 표시되고 조명 색은 바뀌지 않습니다.
- `기본 설정으로 되돌리기`: 선택한 공연장을 설치할 때의 기본 점등·밝기·색 설정으로 되돌립니다. 나중에 수정한 PDA 값을 다시 읽지는 않습니다.

게임 안에서 조명 창을 닫았다가 다시 열어도 선택한 공연장의 현재 설정을 보여 줍니다. 게임을 완전히 종료한 뒤에도 유지하려면 축제 저장 기능이 별도로 연결되어 있어야 합니다. 현재 확인한 프로젝트의 저장 기록 화면은 실제 저장 기능 연결 전 구조이므로, 조명 설정을 바꾸는 것만으로 디스크에 자동 저장된다고 생각하면 안 됩니다.

개발 측에서는 기존 시설 스냅샷, 즉 시설 상태를 모아 담는 데이터에 조명 설정을 함께 넣습니다. 이 데이터를 저장하고 복원하는 검증 결과와 실제 게임 저장 메뉴 연결 여부를 문서 끝에 따로 기록합니다.

## 5. 조명 설정창의 모양을 UMG에서 바꾸기

1. `Content/FestaFiesta/UI/Facility`에서 `WBP_FF_FacilityLightingControls`를 엽니다.
2. 상단에서 `Designer`를 선택합니다.
3. 왼쪽 `Hierarchy`에서 바꾸려는 글자·버튼·슬라이더를 선택합니다.
4. 오른쪽 `Details`에서 글자 크기, 색, 여백, 정렬, 크기를 변경합니다.
5. `Compile`과 `Save`를 누릅니다.
6. 게임에서 시설 정보창을 열어 긴 한글 문장이나 숫자가 잘리지 않는지 확인합니다.

프로젝트 인게임 UI는 밝은 바탕과 차분한 청록색을 사용합니다. 새 색을 임의로 추가하기보다 기존 시설 정보창과 같은 색을 유지하면 자연스럽습니다.

| 용도 | 색상 |
|---|---|
| 강조·주요 버튼 | 청록 `#527C6B` |
| 기본 배경 | 밝은 종이색 `#F7F8F6` |
| 본문 글자 | 짙은 녹회색 `#24332E` |
| 보조 글자 | 회녹색 `#6F7B75` |
| 경계선 | 연한 회녹색 `#CCD5CF` |

**연결된 위젯의 이름은 유지합니다.** 이름은 화면과 기능을 연결하는 표식입니다. 버튼 이름을 바꾸거나 다른 위젯 종류로 교체하면 클릭 기능이 끊길 수 있습니다. 글자 내용·색·여백·위치는 바꿀 수 있으며, 기능 연결용 위젯 이름의 확정 목록은 아래에 기입합니다.

기능 연결용 위젯 이름:

| 이름 | 위젯 종류 | 연결된 기능 |
|---|---|---|
| `Button_LightingToggle` | Button | 전체 켜기/끄기 |
| `Text_LightingToggle` | Common Text Block | 현재 켜짐 상태와 다음 동작 |
| `Slider_LightingBrightness` | Slider | 밝기 변경 |
| `Text_LightingBrightness` | Common Text Block | 현재 밝기 % |
| `Button_LightingOriginal` | Button | 각 램프의 원래 색 |
| `Button_LightingTeal` | Button | 청록 프리셋 |
| `Button_LightingSunset` | Button | 노을 프리셋 |
| `Button_LightingViolet` | Button | 보라 프리셋 |
| `Input_LightingColor` | Editable Text Box | 색상 코드 입력 |
| `Text_LightingColorStatus` | Common Text Block | 현재 색 적용 방식 |
| `Button_LightingReset` | Button | 설정 초기화 |

프리셋의 실제 색은 WBP의 `Class Defaults → Lighting → Presets`에서 `Teal Color`, `Sunset Color`, `Violet Color`로 변경합니다. 버튼 이름을 유지하고 표시되는 글자나 버튼 색을 새 프리셋에 맞추면 됩니다. 예를 들어 `Sunset Color`를 연한 분홍으로 바꾸고 버튼에 표시되는 이름도 '분홍'으로 수정할 수 있습니다.

실행 중 숫자와 상태는 프로그램이 갱신합니다. Designer에서 쓴 밝기 숫자가 게임에서 다른 숫자로 바뀌는 것은 현재 공연장의 실제 설정을 보여 주기 때문입니다.

바로 편집할 수 있는 글자는 `Text_LightingTitle`의 '무대 조명', `Text_LightingReset`의 '기본 설정으로 되돌리기', `Text_LightingPreset0~3`의 프리셋 이름입니다. 반면 켜짐 상태, 밝기 %, 색상 적용 상태, 현재 색상 코드는 게임 상태에 맞춰 자동으로 갱신됩니다.

조명 카드가 정보창 안에서 놓이는 위치는 `WBP_FF_FacilityInfoPanel`의 `Widget_LightingControls`에서 바꿉니다. 카드 안의 버튼 배치는 `WBP_FF_FacilityLightingControls`에서 바꿉니다. 이 두 단계만 구분하면 화면 전체를 새로 만들 필요가 없습니다.

## 6. 다른 시설에도 같은 기능 붙이기

기존 조명 Blueprint를 복제하면 C++ 코드를 새로 작성하지 않고 같은 기능을 재사용할 수 있습니다.

1. 콘텐츠 브라우저에서 `BP_MainStage_Grand_Lighting`을 우클릭해 `Duplicate`를 선택합니다.
2. `BP_SubStage_Lighting`처럼 어떤 시설의 조명인지 알 수 있는 이름을 붙입니다.
3. 복제한 Blueprint를 열어 조명의 위치·방향·개수·밝기를 새 시설에 맞게 조정합니다. 참고용 `PreviewStageMesh`도 새 시설 메시로 바꾸면 편합니다.
4. 새 시설의 PDA를 열고 `Facility Lighting → Lighting Rig Class`에 방금 만든 Blueprint를 지정합니다.
5. `Lighting Enabled`와 `Brightness Multiplier`를 정하고 저장합니다.
6. 게임에서 그 시설을 새로 설치하고 시설 정보창의 조명 카드가 표시되는지 확인합니다.

Blueprint의 부모 클래스는 `FFZSFacilityLightingRig`를 유지합니다. 완전히 빈 Blueprint부터 만들 때도 이 클래스를 부모로 선택해야 전체 밝기와 색 변경 기능에 연결됩니다. `Lighting Root` 아래에 실제 `Spot Light`, `Point Light`, `Rect Light`를 추가하면 됩니다.

조명이 없는 시설에는 `Lighting Rig Class`를 비워 둡니다. 모든 시설이 조명 카드를 표시할 필요는 없습니다. 서로 다른 무대 메시를 강화 단계별로 사용하는 시설은 각 모델에서도 램프 위치가 맞는지 별도로 확인합니다.

## 7. 자주 생기는 문제 해결하기

| 보이는 문제 | 확인할 순서 |
|---|---|
| 새 공연장을 설치했는데 조명이 없음 | PDA의 조명 Blueprint 연결 → 기본 점등 여부 → 전체 밝기 → Blueprint의 램프 밝기 순서로 확인합니다. |
| 램프는 켜진 것 같은데 바닥에 빛이 없음 | 램프 방향과 도달 거리를 확인하고, 어두운 시간대에서 비교합니다. |
| PDA를 바꿨는데 예전 공연장이 그대로임 | 새 공연장을 설치해 비교합니다. 기존 저장 시설은 설치 당시 기본값 또는 개별 설정을 유지할 수 있습니다. |
| 조명이 무대에서 어긋남 | 원본 조명 Blueprint가 현재 `Visual Mesh`와 짝이 맞는지 확인합니다. 무대 메시를 다른 모델로 교체하면 램프 배치도 조정해야 합니다. |
| 켜기/끄기를 해도 장식 부분이 밝아 보임 | 실제 광원과 발광 재질은 별개입니다. 무대 LED·램프 표면의 발광 재질은 메시 재질에서 수정합니다. |
| 바닥은 밝아지지만 공중 빛줄기가 안 보임 | 공중 빛줄기는 레벨의 안개 설정에도 영향을 받습니다. 조명 켜짐 여부는 먼저 바닥과 무대 표면으로 확인합니다. |
| WBP를 수정했는데 화면이 바뀌지 않음 | 실제 연결된 WBP인지 확인하고 `Compile → Save` 후 게임을 다시 실행합니다. |
| 버튼을 눌러도 반응이 없음 | 기능 연결용 위젯 이름과 타입이 유지되는지, 조명 가능한 공연장을 선택했는지 확인합니다. |

## 8. 혼자서 작업을 마무리하는 확인 순서

1. 새 공연장을 설치하면 조명이 켜집니다.
2. 게임에서 조명을 끄면 바닥에 비치는 빛이 사라지고, 다시 켜면 돌아옵니다.
3. 밝기를 낮추고 높였을 때 차이가 보입니다.
4. 색을 바꾸면 선택한 공연장의 빛만 바뀝니다.
5. 공연장을 이동·회전해도 조명이 무대와 함께 움직입니다.
6. 조명 창을 닫았다가 다시 열어도 개별 설정이 유지됩니다. 실제 게임 저장 기능이 연결된 버전이라면 저장 후 불러오기까지 확인합니다.
7. 공연장을 철거하면 조명도 함께 사라집니다.
8. WBP의 버튼과 글자가 화면 밖으로 나가거나 서로 겹치지 않습니다.

이 목록은 사용자가 변경 후 확인할 항목입니다. 아래의 개발 검증 결과와 구분합니다.

## 이번 작업의 검증 결과

- 언리얼 Editor용 C++ 빌드: 통과했습니다.
- 실제 메인공연장 PDA에 메시와 조명 Blueprint를 연결했고, 조명 10개를 가진 Blueprint와 UMG WBP를 생성·저장했습니다.
- 실제 PDA를 사용하는 설치 API 자동화 테스트에서 자동 점등, 밝기 절반 변경, 끄기, 색상 변경, 기본값 복원, 상태 복원, 철거와 조명 제거를 확인했습니다.
- 시설의 회전·이동·확대에 조명이 따라가는지, 숨겨진 복원 준비 시설이 빛을 내지 않는지, 밝기를 반복 적용해도 잘못 곱해지지 않는지 확인했습니다.

- GPU로 실제 UMG 이미지를 렌더하여 1280×720 화면의 스크롤·고정 버튼 영역과 조명 카드 글자·색·배치를 확인했습니다.

관련 자동화 테스트는 총 8개가 통과했습니다. 조명 검증 5개와 기존 시설 정보창·일시정지·시설 강화 관련 회귀 검증 3개입니다. 디스크에 저장된 PDA의 에셋 번들에 조명 Blueprint가 포함되는지, WBP 생성 명령을 다시 실행해도 기존 화면 파일이 유지되는지도 확인했습니다. 설치 검증은 실제 에셋을 사용하는 별도 테스트 월드에서 수행했습니다. 전체 `Test_Main` 맵을 마우스로 조작하는 수동 플레이, 패키징된 실행 파일, 여러 공연장을 함께 켰을 때의 성능 측정은 이번 검증에 포함하지 않았습니다.
