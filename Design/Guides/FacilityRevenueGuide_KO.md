# 시설별 수익 Data Table 설정 가이드

수정일: 2026-09-29

**DT_FacilityRevenues 표 한 곳**에서 시설별 일반 매출, 수수료율, 레벨별 수익 배율, 프로그램 참가비를 조정합니다. 현재 시설 114종을 기준으로 관리하며, 프로그램을 열 수 있는 시설 6종의 참가비도 준비했습니다.

**2026-09-22 적용 상태:** 미니게임 실행 기능 정리에 맞춰 연결 전용 CSV 행 3개와 추가 도구를 삭제했습니다. 기존 Data Table의 114개 행과 금액은 유지합니다. 다른 사람이 만든 정산 코드가 사용하는 미니게임 보상 필드는 호환성 때문에 남아 있으나, 일반 시설을 편집할 때 새 보상 행을 추가하지 않습니다.

## 1. 금액 바꾸기

1. 최신 코드가 빌드된 프로젝트를 Unreal Editor로 엽니다. 업데이트 전에 에디터를 열어 두었다면 새 빌드를 적용한 뒤 다시 엽니다.
2. 게임이 실행 중이면 **Stop(정지)**을 누릅니다.
3. 하단 **Content Drawer(콘텐츠 드로어)**를 엽니다. 기본 단축키는 **Ctrl+Space**입니다.
4. `Content > FestaFiesta > Data > Economy` 폴더로 이동합니다.
5. **DT_FacilityRevenues**를 더블클릭합니다.
6. 표의 **시설 이름** 열에서 바꿀 시설을 찾고 해당 행을 클릭합니다. 검색창에 시설 이름이나 Row Name의 일부를 입력해 찾을 수도 있습니다.
7. 아래 **Row Editor(행 편집기)**에서 **1인 1회 매출 (Gold)**을 원하는 숫자로 바꿉니다. 내부 속성 이름은 `RevenuePerUseGold`입니다.
8. **Ctrl+S**로 표를 저장합니다.
9. 게임을 실행하고 시설 정보 **기본 탭 상단의 팀당 예상 수익**과 이용 완료 후 **오늘 매출**을 확인합니다. 1~6명 팀의 일반 이용 1회 수익을 각각 표시합니다. **기존 시설을 철거하거나 다시 설치할 필요가 없습니다.**

시설의 **오늘 매출은 실제 보유 Gold에 적립된 수익**입니다. 일반 이용은 `1인 1회 매출 × 이용한 팀 인원 × 수수료율 × 강화 배율 × 시너지 배율`을 모두 곱한 뒤 한 번 반올림해 정산합니다. 예를 들어 표의 매출이 30 Gold, 수수료율이 12%, 추가 배율이 1이면 1명 팀은 4 Gold, 4명 팀은 14 Gold가 들어옵니다. 팀당 예상 수익도 같은 계산을 사용합니다. 입장·대기 중에는 매출을 만들지 않고, 팀의 이용이 완료되면 시설 위 배지·시설 정보의 오늘 매출에 함께 누적됩니다. 유료 프로그램 참가비는 별도 실제 정산액으로 합산됩니다.

실제 파일은 `Content/FestaFiesta/Data/Economy/DT_FacilityRevenues.uasset`입니다. 표에서 한 행의 숫자를 바꾸면 그 시설 종류에 해당하는 모든 설치 시설에 적용됩니다. 다른 종류의 시설은 각자의 행을 따릅니다.

## 2. 표의 항목 읽기

| 항목 | 의미 | 수정 방법 |
|---|---|---|
| Row Name | 게임이 시설을 찾는 고유 ID | 기존 행 이름은 그대로 둡니다. 예: `Booth_FoodStall_Burger` |
| 시설 이름 | 사람이 읽기 쉬운 이름 | 시설을 찾을 때 사용합니다. 연결을 결정하는 값은 Row Name입니다. |
| 1인 1회 매출 (Gold) | 손님 1명이 일반 시설 이용을 완료했을 때의 매출 | 0 이상의 정수를 입력합니다. |
| 시설별 수수료율 사용 | 이 표에서 정한 수수료율을 사용할지 | 일반 시설 행은 켜져 있습니다. |
| 수수료율 (0~1) | 일반 매출 중 플레이어가 받는 비율 | 0.12는 12%, 1은 전액입니다. |
| 레벨별 수익 배율 | 시설 레벨마다 일반 이용 수입에 곱할 배율 | 왼쪽은 레벨, 오른쪽은 배율입니다. 1 → 1.0, 2 → 1.5 등입니다. |
| 프로그램별 1인 참가비 (Gold) | 이 시설에서 여는 각 프로그램의 참가비 | 왼쪽은 프로그램 ID, 오른쪽은 1명당 금액입니다. 0은 무료입니다. |

**무료로 만들려면 해당 금액을 0으로 바꾸세요. 행이나 프로그램 항목을 삭제하는 것은 무료 설정이 아닙니다.** 삭제하면 이전 기본값이 적용될 수 있습니다. 일반 이용도 프로그램도 모두 무료로 만들려면 두 금액을 각각 0으로 바꿉니다. 프로그램 개최 비용까지 0이 되는 것은 아닙니다.

## 3. 매출과 실제 들어오는 돈의 차이

**일반 이용 매출**은 손님이 시설에서 쓰는 금액입니다. 이 일반 매출에서 플레이어가 받는 **수입**에는 수수료율이 적용됩니다. 프로그램 참가비는 아래의 별도 계산법을 따릅니다.

**일반 이용 수입 = 표의 일반 매출 × 이용 완료 인원 × 표의 수수료율 × 표의 현재 레벨 배율 × 시너지 수익 배율**

모두 곱한 뒤 한 번 반올림합니다. 손님 무리 전체가 이용을 마칠 때 함께 정산하므로, 화면의 1인 예상 수익을 인원수만큼 더한 값과 실제 정산은 반올림 때문에 조금 다를 수 있습니다.

현재 표의 시설별 수수료율은 기존 부산 축제와 같은 12%(설정값 0.12)입니다. 아래는 표의 금액을 50으로 입력한 경우의 계산 예시이며, 시설에 실제로 넣은 초기 밸런스 값과는 구분하세요.

| 이용 상황 | 계산 | 실제 수입 |
|---|---|---|
| 기본 시설을 1명이 이용 완료 | 50 × 1 × 0.12 | 6 Gold |
| 기본 시설을 4명이 이용 완료 | 50 × 4 × 0.12 | 24 Gold |
| 강화 배율 1.5에서 4명이 이용 완료 | 50 × 4 × 0.12 × 1.5 | 36 Gold |

설치만 하거나 줄을 서는 순간에는 수입이 생기지 않습니다. 일반 이용을 완료해야 정산됩니다. 이용 완료 기능이 없는 도로·장식 등에 양수를 입력해도 수입 발생 기능이 추가되지는 않습니다.

## 4. 프로그램 참가비 바꾸기

1. 같은 표에서 프로그램을 열 시설을 선택합니다. 예: **모래공방**, Row Name `Booth_CraftExperience_SandArt`.
2. 아래 행 편집기의 **프로그램별 1인 참가비 (Gold)**를 펼칩니다. 내부 이름은 `ProgramFeesPerPerson`입니다.
3. `Program_SandArtWorkshop` 항목의 **오른쪽 값**을 바꿉니다. 왼쪽 ID는 그대로 둡니다.
4. 예를 들어 30을 40으로 바꾸고 **Ctrl+S**로 저장합니다.
5. 게임에서 모래공방을 선택해 프로그램 편성창을 엽니다. 1인 참가비가 40 Gold, 정원 12명 기준 최대 수입이 **480 Gold**인지 확인합니다.
6. 프로그램을 편성하고 시작 시각까지 진행합니다. 예약 참가 인원이 12명이면 480 Gold가 한 번 들어옵니다. 개최 비용 200 Gold는 편성할 때 별도로 지출합니다.

**프로그램 수입 = 해당 시설의 프로그램 참가비 × 예약에 확정된 참가 인원**입니다. 최대 정원까지만 계산하며, 일반 이용의 수수료·강화·시너지 배율은 곱하지 않습니다. 화면의 최대 수입은 개최 비용을 빼기 전 금액입니다. 준비 화면에서도 시설 선택 후 그 시설의 최대 수입을 보여 줍니다.

| 프로그램 ID | 프로그램 이름 | 설정할 시설 | 초기 참가비 / 정원 / 최대 수입 |
|---|---|---|---|
| `Program_SandArtWorkshop` | 바다향기 공방 | 모래공방, 나만의 부채 공방, 조개 팔찌 공방, 파도 레진 키링 공방 | 30 / 12명 / 360 Gold |
| `Program_SunsetYoga` | 선셋 요가 | 체험장, 관객 댄스 챌린지 무대 | 25 / 16명 / 400 Gold |

같은 프로그램이어도 시설 행마다 다른 참가비를 입력할 수 있습니다. 모래공방을 40으로 바꿔도 조개 팔찌 공방이 자동으로 40이 되지는 않습니다. 한 시설에서 여러 프로그램을 열도록 설정했다면 이 항목에 **+**로 프로그램 ID와 참가비를 각각 추가합니다. ID는 축제 설정의 Program Catalog에 등록된 Program Id를 그대로 복사합니다.

이 표에 참가비를 추가하는 것만으로 새로운 프로그램이나 허용 시설이 만들어지지는 않습니다. 프로그램 이름·정원·시간·개최 비용·필요 인원·허용 시설 종류는 기존 축제의 **Program Catalog**에서 설정합니다.

## 5. 어떤 설정이 먼저 적용되나요?

| 순서 | 조건 | 사용하는 값 |
|---|---|---|
| 1 | 수익표에 해당 시설의 Row Name이 있음 | DT_FacilityRevenues의 금액. 0도 그대로 사용합니다. |
| 2 | 표에 행이 없고 기존 시설 개별 설정이 켜져 있음 | 시설 설치 당시 Data Asset의 개별 금액 |
| 3 | 표에 행이 없고 시설 개별 설정도 꺼져 있음 | Festival Definition의 소분류 공통 기본값 |

현재 114종은 모두 표에 행이 있으므로 **시설 수익은 이 표에서 수정하면 됩니다.** 이전 안내의 **Override Revenue per Use**를 켤 필요가 없습니다. 켜져 있어도 수익표에 행이 있으면 표의 값이 우선합니다.

수수료는 **시설별 수수료율 사용**이 켜져 있으면 표를 따릅니다. 꺼져 있거나 행이 없으면 축제 공통 수수료율을 사용합니다. 레벨별 배율에서 빠진 레벨은 설치·강화 당시 시설에 저장된 기존 배율을, 프로그램별 참가비에서 빠진 프로그램은 Program Catalog의 기존 참가비를 사용합니다. 초기 제공 표는 실제 시설 레벨과 허용 프로그램을 모두 채워 두었습니다.

시설끼리 가까이 배치해 얻는 **조합 추가 수익**은 같은 Economy 폴더의 **DT_FacilitySynergies**에서 관리합니다. 해당 행의 **추가 수익 (%)**에 10을 넣으면 일반 이용 수입에 +10%가 적용됩니다. 이 표는 게임 시작 때 읽으므로 수정 후 저장하고 게임을 다시 실행합니다. 여러 조합의 합계에는 Project Settings의 **FestaFiesta 시설 조합 → 시설당 추가 수익 상한 (%)**이 적용됩니다. 기본 상한은 +50%입니다.

기본 축제 `DA_Festival_Busan`의 **Facility Revenue Table**은 이 표를 사용합니다. 다른 축제 설정을 사용할 때는 해당 축제의 같은 항목에 `DT_FacilityRevenues`를 연결합니다.

## 6. 기존 시설과 실행 중 변경

표의 금액은 정산할 때마다 확인합니다. 기존에 설치한 시설과 저장 파일에서 복원한 시설도 **다음 이용 완료부터 현재 표의 값**을 사용합니다. 프로그램은 **아직 정산되지 않은 경우** 정산 시점의 표 참가비를 적용하고, 한 번 받은 참가비는 다시 지급하지 않습니다. 프로그램 편성의 저장·불러오기 기능을 새로 추가한 것은 아닙니다. 이미 받은 수입을 다시 계산하거나 돌려주지는 않습니다.

에디터에서 같은 표를 수정하면 다음 정산과 예상 수익 조회에 반영되며 월드 수익 표시도 갱신됩니다. 저장을 해야 프로젝트를 다시 열어도 값이 유지됩니다. 작업 확인은 게임 정지 → 표 수정 → 저장 → 재실행 순서를 권장합니다. 이미 배포한 실행 파일에 반영하려면 수정한 에셋을 포함해 다시 패키징해야 합니다.

## 7. 초기 밸런스 기준

일반 매출이 있는 부스 31종은 설치비, 1명당 이용 시간, 강화 가능 여부를 기준으로 금액을 나눴습니다. 도로·공공시설·장식 등 83종의 일반 이용 매출은 0으로 설정했습니다. 프로그램 참가비 6개는 기존 30/25 Gold를 그대로 옮겼습니다. 같은 프로그램의 개최 비용·정원·내용이 같으므로 초기 참가비도 같게 유지합니다. 축제 전체 입장료·목표 보너스·피날레는 시설 수익과 별개인 기존 축제 설정입니다.

| 부류 | 초기 1인 1회 매출 범위 |
|---|---|
| 음식 | 22~36 Gold |
| 공예 | 24~28 Gold |
| 게임 | 28~36 Gold |
| 굿즈 | 32~38 Gold |
| 야간 | 34~40 Gold |
| 공연·휴식·안내·안전·화장실·포토존·조명·도로·타일 | 일반 이용 매출 0 Gold |

수익값은 **현재 실제 에셋을 바탕으로 계산한 초기 밸런스**입니다. 모든 시설에 손님이 끊임없이 오는 상황을 전제하지 않고, 강화 가능한 시설에는 성장 여지를 남겼습니다. 이동 거리·손님 취향·혼잡·행사 시간에 따라 실제 수입은 달라집니다. 계산 근거와 시설별 금액은 `Design/Guides/FacilityRevenueBalance_KO.md`에 정리했습니다.

검토 기준은 1배속입니다. 현재 대기열과 축제 시계가 배속을 처리하는 방식에 차이가 있어 2배속·4배속에서는 같은 일일 수입을 보장하지 않습니다. 최종 난이도는 1배속 플레이 결과로 조정하세요.

## 8. 새 시설 추가 / CSV 사용

새 시설을 만들면 이 표에 행을 하나 추가하고 **Row Name을 시설 Data Asset의 Facility Definition ID와 똑같이** 입력합니다. 시설 이름과 매출, 수수료율, 레벨별 배율, 해당하는 프로그램 참가비 설정을 채운 뒤 저장하세요. 강화 배율 목록에 레벨을 추가해도 시설 자체에 강화 단계가 생기는 것은 아닙니다. 시설 ID는 `PDA_FFZS_`로 시작하는 에셋 파일명과 다릅니다. 예: 파일명이 `PDA_FFZS_Booth_FoodStall_Burger`이면 현재 시설 ID는 `Booth_FoodStall_Burger`입니다. 정확한 ID는 Data Asset에서 확인하세요.

`data/unreal/facility_revenues_v0.csv`는 처음 표를 만들 때 사용한 원본입니다. **게임은 CSV가 아니라 저장한 Data Table을 읽습니다.** 평소에는 Data Table에서 수정하면 됩니다. CSV를 다시 Import/Reimport하면 표의 수동 수정값을 덮을 수 있으므로, CSV에서 일괄 관리하려는 경우에만 원본과 표를 함께 맞추세요. 제공된 생성 도구는 기본 실행 시 기존 표를 덮어쓰지 않습니다. 개발자용 최초 확장 옵션 `-FFMigrateFacilityIncome`은 기존 일반 매출을 보존하면서 새 수익 항목만 채우고 원본을 Saved에 백업합니다. 해당 새 항목이 이미 편집된 표에는 이전 옵션을 다시 실행하지 않습니다.

## 9. 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 표가 보이지 않음 | 최신 에셋을 받았는지, Economy 폴더에 있는지 확인합니다. |
| 행 편집기에 금액 항목이 없음 | 최신 Editor 빌드를 적용하고 다시 엽니다. 수익표의 행 형식은 `FF_FacilityRevenueTableRow`입니다. |
| 이전 Data Asset 금액을 바꿔도 변화가 없음 | 정상입니다. 표에 행이 있는 시설은 표의 금액이 우선합니다. |
| 0으로 했는데 돈이 들어옴 | 같은 시설 ID의 행인지 확인하고, 입장료·다른 시설·유료 프로그램 수입과 구분합니다. 이미 기록된 수입은 지워지지 않습니다. |
| 값이 전혀 적용되지 않음 | Ctrl+S 저장 여부와 사용 중인 축제의 Facility Revenue Table 연결을 확인합니다. |
| 작은 값을 넣었더니 수입이 0임 | 수수료 적용 후 반올림 결과가 0일 수 있습니다. |
| 프로그램 참가비가 그대로임 | 선택한 시설 행과 프로그램 ID를 확인합니다. 프로그램별 참가비의 오른쪽 값을 수정해야 합니다. |
| 강화 배율을 바꿔도 변화가 없음 | 현재 시설 레벨에 해당하는 항목을 고쳤는지 확인합니다. 프로그램 참가비에는 강화 배율이 적용되지 않습니다. |
| 표 연결 오류 또는 음수 경고 | 올바른 표를 연결하고 금액·배율은 0 이상, 수수료는 0~1, 레벨은 1 이상으로 고칩니다. |
