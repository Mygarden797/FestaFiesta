# 시설 UI V2 — 대기열과 게임 HUD 표현 개선

작성일: 2026-09-20  
상태: **사용자가 “아직 통과 아니다”라고 명시한 검토용 시안. 구현 미승인.**

이번 작업은 이미지와 디자인 문서의 개정이다. 게임 플레이 코드, C++/UMG, WBP, uasset, 게임 데이터는 이 개정 작업에서 변경하지 않는다. 버튼·토글·재질·월드 오버레이는 승인 후 구현할 제안이며, 이미지에 그려졌다는 이유로 동작이 구현된 것으로 간주하지 않는다. 예시 수치는 실제 플레이 기록이 아니다.

| 배치 정보 | 설치 전 정원·동선과 설치 후 실시간 점유를 명확히 구분 |

## 1. 배치 그리드와 대기열

- 시설 면적은 실선, 안전 여유는 점선, 대기열 예약 영역은 옅은 별도 면과 테두리로 구분한다. 격자가 시설·동선보다 강하게 보이지 않도록 원거리 보조선을 줄인다.
- 실제 `QueueSplinePointsCm`와 슬롯 간격을 따라 번호가 있는 대기 자리를 표시한다. 보기 편한 임의 직선이나 경로로 실제 꺾임을 바꾸지 않는다.
- `진입 → 대기 → 서비스 → 출구`를 작은 방향 화살표와 라벨로 보여준다. 라벨은 실제 Entry/Service/Exit 앵커를 따른다. 단순 표시만으로 길 연결 또는 접근 가능 판정을 보증하지 않는다.
- 선택 시설 옆에 `대기 정원 5명`, `동시 이용 1명`, `1인 이용 6초`처럼 정적 사양을 배치한다. 이 수치는 예시이며 시설의 실제 사양·강화 상태에서 읽는다.
- 설치 전에는 `설치 전 미리보기`를 표시한다. 아직 존재하지 않는 시설에 라이브 점유나 예상 대기를 만들어 넣지 않는다.
- `격자 / 안전 여유 / 대기열 / 동선` 토글과 시설 정보의 `대기열 보기`는 **시각 표시 제안**이다. 토글은 표시만 바꾸며 정원·예약 영역·충돌 판정·NPC 이동을 변경하지 않는다.
- 대기열 충돌에는 해당 영역과 이유를 강조한다. 잔액 부족이나 단계 제한 때문에 가짜 충돌 영역을 만들지 않는다. 현재 검증은 영역별 실패 사유를 제공하므로 정확한 교차 면적을 아는 것처럼 그리지 않는다.
- 길이만 늘려 정원이 늘어나는 것처럼 표현하지 않는다. 최대 대기 수와 슬롯 수는 사양을 따르고 필요한 경로 길이는 `(정원 - 1) × 슬롯 간격`을 충족해야 한다.

## 2. 시설 정보와 라이브 대기열

시설 이름·운영 상태 아래에 **대기열 점유**, 대기·처리 중 팀 수, 예상 시간을 먼저 배치한다. 자세한 처리 속도와 정적 정원은 같은 카드의 보조 정보로 둔다.

| 상태/항목 | 문구와 의미 |
|---|---|
| 설치 전 | `대기 정원 5명 · 동시 이용 1명` 등 설계 사양만 표시 |
| 등록된 준비 단계 시설 | 실제 운영 상태를 표시. 미운영 예상 시간은 `운영 시작 후 확인` 등으로 구분하며 0초로 만들지 않음 |
| 실시간 점유 | `대기열 점유 3 / 5명` 또는 `대기·처리 중 3 / 5명` |
| 팀 수 | `대기·처리 중 2팀`; 팀 수를 인원 수로 취급하지 않음 |
| 남은 서비스 인원 | 아직 서비스가 끝나지 않은 인원. 총점유와 독립된 값 |
| 예상 시간 | 제목은 `1인 예상 시간`, 도움말은 `1인 이용 완료까지의 예상 시간` 권장 |
| 운영 상태 | `운영 중 · 입장 가능`, `운영 중 · 현재 만석`, `운영 종료` |
| 데이터 준비 중/미지원 | `운영 정보 준비 중` / `운영 정보 사용 불가`; 실제 0명과 구분 |
| 조명·길·타일 | `대기열 없음` 또는 `해당 없음` |

현재 Project Queue의 점유는 파티 전체가 끝날 때까지 서비스를 이미 받은 멤버도 포함한다. 따라서 점유 게이지를 순수 대기 인원으로 부르거나 별도 서비스 인원을 더해 부풀리지 않는다. 플러그인의 정적 대기 정원과 프로젝트의 보수적 총점유 상한이 같은 수로 연결되는 점을 유지한다.

현재 예상 시간은 `(남은 서비스 인원 + 신규 1명) / 초당 처리량`이다. 본인의 서비스도 포함하므로 빈 줄이라고 0초로 표시하지 않는다. 기존 포맷인 `1분 미만`, `약 N분`, `계산 불가`를 활용하며, 초 단위 세분화는 별도 표시 변경으로 명시하고 승인 후 연결한다. 처리량은 `명/분`으로 통일한다.

## 3. 강화 후 대기열 검증

크기 변경 강화에는 현재/강화 후 시설 면적, 안전 여유, 대기열 예약 영역과 동선을 함께 비교하는 미리보기를 제안한다. 강화 후 사양으로 실제 배치 검증을 호출한 결과만 `공간 확보됨` 또는 실패 사유로 표시한다. 대기·이용·퇴장 점유, 운영 종료 여부, 허용 단계, 잔액도 기존 규칙을 따른다. 미리보기의 초록 테두리만으로 구매 가능을 확정하지 않는다.

## 4. 시설별 매출 순위 V2

상단에는 `오늘 / 축제 누적`, 선택 기간 합계, 집계 시설 수를 둔다. 목록은 `순위 배지 → 시설 썸네일·이름 → 금액 → 매출 비중 막대` 순서로 읽히게 하고 선택 행에 진주광 테두리를 적용한다. 선택 시설의 정보 보기 행동은 하단에 고정한다.

**막대 의미를 바꾸는 제안:** 기존 코드는 최대 매출 대비 `RelativeRevenue`를 그린다. V2 시안은 **같은 기간 전체 합계 대비 `Share`**를 그리며 모든 행이 같은 100% 기준을 사용한다. 예시가 `400 / 300 / 200 / 100 Gold`, 합계 `1,000 Gold`라면 막대는 **40% / 30% / 20% / 10%**다. 첫 행을 100% 채우지 않는다. 이것은 아직 적용되지 않은 UI 표시 변경으로, 승인 후 막대 바인딩·라벨·검증을 함께 변경해야 한다. 매출 장부나 순위 계산은 바꾸지 않는다.

- 공동 순위 `1, 2, 2, 4`를 유지한다. 메달은 순서를 읽는 장식이며 게임 보상이나 업적이 아니다.
- 설치된 수익 시설이 없음, 설치 시설은 있으나 매출 0, 데이터 준비 중/조회 실패를 구분한다. 전체 합계 0에서 비중은 `—`이며 막대는 비운다.
- 모든 매출이 0인 경우 코드상 공동 1위일 수 있으나 과장된 우승 연출 대신 `첫 매출을 기다리는 중` 상태를 사용한다. 순위 의미를 변경하려면 별도로 명세한다.
- 현재 설치된 부스 및 수익 장부가 있는 시설만 집계하고 제거/계획 시설은 제외한다. 설치 인스턴스별 구분과 해당 시설에 귀속된 프로그램 매출을 보존한다.
- 모델에 없는 전일 대비, 순위 상승, 시간별 추이, 가짜 혼잡도·보상은 넣지 않는다.

## 5. 게임 HUD의 톤앤매너

아이보리 에나멜 면, LightTeal·세이지 바탕, 짙은 녹색 제목·버튼을 중심으로 한다. 이리디센스는 선택된 패널의 얇은 진주광 테두리, 작은 순위 배지, 주요 버튼의 광택에 사용한다. 낮은 채도의 청록·연보라·분홍빛이 가장자리에 자연스럽게 이어지도록 하고 숫자와 본문 아래는 차분한 단색을 유지한다.

오로라는 패널 헤더의 부드러운 빛으로, 메쉬 그라디언트는 썸네일 받침과 넓은 장식 면에 제한한다. 기존 시설 썸네일·3D 에셋과 축제 월드의 비중을 유지하고 판타지 건물이나 다른 장르의 배경으로 교체하지 않는다. 색만으로 상태를 구분하지 않고 슬롯 번호·점선·아이콘·문구를 함께 사용한다. 움직이는 광택과 재질 효과는 승인 이후 성능·가독성을 확인할 구현 항목이다.
