# 시설 강화 시스템

시설 강화는 **가게 한 곳의 장비와 건물을 개선하는 것**과 같습니다. 같은 음식 부스를 두 개 설치해도 구매한 부스만 바뀝니다. 시설마다 강화 사용 여부, 가격, 수익, 처리 속도, 외형과 크기를 따로 정할 수 있습니다.

## 플레이 방법

1. 준비 또는 아침 점검 시간에 설치된 시설을 선택합니다.
2. 시설 정보 카드에서 현재 1인 예상 수익과 기본 대비 수익 변화를 확인합니다. 강화 영역에는 다음 수익·변화 Gold·증감률·수익 배율과 서비스 시간·최대 처리량·비용·구매 후 잔액을 보여 줍니다. 크기가 달라지면 현재 크기와 다음 크기도 미터 단위로 표시합니다.
3. 강화 버튼을 누르면 현재보다 높은 레벨 중 가장 가까운 작성 단계로 진행합니다. 성공하면 같은 카드에서 바뀐 상태를 확인할 수 있습니다. 무료 단계도 같은 버튼으로 진행합니다.
4. 다음 날, 이동, 시설 스냅샷 복원 뒤에도 구매한 상태는 유지됩니다. 같은 종류를 새로 설치하면 별도의 시설로 시작합니다.

레벨을 사용하지 않는 시설도 현재 수익을 표시하지만 레벨 표시와 강화 영역 전체는 숨깁니다. 무료 시설의 수익은 0 Gold입니다. 레벨을 사용하는 시설은 운영 중에도 현재 수익과 레벨을 볼 수 있지만 구매 상세와 버튼은 숨깁니다.

운영 중이거나 손님이 남아 있는 시설, 재배치가 필요한 시설, 오늘 프로그램이 편성된 시설은 강화할 수 없습니다. 커진 시설을 놓을 공간이 없을 때도 구매를 거절합니다. 버튼 옆에 이유를 표시하며, Gold가 모자라면 구매 후 잔액 대신 부족액을 보여 줍니다. 실패한 강화에는 돈을 쓰지 않습니다.

## 기획자가 설정하는 곳

콘텐츠 브라우저의 `/Game/FestaFiesta/Building/FF_Data_Building/`에서 해당 `UFFZSFacilityDefinition` Data Asset을 엽니다. Details 상단의 **Facility Upgrade**에 필요한 항목을 모았습니다. 이 항목들은 해당 에셋의 `Spec`을 직접 편집하며, 별도의 전역 강화 표는 사용하지 않습니다.

| Details 항목 | 뜻 |
|---|---|
| `Use Facility Levels` (`Spec.bUsesFacilityLevels`) | 켜면 이 시설에 레벨과 강화 기능을 사용합니다. 끄면 레벨 표시와 강화 버튼을 모두 숨기며, 작성해 둔 단계 데이터는 보존합니다. |
| `Upgrade Tiers` (`Spec.UpgradeTiers`) | 단계 개수의 기획상 상한이 없는 강화 목록입니다. 레벨 사용을 켜고 목록을 비워 두면 최대 Lv.1 시설입니다. |
| `Target Level` | 2 이상의 서로 다른 레벨 번호입니다. Lv.10 상한, 번호 연속성, 배열 순서 제한이 없습니다. 예: 20·5·99로 작성해도 1→5→20→99로 진행합니다. |
| `Cost Multiplier` | 설치비에 곱하는 구매 비용입니다. 0 이상으로 설정하며 상한은 없습니다. 0이면 무료 단계입니다. |
| `Service Duration Multiplier` | Lv.1 서비스 시간에 곱하는 양수입니다. 1이면 유지, 2이면 두 배 느려집니다. 이전 단계보다 증가하거나 감소해도 됩니다. |
| `Revenue Multiplier` | Lv.1 수익에 곱하는 0 이상의 배율입니다. 0이면 수익 없음, 0.5이면 절반, 1.5이면 1.5배입니다. 이전 단계와의 비교 제한이나 100배 상한이 없습니다. |
| `Size Multiplier` | Lv.1 가로·세로·높이에 곱하는 양수입니다. 0.75면 축소, 1이면 유지, 5면 5배입니다. 값 설정에 4배 상한이나 증가 조건이 없습니다. 실제 배치와 동선은 별도 검증합니다. |
| `Level Visual Mesh` | 해당 레벨에 사용할 선택적 Static Mesh입니다. 비우면 항상 Lv.1의 `Spec.VisualMesh`를 사용합니다. |

예를 들어 음식 부스는 3레벨까지, 안내소는 레벨 없이, 다른 체험 부스는 서로 다른 비용과 크기로 설정할 수 있습니다. 설정은 설치할 때 각 시설에 보관하므로 에셋 수정이 이미 설치된 시설이나 구매한 효과를 소급해서 바꾸지 않습니다. 수정한 설정을 게임에서 확인하려면 새로 설치합니다.

**비용·수익·시간·크기를 이전 단계와 같게 유지하거나 증가·감소시킬 수 있습니다.** 외형만 변경하는 단계와 모든 효과가 같은 단계도 허용합니다. 새 항목을 추가할 때는 기존 항목과 `Target Level`이 중복되지 않게 지정하십시오. 숫자의 계산 가능 여부, 음수 비용·수익, 0 이하 시간·크기, 중복 레벨은 오류 항목과 필드를 구체적으로 알려 줍니다.

기획상 상한을 없앤 것이므로 `int32` 레벨·Gold, 유한한 실수, 건물의 실제 공간 등 저장·실행상의 표현 범위는 유지합니다. 너무 작은 서비스 시간은 기존 대기열 실행 정밀도인 최소 0.01초로 적용하며 UI도 같은 실제 시간을 보여 줍니다. 큰 비용을 Gold 자료형으로 표현할 수 없으면 구매 견적을 거절하고, 수익은 잔액·누적 매출·장부가 같은 수용 금액을 기록하도록 처리합니다.

### 외형과 크기 확인

1. Lv.1 외형은 원본 `Spec.VisualMesh`에 지정합니다. 강화 목록에 Lv.1 항목을 추가하지 않습니다.
2. 각 단계의 `Level Visual Mesh`에 원하는 Static Mesh를 지정합니다. Lv.2에만 메시를 지정하고 Lv.3을 비우면, Lv.3은 Lv.1 메시로 돌아갑니다.
3. **Preview Facility Levels**를 누르면 별도 3D 미리보기 창이 열립니다.
4. 창의 **Preview Level** 목록에서 실제 작성된 레벨을 선택하며 외형과 크기를 비교합니다. 목록은 숫자순으로 표시합니다. 레벨 변경만으로 카메라가 자동 확대·축소되지 않아 크기 차이를 그대로 볼 수 있습니다.
5. Details에서 데이터를 수정한 뒤 **Refresh Preview**를 눌러 반영합니다. 이때 전체 레벨이 보이도록 화면 범위를 다시 맞춥니다.

미리보기는 에디터의 현재 맵이나 설치된 시설을 바꾸지 않으며 구매도 발생하지 않습니다. 잘못된 단계 설정은 미리보기의 안내로 확인할 수 있습니다.

메시 교체만으로 배치 크기가 달라지지는 않습니다. 실제 공간과 건물 크기는 `Size Multiplier`로 조절합니다. 예를 들어 Lv.2가 1.15, Lv.3이 1.30이면 Lv.3은 원본의 1.30배입니다. 1.15 × 1.30으로 누적되지 않습니다. 서로 다른 메시의 모양은 해당 에셋에 설정된 기존 시각 크기 규칙을 따릅니다.

시설 크기가 바뀌어도 설치된 격자의 시작점은 유지합니다. 건물 중심과 대기 동선·예약 공간·입장/서비스/퇴장 지점을 새 크기와 위치에 맞춰 조정합니다. 사람 간 최소 간격, 대기 정원, 동시 이용 인원은 유지합니다. 시설 둘레의 추가 안전 여유 거리는 적용하지 않습니다. 다른 시설과 겹치거나 구역 밖으로 나가면 구매할 수 없습니다. 축소할 때에도 대기열 길이·인원 간격·예약 공간이 유효해야 합니다. 변경 후 동선이 현재 NavMesh에서 연결되지 않으면 구매 전에 거절합니다. 기존 장애물 때문에 축소 후의 동선이 아직 NavMesh에 없는 경우에도 이 동기 검사는 보수적으로 거절할 수 있으며, 별도의 비동기 길찾기 준비 단계는 추가하지 않았습니다.

## 기존 부스 설정 이관

[이관 스크립트](../../Tools/facilities/migrate_facility_upgrade_settings.py)는 이전 전역 설정의 대상이던 부스 7개에 시설별 강화 목록을 옮기는 용도입니다. 나머지 시설 11개는 레벨 사용을 끈 상태로 유지합니다. 기존 기본 설정은 다음과 같습니다.

| 구매 | 해당 구매 비용 | Lv.1 서비스 시간 배율 | Lv.1 수익 배율 | Lv.1 크기 배율 |
|---|---:|---:|---:|---:|
| Lv.1 → Lv.2 | 설치비의 30% | 0.80 | 1.50 | 1.15 |
| Lv.2 → Lv.3 | 설치비의 60% | 0.65 | 2.25 | 1.30 |

설치비 400 Gold, 서비스 시간 4초인 부스라면 첫 강화는 120 Gold로 3.2초, 두 번째는 240 Gold로 2.6초가 됩니다. 비용은 가장 가까운 정수 Gold로 반올림하며 결과가 0이면 무료입니다. 시간·수익·크기는 모두 Lv.1 기준이므로 이동하거나 복원해도 중복 적용되지 않습니다. 단계마다 수익을 1.5배씩 늘리려면 표처럼 Lv.2는 1.5, Lv.3은 2.25를 작성합니다. 두 단계 모두 1.5로 쓰면 두 단계의 수익은 같습니다.

이관에서 새 레벨 메시를 임의로 지정하지 않습니다. 각 단계는 기존 Lv.1 메시를 사용하며, 이후 기획자가 원하는 Static Mesh를 지정할 수 있습니다. 이전 설정을 추출한 `Artifacts/FacilityUpgrade/LegacyUpgradeConfig.json`이 있으면 그 비용·시간 표를 사용합니다. 이미 작성된 시설별 설정은 보존하며, 처리 표시를 남겨 재실행 때 사용자가 끈 레벨 기능을 다시 켜지 않습니다. 저장 실패 시 에셋을 복구합니다. 정상 처리 내역은 `Artifacts/FacilityUpgrade/PerFacilityMigrationReport.json`에 기록합니다.

이 수치는 플레이 테스트를 시작하기 위한 설정입니다. 처리량은 손님이 계속 온다는 가정의 최대치이며, 강화가 손님 수나 이용 요금을 직접 늘리지는 않습니다. 철거 환급은 기존 설치비 규칙을 따르며 강화비는 환급되지 않습니다.

### 실제 수익과 화면의 숫자

손님이 유료 이용을 마치면 `이용 인원 × 소분류별 이용 매출 × 축제 수수료율 × 해당 시설의 수익 배율`을 계산한 뒤 마지막에 한 번만 정수 Gold로 반올림합니다. 기본 금액과 수수료율은 기존 Festival Definition의 `RevenuePerUseByMinorToken`·`BoothCommissionRate`(2026-10-09부터 1.0, 부스 매출 전액이 축제 몫)를 사용하며, 시설 Data Asset에서는 그 위에 적용할 강화 배율을 정합니다. 실제 결제와 UI 견적은 같은 계산 함수를 호출합니다.

화면의 **1인 예상 수익**은 이 계산을 한 명 기준으로 보여 줍니다. `기본 대비 +N Gold`는 Lv.1 대비 현재 변화액, 강화 견적의 변화 금액은 현재 대비 다음 단계의 차이입니다. 감소하면 `-N Gold`, 변화가 없으면 `0 Gold`로 표시합니다. `기본 ×1.5`는 Lv.1 대비 설정 배율입니다. 증감률은 화면에 표시된 정수 Gold끼리 비교하므로 반올림으로 생기는 금액 차이와 맞습니다. 현재 수익이 0이면 증감률은 생략합니다.

예를 들어 반올림 전 기본 수익이 10.4 Gold이면 현재 표시는 10 Gold, 1.5배 강화 후에는 15.6을 반올림한 16 Gold입니다. 화면은 `10 → 16 Gold`, `변화 +6 Gold (+60%)`, `기본 ×1.5`를 표시합니다. 실제 여러 명의 결제는 인원까지 곱한 뒤 한 번 반올림하므로 1인 표시액을 단순히 인원수만큼 더한 값과 차이가 날 수 있습니다. 무료 시설은 배율을 올려도 수익이 0입니다.

## 구현 방식 — 쉽게 설명하면

| 설계 | 쉬운 설명 | 효과 |
|---|---|---|
| 원본 사양 + 시설별 상태 | 공통 설계도를 복사하고 각 가게의 등급을 따로 보관 | 같은 종류의 다른 시설에 영향 없음 |
| 하나의 구매 명령 | 강화 결제를 한 계산대에서 처리 | 다른 화면이나 Blueprint에서도 조건 검사 유지 |
| 예약 → 적용 → 확정 | 비용을 확보하고 건물·대기열 변경이 끝나면 영수증 발행 | 실패하면 돈·크기·성능·대기열을 함께 복원 |
| 구매 번호와 표시 당시 레벨 검사 | 처리한 영수증과 오래된 견적을 다시 사용하지 않음 | 중복 결제와 오래된 화면의 클릭 방어 |
| 완료 뒤 알림 | 모든 변경이 끝난 상태를 화면에 전달 | 돈·레벨·실제 동작이 일치하는 화면 표시 |
| 공통 효과·정산 계산 | 시설·대기열·UI가 같은 원본과 배수를 사용하고 마지막에 한 번 반올림 | 표시 수치와 실제 동작의 불일치 방지 |
| 필요한 대상만 갱신 | 구매 시 해당 시설을 변경하고 선택된 시설만 견적 조회 | 강화 시스템의 상시 Tick·전체 시설 반복 탐색 없음 |

짧은 중복 클릭 방어도 적용해 더블클릭으로 다음 두 단계를 연달아 구매하지 않도록 합니다. 실제 구매 시에는 게임 시스템이 레벨·단계 값·돈·운영 상태·공간을 다시 검사합니다. 무료 단계도 같은 명령 예약·확정·복구 경로를 사용하지만 지출 장부와 잔액 변경 알림은 만들지 않습니다. UI 견적은 크기가 그대로인 경우 반복 공간 검사를 생략하지만, 실제 구매에서는 항상 공간을 확인합니다. 단계가 많아져도 정의 검증과 미리보기에서 전체 강화 목록을 매 단계마다 복사하거나 없는 레벨 번호를 순회하지 않습니다.

### 구현 위치와 API

- `FF_ZoneSystem`의 `FFFZSFacilityUpgradeTier`·`FFZSFacilityUpgradeRules`: 시설별 단계, 검증과 원본에서 효과 사양 계산.
- `FF_ZoneSystem`의 시설 Actor·World Subsystem: 시설별 상태, 크기·외형, `Upgrade` 명령과 스냅샷.
- `FF_ZoneSystemEditor`: Data Asset Details의 설정 노출과 별도 3D 레벨 미리보기.
- `Building/FF_FacilityUpgradeTypes`: 표시용 견적과 Gold 비용 계산.
- `Building/FF_FacilityUpgradeSubsystem`: 구매 진입점과 프로젝트 구매 조건. 별도 Tick 없음.
- `Zone/FF_ZoneSystemQueueBridgeSubsystem`: 실제 손님 대기열의 후보 적용과 실패 복구.
- `Economy/Rules/FF_BoothRevenueRules`·`FF_QueueEconomyBridgeSubsystem`: 공통 정산 계산과 이용 완료 시 해당 시설의 수익 배율 적용.
- `Festival/FF_FestivalProgressionSubsystem`: 비용 예약·확정·해제, 지출 장부와 최종 알림.
- `UI/Facility`: 시설 카드의 레벨·견적·버튼·실패 이유와 기존 WBP 마이그레이션.

Blueprint/C++에서는 `GetUpgradePreview(FacilityInstanceId, OutPreview)`로 조회하고 `TryUpgradeFacility(FacilityInstanceId, ExpectedCurrentLevel, OutFailureReason)`으로 구매합니다. `ExpectedCurrentLevel`은 화면에서 보여 준 레벨입니다. 견적의 `bHasLevels`가 꺼져 있으면 레벨과 강화 UI를 모두 숨깁니다.

`bHasUpgradeQuote`는 가격까지 계산된 견적인지 나타냅니다. 비용이 0인 정상 무료 견적과 가격 계산 실패를 이 값으로 구분합니다. `bCanUpgrade`는 운영 상태·잔액·배치 등 구매 조건까지 충족하는지 나타냅니다.

## 저장과 UI 호환

현재 Zone 시설 스냅샷은 **schema 7**입니다. 시설마다 설치 당시의 원본 사양과 강화 목록, 메시 참조, 현재 레벨·시간 배수·수익 배수·크기 배수를 보관합니다. 복원할 때 이 원본에서 실제 크기와 외형을 다시 만들며, 변경된 Data Asset을 읽어 구매 효과를 바꾸지 않습니다. 수익 배수 필드가 없는 이전 데이터는 기본 1배를 사용합니다.

| 이전 스냅샷 | schema 7로 가져올 때의 처리 |
|---|---|
| schema 3·4·5 | 기존 단위·회전 변환과 설치 사양·명령 영수증을 유지합니다. 내부 레벨은 1, 시간·수익·크기 배수는 1로 두고 레벨 기능을 끄며 강화 목록은 비웁니다. 새 Data Asset의 강화 설정을 과거 시설에 자동 적용하지 않습니다. |
| schema 6 | 구매한 레벨과 시간 효과를 보존하고 수익·크기 배수는 1로 유지합니다. 구매 이력이 있는 Lv.2 이상 시설은 현재 레벨을 표시하되 새 강화 목록을 주입하지 않습니다. Lv.1 시설은 레벨 기능을 끕니다. |

이 저장 지원은 기존 **Zone 시설 스냅샷** 범위입니다. Gold·날짜·Party 상태까지 담는 전체 게임 저장 기능을 새로 추가한 것은 아닙니다. 전체 게임 저장에서는 경제와 시설 스냅샷을 같은 시점에 보관해야 합니다.

`FF.BuildFacilityInfoUMG`는 누락된 강화 위젯을 추가하고 강화 영역을 요약 다음, 프로그램·운영 정보 이전으로 배치합니다. 이미 강화 위젯이 있는 에셋도 순서를 검사해 필요한 경우 해당 영역만 이동합니다. 기존 Designer 노드·그래프·스타일과 388×500 카드, 내부 스크롤, 고정 하단 행동 영역은 보존합니다. 자세한 이름·타입·배치 계약은 [시설 정보 UI 문서](../UXUI/FacilityInfo_LightTeal/README.md)를 참고합니다.
