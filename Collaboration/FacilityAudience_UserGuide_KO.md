# SunsetMainStage 관람 공간 — 시설 담당자 작업 가이드

작성일: 2026-09-10 · 대상: UE 5.7 / FF_ZoneSystem

[팀 공유 노션 가이드](https://app.notion.com/p/3d796c43a7f78071a5a7ffd485607128) · 노션에는 작업 절차와 연동 계약을 작성했습니다. 실제 좌표가 담긴 안내도 파일은 로컬에 보관합니다.

시설에서 할 일은 **관객이 설 자리, 들어올 곳, 나갈 곳, 바라볼 곳을 정하고 실제 맵에서 길이 연결되는지 확인하는 것**입니다. 이번 작업으로 그 데이터를 편집·검증하고 NPC 담당자가 읽을 수 있게 만들었습니다.

**아직 전체 NPC가 정시에 모이는 기능까지 연결된 상태는 아닙니다.** 공연 시간과 1배속은 시간 담당자, 이동 명령과 자리 배정은 NPC 담당자가 연결해야 합니다. 시설 담당자는 아래 순서로 관람 공간을 준비하고 검수하면 됩니다.

## 1. 먼저 열어 볼 곳

1. 새 C++ 코드로 `FestaFiestaEditor / Win64 / Development`를 빌드한 뒤 언리얼 에디터를 다시 엽니다. 이번 작업 환경에서는 빌드가 완료되었습니다. 팀원이 변경 사항을 받으면 그 PC에서도 빌드해야 합니다.
2. 콘텐츠 브라우저에서 `PDA_FFZS_Performance_MainStage_SunsetMainStage`를 검색해 더블클릭합니다.
3. Details에서 **Facility Audience → Audience Layout**을 펼칩니다.
4. **Enable Audience Area**가 켜져 있는지 확인합니다. 대상 PDA에는 이미 초기 배치를 저장했습니다.
5. **Preview Facility Levels**를 누릅니다. Columns / Rows / 면적 한도를 확정하면 열린 관람 미리보기도 자동으로 갱신됩니다. 다른 값을 수정했을 때는 **Refresh Preview**를 누릅니다.

버튼이 보이지 않으면 에디터를 다시 시작하고 빌드 결과를 확인합니다. 기존에 열어 둔 에디터에는 새 Details 화면이 반영되지 않을 수 있습니다. 항목에 마우스를 올리면 한국어 설명을 볼 수 있으며 **Show Korean Help**에도 설명을 추가했습니다.

## 2. 가장 자주 할 작업: 정원 변경

1. NPC 담당자에게 **공연 때 모을 사람 수**를 확인합니다. 파티 수가 아니라 실제 사람 수입니다.
2. **Columns**에 한 줄의 인원, **Rows**에 줄 수를 입력합니다. 두 값을 곱한 수가 정원입니다.
3. 숫자 입력 후 **Enter**를 누르거나 입력 칸 밖을 눌러 확정합니다. 자리·입구·출구·필요한 간격과 위치를 자동 보정하고 **전체 시설 검증**을 실행합니다. 정원 변경에는 별도 Arrange 버튼이 필요 없습니다.
4. Facility Audience의 **자동 보정 및 전체 검증 통과** 표시와 미리보기를 확인합니다.
5. **보정 이유와 변경 전후 값**을 확인합니다. 면적이 부족하면 모든 사용 레벨에 필요한 최소 면적을 자동으로 늘려 입력한 인원을 적용합니다. 면적을 미리 계산하거나 인원을 다시 입력할 필요가 없습니다.
6. PDA를 저장한 뒤 테스트용 축제에서 새로 설치해 실제 맵을 확인합니다.

현재 초기값은 **12열 × 10줄 = 120명**입니다. 전체 NPC 수를 조사해서 확정한 정원이 아닙니다. 대상 NPC가 120명을 넘으면 이 배치로 전원 수용할 수 없습니다. 예를 들어 12열 × 15줄은 180자리지만, 공간과 경로 검증을 통과해야 사용할 수 있습니다.

인원 변경 자동 보정은 **입력한 행·열을 그대로 유지**하고, 자리·입출구 위치와 필요한 면적을 계산합니다. 무대나 일반 Queue에 겹치면 첫 줄 Y를 필요한 만큼 뒤로 옮기고, NPC 크기와 가장 작은 업그레이드 배율에 맞춰 부족한 간격/여백을 늘립니다. Z와 바라볼 지점은 유지합니다. 수동 입출구 배치는 자동 위치로 바뀝니다. **Ctrl+Z 한 번**으로 인원·면적·위치 보정을 함께 되돌릴 수 있습니다.

예를 들어 12열 × 50줄을 입력했는데 공통 면적이 부족하면, 초기 배치 기준으로 필요한 관람 면적 한도를 1,174m²로 계산해 적용합니다. 화면에 **면적이 부족했던 이유와 Audience Area Limit이 0 → 1,174m²로 바뀐 내용**이 표시됩니다. 이 숫자는 초기 배치의 예시이며 실제 간격과 레벨 설정에 따라 달라집니다.

### 자동으로 해결할 수 없는 오류가 남을 때

1. Facility Audience에 **적용 대기: 요청 ○열 × ○줄 = ○명**과 실제 오류 원인이 표시됩니다. 요청 숫자를 버리지 않습니다.
2. 표시된 문제를 수정합니다. 예를 들어 시설 이름 누락·메시 참조 오류는 해당 항목을 고치고, 지원 상한을 넘는 배치는 설명에 따라 간격/여백/업그레이드 배율 또는 코드 한도를 검토합니다.
3. **Apply Requested Audience Values**를 누릅니다. 보관한 인원을 현재 시설 설정에 맞춰 다시 계산하고 전체 검증 후 적용합니다.

자동 계산한 보정안이 있어도 다른 오류가 남아 전체 검증을 통과하지 못했다면 **아직 미적용**이라고 표시합니다. 실제 설치에 쓰는 Spec에는 완전히 검증된 변경만 반영합니다. 적용 대기 요청은 **현재 에디터 세션**에 보관되며 에디터 종료 후에는 유지되지 않습니다.

### 자동 계산보다 넉넉한 면적을 직접 지정하고 싶을 때

1. **Facility Audience → Audience Layout → Audience Area Limit (m²)**을 찾습니다.
2. 원하는 관람 면적 한도를 m²로 입력하고 확정합니다. 예를 들어 **2000**은 관람 공간만 최대 **2,000m²**까지 허용한다는 뜻입니다. 정원을 입력하는 칸이 아닙니다.
3. **Columns / Rows**를 입력합니다. 지정한 한도가 충분하면 유지하고, 부족하면 필요한 최소 면적으로 늘린 뒤 이유를 표시합니다.
4. 결과의 **관람 영역 ○○m²**와 정원을 확인하고 저장합니다.

**0**은 기존 공통 면적 예산(현재 기본 1,000m²)에 무대·여유 공간·일반 Queue·관람 영역을 합산하는 방식입니다. **양수**는 이 시설의 관람 영역만 별도 면적 한도로 계산합니다. 무대 본체와 일반 Queue의 공통 한도는 그대로입니다. 한도를 늘려도 실제 맵에 빈 땅이나 길이 생기는 것은 아닙니다.

관람 면적 지원 한도는 최대 **50,000m²**, 관람 인원은 최대 **8,192명**, 행·열은 각각 최대 **512**입니다. 자동 보정은 사용 중인 모든 업그레이드 레벨의 면적을 계산해 필요한 한도를 정합니다. 런타임에서 업그레이드할 때 이 한도 값 자체를 배율로 늘리는 것은 아닙니다. 입력한 한도가 부족하면 필요한 최소값으로 보정하며 이유를 표시합니다. 지원 상한이나 관람 외부의 오류는 요청값을 보관하고 설명합니다. 인원을 임의로 줄여 통과시키지 않습니다.

**Arrange Audience Layout**은 첫 줄 위치나 간격을 직접 조절한 뒤 수동으로 다시 정렬할 때 사용합니다. 이 수동 버튼은 기존처럼 첫 줄 Y/Z와 바라볼 지점을 유지합니다.

## 3. 숫자를 읽는 방법

좌표와 거리는 모두 **cm**입니다. 100은 1m입니다. 좌표의 기준은 시설 중심이며 시설과 함께 회전합니다. 월드 전체의 원점 좌표를 넣는 칸이 아닙니다.

| 화면 항목 | 뜻 | 현재 초기값 |
| --- | --- | --- |
| Columns / Rows | 한 줄의 인원 / 앞에서 뒤로 늘어나는 줄 수 | 12 / 10 |
| Audience Area Limit (m²) | 관람 공간에만 적용할 면적 한도. 0은 기존 공통 면적 예산 | 0 |
| First Seat Local Position (cm) | 첫 줄 왼쪽 사람의 발 위치. X=오른쪽, Y=관객 쪽, Z=높이 | X -760 / Y 1400 / Z 0 |
| Column Spacing (cm) | 좌우 자리 중심 사이 거리 | 120 |
| Row Spacing (cm) | 앞뒤 자리 중심 사이 거리 | 120 |
| Additional Center Aisle (cm) | 가운데 두 열에 기존 간격 외에 추가하는 폭 | 200 |
| Perimeter Margin (cm) | 가장자리 자리 중심에서 관람 공간 경계까지의 여유 | 180 |
| NPC Radius (cm) | 관객 몸의 보행 충돌 반경. NPC 담당자와 맞출 값 | 34 |
| Arrival Tolerance (cm) | NPC가 자리 중심에서 허용받는 도착 오차 | 25 |
| Audience Entry Local Position (cm) | 관람 입구 | X -850 / Y 2570 / Z 0 |
| Audience Exit Local Position (cm) | 관람 출구 | X 850 / Y 2570 / Z 0 |
| Stage Focus Local Position (cm) | 관객이 바라볼 무대의 기준점 | X 0 / Y 500 / Z 200 |

현재 관람 공간은 바깥 여백을 포함해 **18.8m × 14.4m**입니다. 무대 자체 크기와 별개입니다. 가운데 두 열의 자리 중심 간 거리는 기존 120cm에 추가 200cm를 더한 320cm입니다. 200cm가 실제 사람이 통과할 수 있는 최종 유효 폭이라는 뜻은 아닙니다.

[현재 배치 설명 그림](FacilityAudience_Layout.html)은 PDA에서 계산한 평면 안내도입니다. 실제 레벨의 지형·장애물·NPC 이동을 촬영한 화면이 아닙니다.

## 4. 무대와 사람 사이 거리 조절

1. **First Seat Local Position (cm)**의 **Y**를 늘리면 첫 줄이 무대에서 멀어집니다. 줄이면 가까워집니다.
2. **Arrange Audience Layout**을 누르면 바뀐 첫 줄 위치에 맞춰 입구·출구도 다시 배치됩니다.
3. 지면 높이를 바꾸려면 첫 자리의 **Z**를 바꾸고 다시 정렬합니다. 입구·출구는 같은 바닥 높이를 사용합니다.
4. **Stage Focus Local Position (cm)**은 무대에서 바라볼 지점입니다. 입구나 NPC가 걸어갈 목적지로 사용하지 않습니다.

초기 배치는 무대 앞쪽을 시설의 **+Y 방향**으로 정했습니다. 미리보기에서 무대 실제 앞면과 다르면 메쉬 방향과 시설 기준을 먼저 확인하세요. 시설 전체 위치와 회전은 기존 배치 도구로 바꿉니다. 크기는 Actor Scale을 직접 늘리지 말고 기존 시설 PDA 크기/업그레이드 설정을 사용합니다.

## 5. 미리보기에서 확인할 것

| 표시 | 확인할 내용 |
| --- | --- |
| 초록색 작은 십자 | 사람이 설 자리. 무대나 일반 대기줄에 들어가면 안 됩니다. |
| 초록색 바깥 경계 | 다른 시설이 차지하면 안 되는 관람 공간. 실제 맵에서 충분히 비어 있어야 합니다. |
| 파란색 지점 | 관람 입구. 바깥 보행로에서 접근할 수 있어야 합니다. |
| 주황색 지점 | 관람 출구. 퇴장 후 이동할 보행로와 이어져야 합니다. |
| 흰색 방향선 | 관객이 바라볼 방향. 무대 쪽이어야 합니다. |

레벨 선택을 바꿔 업그레이드별 크기도 확인합니다. 업그레이드 배율은 관람 위치·간격·여백도 함께 바꾸며, **행·열과 정원은 그대로**입니다. 축소 때문에 안전 간격이 부족해지면 검증이 실패합니다.

미리보기는 표시 비용을 제한하기 위해 최대 1,024자리만 그립니다. 이것은 데이터 정원 제한이 아닙니다. 미리보기는 실제 맵의 보행 가능 여부를 검사하지 않습니다.

## 6. 실제 맵에서 시설 담당자가 할 최종 확인

1. 별도 테스트용 축제 또는 복사한 테스트 레벨에서 변경한 PDA로 무대를 새로 설치합니다.
2. 관람 경계까지 포함해 다른 시설·담장·장식물과 겹치지 않는지 확인합니다. 이 영역은 시설 배치 점유에 포함되므로 예전보다 넓은 빈 공간이 필요합니다.
3. 에디터 뷰포트에서 **P**를 눌러 NavMesh(걸을 수 있는 영역) 표시를 켭니다. 표시가 없으면 레벨의 NavMesh 설정/빌드 상태를 담당자와 확인합니다.
4. 입구·자리·출구가 걸을 수 있는 바닥에 있고, 바깥 보행로 → 입구 및 출구 → 다음 목적지의 길이 끊기지 않는지 봅니다.
5. NPC 담당자가 제공하는 경로 검사에서 **모든 자리**의 입장·퇴장 검사 결과를 받습니다. 이번에 제공한 `Check Audience Navigation Batch`는 한 번에 최대 64자리만 검사합니다. 현재 120자리는 `시작 0 / 개수 64`, `시작 64 / 개수 56` 두 묶음 모두 성공해야 합니다.
6. 실제 목표 인원을 이동시켜 입구 밀림, 자리 겹침, 지형 높이, 무대 방향, 퇴장 막힘을 관찰합니다. 길이 존재해도 모든 사람이 제시간에 도착한다는 보장은 없습니다.

일반 **Queue의 정원과 서비스 시간은 관람 정원 설정이 아닙니다.** 관객 수를 늘리려고 Queue 값을 바꾸지 마세요. 관람 공간은 보행 가능한 예약 영역으로 처리하며 무대 본체처럼 보행을 막는 장애물로 만들지 않았습니다.

PDA는 새 시설의 설계도입니다. **이미 설치된 시설과 기존 저장 데이터는 설치 당시 Spec을 유지합니다.** PDA를 저장했다고 기존 시설 전체가 자동 갱신되지는 않습니다. 이번 작업에서 운영 중인 맵이나 저장 파일을 일괄 변경하지 않았습니다.

## 7. 오류가 뜰 때

| 증상 | 시설 담당자가 확인할 순서 |
| --- | --- |
| 관람 공간이 꺼져 있음 / 정원이 0 | Enable Audience Area, Columns, Rows 확인 |
| 입구·출구 오류 | 첫 자리 Z를 확인한 뒤 Arrange Audience Layout 실행. 수동 배치는 자리 배열 내부를 피하고 가장자리 통로에 둡니다. |
| 자리 간격 오류 | 현재 반경 34 + 도착 오차 25 기준 최소 간격·여백은 118cm입니다. 실제 NPC 반경이 커지면 다시 계산해야 합니다. |
| 무대나 Queue와 겹친다는 오류 | 첫 자리 Y를 늘려 관람 공간을 뒤로 옮기고 다시 정렬합니다. |
| 배치 면적/정원 제한 오류 | 지원 범위 안의 면적 부족은 최소 면적으로 자동 보정합니다. 8,192명/행·열 512/면적 50,000m² 상한이나 무대·Queue 오류는 원인을 확인하고 수정한 뒤 Apply Requested Audience Values를 누릅니다. |
| 실제 맵에 경로가 없음 | 입구·출구 높이, 지형, 장식물 Collision, NavMesh 범위를 확인합니다. 경로 검사 실패를 무시하지 않습니다. |
| 에셋을 고쳤는데 기존 시설 그대로 | 테스트용으로 새로 설치한 시설인지 확인합니다. |
| 공간은 준비됐는데 NPC가 안 옴 | 아래 팀 인계 문서의 시간·NPC 연동 상태를 확인합니다. 시설 배치 데이터만으로 이동 명령이 생기지 않습니다. |

## 8. 팀에 넘기기 전 체크

- [ ] 목표 관객 수를 NPC 담당자와 확인했고 정원이 그 이상이다.
- [ ] 행·열 확정 → 자동 보정/전체 검증 통과 확인 → 미리보기 → 저장을 완료했다.
- [ ] 새로 설치한 시설로 실제 레벨의 보행로와 모든 자리 경로를 확인했다.
- [ ] 실제 목표 인원으로 입장·정시 도착·퇴장을 확인했다.
- [ ] [팀원 인계 문서](FacilityAudience_TeamHandoff_KO.md)의 남은 연동 사항을 공유했다.

코드와 초기 PDA 설정은 준비되었지만 위 체크는 실제 레벨과 팀원 연동 후 수행할 검수 항목입니다. 이번 자동 검사 결과를 이 체크의 완료로 대신하지 않습니다.
