# 시설 설치 지형 기준 안내

일반 시설과 길을 놓을 때 허용하는 바닥의 최대 경사를 **15도**, 시설 아래 높이 차를 **80cm**로 조정했습니다.
이 문서는 기획자·레벨 제작자·개발자가 같은 기준으로 설치 결과를 이해하고 설정을 관리하도록 설명합니다.

**타일은 별도 규칙을 사용합니다.** 타일의 기본 허용치는 89도·2000cm이며 지면 최고점에 수평으로 놓입니다. 적용 범위·메시 지면 태그·설정과 확인 절차는 [타일 기초 바닥 안내](TileFoundation_UserGuide_KO.md)를 참고하세요. 아래 15도·80cm 조정의 설명과 검증 기록은 일반 지면 기준에 대한 기록입니다.

## 1. 무엇이 달라졌나요?

| 판단 항목 | 이전 기준 | 이번 기준 | 뜻 |
| --- | --- | --- | --- |
| 최대 경사 | 5도 | 15도 | 검사한 바닥 중 가장 가파른 부분의 허용 경사입니다. |
| 전체 높이 차 | 20cm | 80cm | 검사한 바닥에서 가장 높은 곳과 가장 낮은 곳의 차이입니다. |

이전보다 완만한 언덕이나 높낮이가 조금 있는 땅에 시설을 놓기 쉬워집니다.
두 값은 **동시에 만족해야 하는 별도의 조건**입니다.
경사가 작아도 시설 전체가 차지하는 바닥의 높이 차가 크면 설치할 수 없습니다.
반대로 높이 차가 작아도 검사 지점에 가파른 면이 있으면 설치할 수 없습니다.

## 2. ‘전체 바닥의 높이 차’는 어떻게 계산하나요?

게임은 시설이 차지하는 바닥 영역 안에서 여러 지점을 골라 땅을 검사합니다.
이렇게 골라 검사한 지점을 **표본**, 또는 **샘플**이라고 합니다.
시설이 여러 바닥 영역으로 구성되어 있으면 그 영역에서 수집한 표본들을 함께 비교합니다.

```text
높이 차 = 검사한 표본 중 가장 높은 높이 - 가장 낮은 높이
```

예를 들어 검사한 높이가 100cm, 130cm, 160cm라면 전체 높이 차는 60cm입니다.
각 지점과 바로 옆 지점의 차이가 아니라, 시설 아래 표본 전체의 최고점과 최저점을 비교합니다.

이 방식은 **실제 바닥의 모든 점을 빠짐없이 검사한다는 뜻은 아닙니다.**
표본 사이에 있는 아주 작은 돌출부나 움푹 팬 곳은 측정되지 않을 수 있습니다.
표본 간격은 별도 설정이며, 이번 변경은 경사와 높이 차의 허용치만 다룹니다.
시설의 크기·위치·회전에 따라 검사하는 지점이 달라질 수 있습니다.

## 3. 예시로 이해하기

아래 예시는 바닥을 정상적으로 찾았다고 가정하고 **경사·높이 차 두 조건만** 비교합니다.

| 검사된 최대 경사 | 검사된 전체 높이 차 | 지형 조건 결과 | 이유 |
| --- | --- | --- | --- |
| 10도 | 60cm | 통과 | 15도 이하이며 80cm 이하입니다. |
| 10도 | 90cm | 실패 | 경사는 괜찮지만 높이 차가 80cm를 넘습니다. |
| 16도 | 40cm | 실패 | 높이 차는 괜찮지만 경사가 15도를 넘습니다. |
| 15도 | 80cm | 기준상 통과 | 두 값 모두 허용 상한과 같습니다. |

실제 게임의 경사와 높이는 물리 검사로 얻은 수치입니다.
눈으로 보기에 평평하거나 경계값에 가까워 보인다는 이유만으로 통과를 보장하지는 않습니다.
최종 결과는 게임에 표시되는 배치 가능 여부와 실패 사유로 확인합니다.

## 4. 지형 조건을 통과해도 설치되지 않는 경우

지형 검사는 설치에 필요한 여러 검사 중 하나입니다.
다음 조건도 함께 만족해야 합니다.

- 시설 전체가 허용된 건축 구역 안에 있어야 합니다.
- 기존 시설이나 장애물과 겹치지 않아야 합니다.
- 시설 주변의 이용 공간과 대기 줄 공간이 확보되어야 합니다.
- 보호 구역으로 지정된 통로를 침범하지 않아야 합니다.
- 설치 비용·설치 한도·현재 게임 단계 등 다른 설치 조건도 충족해야 합니다.

배치가 거절되면 먼저 화면에 표시된 사유를 확인하세요.
경사나 높이 차가 원인이라면 더 평평한 위치로 옮기거나 위치·회전을 조정합니다.
충돌이나 구역 제한이 원인이라면 해당 조건을 해결해야 합니다.

## 5. 바닥과 시설 모양은 어떻게 되나요?

이 문서에서 설명하는 일반 시설 기준 변경은 **설치를 허용하는 판단 기준을 넓히는 작업**입니다.
땅을 자동으로 평평하게 만들거나, 시설 아래에 기초·받침대를 생성하는 기능은 포함하지 않습니다.
설치할 수 있는 경사진 장소가 늘어나면 시설 일부가 떠 보이거나 땅에 묻혀 보일 수 있습니다.
레벨 제작자는 실제 배치 후 시설의 바닥 접촉 상태와 손님이 다니는 모습을 함께 확인하세요.

## 6. 기획자·레벨 제작자가 값을 바꾸는 방법

1. Unreal Editor에서 **Edit → Project Settings**를 엽니다.
2. **Game → FF Zone System** 항목을 찾습니다. 표시 이름은 `FF_ZoneSystem`으로 보일 수도 있습니다.
3. **Placement**에서 아래 두 설정을 확인합니다.
4. 값을 변경한 뒤 설정이 저장되었는지 확인합니다.
5. 에디터를 재시작하고 같은 시설을 같은 위치에 놓아 결과를 확인합니다.
6. 변경 내용을 배포할 때는 변경된 설정을 포함해 게임을 다시 패키징합니다.

| 설정 이름 | 현재 값 | 입력 단위 |
| --- | --- | --- |
| `Max Ground Slope Degrees` / `MaxGroundSlopeDegrees` | 15 | 도 |
| `Max Ground Height Variance Cm` / `MaxGroundHeightVarianceCm` | 80 | cm |

프로젝트에서 공유하는 값은 아래 파일에 저장합니다.

```ini
; Config/DefaultGame.ini
[/Script/FF_ZoneSystem.FFZSDeveloperSettings]
MaxGroundSlopeDegrees=15.000000
MaxGroundHeightVarianceCm=80.000000
```

INI 파일을 직접 수정했다면 실행 중인 에디터가 이전 설정을 갖고 있을 수 있으므로 재시작합니다.
설정만 조정하는 경우 C++ 코드를 다시 컴파일할 필요는 없습니다.
이미 만들어진 실행 파일 묶음에는 새 설정이 자동으로 들어가지 않으므로 재패키징이 필요합니다.
공용 기본값 등 C++ 코드까지 변경했다면 에디터·게임의 해당 빌드도 다시 진행합니다.

## 7. 유지보수 담당자가 알아둘 파일 역할

게임의 설치 기준을 조정할 때는 **프로젝트의 `Config/DefaultGame.ini`를 기준으로 관리**합니다.
사용자의 런타임 설정을 코드가 매번 다시 덮어쓰는 방식으로 구현하지 않습니다.

| 파일 | 역할 |
| --- | --- |
| `Config/DefaultGame.ini` | 이 게임 프로젝트에 적용할 경사·높이 차 기준을 지정합니다. |
| `Plugins/FF_ZoneSystem/Source/FF_ZoneSystem/Public/FF_FFZSDeveloperSettings.h` | 설정 항목과 공용 기본값을 정의합니다. 설정 누락 시 사용할 기본값도 이곳에서 관리합니다. |
| `Plugins/FF_ZoneSystem/Source/FF_ZoneSystem/Private/FF_FFZSDeveloperSettings.cpp` | 설정을 검증에 사용할 값으로 정리합니다. 잘못된 숫자는 공용 기본값이나 허용 범위로 처리합니다. |
| `Plugins/FF_ZoneSystem/Config/DefaultFF_ZoneSystem.ini` | 플러그인의 출하 기본값을 명시합니다. 현재 배포 기준과 일치하도록 관리합니다. |
| `Plugins/FF_ZoneSystem/Source/FF_ZoneSystem/Private/FF_FFZSFacilityActor.cpp` | 클릭한 위치가 시설 범위 안인지 판단할 때 높이 차 설정을 참조합니다. 설정이 없을 때도 공용 기본값을 사용합니다. |

설정 클래스는 `Config=Game`으로 선언되어 있습니다.
따라서 `DefaultFF_ZoneSystem.ini`만 고친다고 `DefaultGame.ini`의 게임 설정이 자동으로 바뀌지는 않습니다.
프로젝트 정책을 바꿀 때는 `DefaultGame.ini`를 먼저 수정하고, 출하 기본 정책까지 바꾸는지 별도로 판단합니다.
이번 변경은 프로젝트 값·공용 기본값·플러그인 출하 기본값을 모두 15도·80cm로 맞춥니다.
클릭 위치 판정의 예외 처리도 같은 공용 기본값을 참조해 별도의 숫자가 남지 않게 합니다.

클릭한 위치를 시설 내부로 인정하는 높이 방향의 여유도 같은 높이 차 설정을 참조합니다.
시설 바닥 범위에 추가되는 판정 여유가 기존 22cm에서 82cm로 넓어집니다. 클릭 감지용 상자 자체의 크기는 바꾸지 않습니다.

배치 검증과 바닥 격자 판정은 `ResolveGroundValidationSettings(Category)`를 통해 분류에 맞게 정리된 설정을 사용합니다. 분류를 넘기지 않는 `ResolveGroundValidationSettings()` 호출은 일반 시설 기준을 유지합니다.
새 기능에서도 이 함수를 사용하면 허용 범위와 잘못된 숫자 처리 기준을 공유할 수 있습니다.
다만 격자는 주변 바닥 상태를 안내하므로, 시설 전체의 최종 설치 결과와 같다고 가정하지 않습니다.

## 8. 기존 테스트에 5도·20cm가 남아 있는 이유

일부 테스트는 **의도적으로 5도·20cm라는 조건을 설정한 뒤** 성공과 실패를 확인합니다.
이 숫자는 특정 상황을 재현하기 위한 시험 조건이며, 현재 게임의 운영 설정을 뜻하지 않습니다.
모든 숫자를 15도·80cm로 일괄 교체하면 원래 확인하던 경계 조건이 사라질 수 있습니다.
기존 고정 시나리오는 유지하고, 프로젝트 설정·공용 기본값의 변경 여부는 해당 목적에 맞게 확인합니다.

## 9. 검증 기록

2026-10-07에 UE 5.7 / Windows 환경에서 확인한 결과입니다.

| 확인 항목 | 결과 | 실행 환경·근거 |
| --- | --- | --- |
| 프로젝트 설정·공용 기본값·플러그인 출하 기본값 일치 | 확인 | 모두 15도·80cm |
| 변경 코드 빌드 | 통과 | `FestaFiestaEditor Win64 Development`, `EditorBuild.log` |
| 관련 자동화 테스트 | 10개 통과 | 설정 1개, 격자 지면 4개, 도로·타일 지형 4개, 시설 위치 조회 1개. 테스트 보고서상 실패·경고·미실행 0개 |
| 새 Unreal 프로세스에서 실제 로드된 설정 확인 | 통과 | `LoadedGroundSettings.json`: 경사 15.0, 높이 차 80.0. 실행 중 설정을 수정하지 않고 조회 |
| 실제 맵에서 지형 조건 통과·실패 확인 | 미실시 | 자동화용 임시 지형과 구분해 플레이 확인 필요 |
| 설치 후 바닥 접촉과 이동 경로 확인 | 미실시 | 실제 플레이 관찰 필요 |
| 게임 재패키징 | 미실시 | 배포 시 변경 설정과 코드가 포함된 패키지 생성 필요 |

이번 실행 로그와 보고서는 `Artifacts/Validation/GroundPlacement-20261007-15deg80cm/`에 있습니다.
이 폴더는 로컬 검증 산출물이므로 다른 PC에서는 다시 실행하거나 보고서를 별도로 전달합니다.
기존 자동화 테스트는 판정 기능의 회귀 검사이며, 새 15도·80cm 값이 로드되는지는 별도 실행값 조회로 확인했습니다.

프로젝트 폴더의 PowerShell에서 관련 빌드·자동화 검증을 다시 실행할 수 있습니다.

```powershell
& '.\Tools\Build\Run-AutomationTests.ps1' -TestFilter @(
    'FF_ZoneSystem.Unit.Settings.GroundValidationResolution',
    'FF_ZoneSystem.Integration.BuildableGrid.Surface',
    'FF_ZoneSystem.Road.TerrainSupport',
    'FF_ZoneSystem.Integration.World.FacilityLookupAtWorldPoint'
) -SkipDataValidation
```

위 명령은 이번 코드·설정 변경과 관련된 검사만 실행합니다. 정식 배포 절차는 [패키징 운영 안내](../Tools/Build/README_KO.md)를 따릅니다.
