# 하나로 이어지는 건설 영역 사용 안내

이 기능은 축제장의 **건설 관리 영역을 하나로 만들고, 기존 구역 사이의 선을 가로질러 시설을 놓을 수 있게** 합니다. 건설을 관리하는 액터는 `BuildArea_Main` 하나입니다.

NPC가 어느 지역에 있는지 판단하고 지역별 혼잡과 이동 거리를 계산하는 기존 `FFZSGameplayZone`은 그대로 사용합니다. `Test_Main`에서는 기존 31개 지역을 보존하는 것이 적용 기준입니다. 맵에 보이는 지역 액터를 전부 삭제하는 작업이 아닙니다.

> （10/14 기준: 2026-10-10 「건축 가능 구역 변경」 커밋에서 `Config/DefaultGame.ini`의 `ProjectZoneIds`가 13개 이름 구역(`GZ_Beach01`~`05`, `GZ_DadaYajang`, `GZ_DadaepoForest`, `GZ_FountainPirates`, `GZ_FleaMarket`, `GZ_PublicParkingWest`, `GZ_TemporaryParkingEast`, `GZ_Operations`, `GZ_Tutorial`)으로 바뀌었고, `GZ_TestMain_01`~`30`·`GZ_DadaPocha`·Sunset 계열은 빠졌습니다. 같은 커밋에서 `Test_Main.umap`도 수정됐습니다. 이 문서의 "31개 지역"은 2026-09-10 기준 값입니다. 2026-10-10 [카메라 수정 기록](../Tools/Camera/CAMERA_REGRESSION_FIX_KO.md) 12절은 본편 `Test_Main`에 런타임 Zone이 13개라고 적었습니다. `BuildArea_Main`의 Source Region IDs와 Boundary Status는 에디터에서 다시 확인해야 합니다.）

`Test_Main`에 통합 관리자를 적용하고 맵을 저장했으며, 에디터를 새로 실행해 정상적으로 불러오는 것까지 확인했습니다. 에디터 빌드와 이번 기능에 추가한 자동화 테스트 15개도 통과했습니다. 실제 수동 플레이와 화면 확인은 기존 레벨 블루프린트 오류 때문에 완료하지 못했으며, FPS도 아직 측정하지 않았습니다.

## 1. 무엇이 달라지나요?

| 상황 | 통합 건설 영역의 동작 |
| --- | --- |
| 두 지역이 빈틈없이 맞닿아 있음 | 그 사이의 경계선을 가로질러 시설을 놓을 수 있습니다. |
| 지역 사이에 실제 빈틈이 있음 | 빈틈은 그대로 남으며, 그 공간을 침범하는 시설은 배치할 수 없습니다. |
| 영역 안에 건설 불가능한 구멍이 있음 | 구멍도 그대로 남습니다. 바깥 테두리만 크게 감싸서 허용하지 않습니다. |
| 시설 중심과 시설 일부가 서로 다른 지역에 있음 | 시설 전체를 기준으로 겹침·보호영역을 확인합니다. 넘어간 쪽의 시설 부분도 선택할 수 있게 처리합니다. |
| 시설을 경계 너머로 이동하거나 회전함 | 조작용 격자와 각도는 같은 월드 기준을 사용합니다. 저장 좌표는 기존 지역 기준을 유지합니다. |
| 바닥이 없거나 경사가 심함 | 기존 지면 검사와 배치 실패 사유가 적용됩니다. |

**이 기능은 기존 지역 경계를 합치는 기능입니다. 바닥을 만들거나 지역 사이의 틈을 자동으로 메우지는 않습니다.** 화면에 보이는 격자는 주변의 비어 있는 땅을 안내합니다. 실제 시설에는 크기, 관람 공간, 대기열, 지면 등 추가 조건이 있으므로 최종 배치 결과를 확인해야 합니다.

## 2. 에디터에서 처음 적용하기

작업할 레벨을 먼저 엽니다. 이 프로젝트의 확인 대상은 `Test_Main`입니다. 새 기능이 포함된 에디터 빌드를 사용해야 아래 액터가 검색됩니다.

**현재 `Test_Main`에는 이미 적용되어 있습니다.** World Outliner에서 `BuildArea_Main`을 선택해 상태를 확인하면 됩니다. 아래 추가 절차는 다른 레벨에 처음 적용하거나 관리자가 없는 경우에 사용하세요. 같은 레벨에는 통합 관리자가 한 개만 있어야 하므로 다시 추가하지 않습니다.

### 방법 A — 직접 추가

1. **Place Actors / 액터 배치** 패널을 엽니다.
2. 검색창에 **FFZS Unified Build Area**를 입력합니다.
3. 아직 통합 관리자가 없을 때만 해당 액터를 레벨에 **한 개** 추가합니다.
4. **World Outliner / 월드 아웃라이너**에서 이름을 `BuildArea_Main`으로 지정합니다.
5. 이 액터를 선택하고 **Details / 디테일** 패널에서 **Rebuild From World Regions** 버튼을 누릅니다.
6. 같은 패널의 표시값을 확인합니다.

| 확인 항목 | 기대하는 상태 |
| --- | --- |
| Build Area 액터 개수 | 레벨에 한 개 |
| Boundary Status | `준비 완료: …개 지역을 하나의 건설 영역으로 통합했습니다.` |
| Source Region IDs | 원본 지역 목록이 들어 있음. `Test_Main`의 적용 기준은 31개 |
| Buildable Area (m²) | 합쳐진 건설 영역 면적이 표시됨 |

상태가 위 표와 같으면 **레벨을 저장**합니다. 레벨 블루프린트의 컴파일 오류가 없는 상태에서 **Play**를 눌러 아래 ‘플레이에서 확인하기’를 진행합니다.

`BuildArea_Main`은 기존 지역에서 경계를 읽어 오는 관리자입니다. 이 액터를 이동하거나 크게 늘려서 건설 범위를 넓히는 방식은 사용하지 않습니다. 기존 지역의 모양을 바꿨다면 **Rebuild From World Regions** 버튼을 다시 누르세요. 버튼은 필요할 때 반복해서 사용할 수 있습니다. 플레이 시작 시에도 경계를 다시 계산합니다.

### 방법 B — 준비 스크립트 실행

현재 열려 있는 레벨에 다음 파일을 에디터의 Python 스크립트 실행 기능으로 실행할 수도 있습니다.

```text
Tools/ZoneSystem/enable_unified_build_area.py
```

Python 콘솔을 사용하는 경우 다음 명령을 실행합니다.

```python
import runpy, unreal; runpy.run_path(unreal.Paths.project_dir() + "Tools/ZoneSystem/enable_unified_build_area.py")
```

스크립트는 기존 지역을 확인하고, 통합 관리자가 없으면 하나를 추가합니다. 이미 하나가 있으면 재사용합니다. 이름은 `BuildArea_Main`, 아웃라이너 폴더는 `Construction`으로 맞추고, 원본 지역 정보가 실행 전후 동일한지도 확인합니다.

**기본 실행은 레벨을 자동 저장하지 않습니다.** 선택된 `BuildArea_Main`의 상태를 확인한 뒤 직접 저장하세요. 같은 스크립트를 다시 실행해도 관리자를 계속 추가하지 않습니다. 통합 관리자가 두 개 이상 발견되면 오류를 표시합니다.

실행 보고서는 다음 위치에 생성됩니다.

```text
Artifacts/Validation/UnifiedConstruction/MapSetup.json
```

기본 실행 보고서의 `saved: false`는 저장 버튼을 누르지 않는 기본 동작을 뜻합니다. 이 값만으로 기능 실패라고 판단하지 마세요.

## 3. 플레이에서 확인하기

건설 메뉴에서 평소처럼 시설을 선택하고 배치하면 됩니다. 공간 검색을 위한 별도 버튼이나 설정은 필요하지 않습니다.

현재 `Test_Main`에는 기존 레벨 블루프린트의 `TryStartInteraction` 및 `BadCast` 노드 관련 컴파일 오류가 남아 있습니다. 담당 개발자가 해당 오류를 해결한 뒤 다음 항목을 확인해야 합니다. 통합 관리자를 반복해서 추가하는 것으로 이 오류가 해결되지는 않습니다.

1. **맞닿은 경계 확인:** 두 지역 사이에 실제 빈틈이 없는 위치에서 시설을 경계에 걸쳐 놓습니다.
2. **이동·회전 확인:** 같은 시설을 경계 양쪽으로 이동하고 회전합니다. 조작 격자나 방향이 지역을 바꾼다는 이유로 갑자기 달라지지 않는지 확인합니다.
3. **선택 확인:** 시설의 중심이 있는 쪽과 반대쪽 부분을 각각 눌러 같은 시설이 선택되는지 확인합니다.
4. **겹침 확인:** 옆 시설, 확보된 대기열 공간, 보호된 통로를 침범하면 배치가 거부되는지 확인합니다.
5. **바깥·빈틈 확인:** 외곽 밖이나 지역 사이 빈틈에 걸친 배치가 거부되는지 확인합니다.
6. **저장·불러오기 확인:** 경계에 걸쳐 놓은 시설을 저장한 뒤 불러와 위치·회전·상태가 유지되는지 확인합니다.

시설을 설치·이동·철거하면 주변 시설을 찾는 검색 목록도 자동으로 갱신됩니다. 일반 사용자는 시설 배치 화면에서 작업하면 됩니다.

## 4. 기존 31개 지역을 유지하는 이유

현재 NPC는 기존 지역 정보를 이용해 주변 목적지를 찾고, 혼잡을 판단하고, 지역 사이의 이동 거리를 계산합니다. 따라서 건설 구역을 이어 주면서도 다음 정보는 보존합니다.

- 기존 지역의 ID와 액터 원점·회전·경계
- 이웃 지역 목록과 출입 앵커
- 지역별 인원 집계와 수용량 기준
- 기존 시설의 소속 지역과 저장 좌표

이번 작업에서 NPC 코드는 수정하지 않았습니다. 준비 스크립트 보고서에서도 기존 31개 지역의 설정이 실행 전후 동일한 것으로 확인됐습니다.

**기존 `FFZSGameplayZone`을 삭제하거나 `Zone ID`, 위치·회전·경계를 임의로 바꾸지 마세요.** 건설 관리자를 하나 추가하는 작업과 NPC 지역 데이터를 바꾸는 작업은 영향 범위가 다릅니다. 지역 자체를 수정해야 한다면 담당 개발자와 함께 NPC 동선·혼잡·저장 호환성을 확인해야 합니다.

## 5. 최적화는 어떻게 동작하나요?

창고에서 물건을 찾을 때 모든 선반을 처음부터 확인하는 대신, 위치표를 보고 가까운 선반부터 찾는 방식과 비슷합니다. 게임도 시설이나 지역의 위치를 내부 목록에 정리해 두고, 필요한 주변 후보부터 확인합니다. 이 위치 목록을 **공간 해시**라고 부릅니다.

| 내부 위치 목록 | 현재 분류 단위 | 하는 일 |
| --- | --- | --- |
| 시설 검색 | 가로·세로 20m | 가까운 시설을 먼저 찾아 배치 겹침·선택 등의 검사 후보를 줄입니다. |
| 지역 검색 | 가로·세로 100m | 위치 주변의 기존 지역을 먼저 찾아 소속 지역 판정을 돕습니다. |

이 20m·100m 구분선은 내부 검색용입니다. 시설 배치를 막는 새 경계가 아니며, 화면의 조작 격자나 시설 저장 좌표의 간격도 아닙니다. 후보를 찾은 뒤에는 실제 시설 모양과 건설 경계를 다시 검사합니다.

성능 개선의 크기는 시설 수·배치 밀도·검사 범위에 따라 달라집니다. **FPS가 몇 배 오른다는 수치는 실제 측정 전에는 제시하지 않습니다.** 이번 작업은 건설 관련 검색과 표시 비용을 줄이는 데 초점을 둡니다. NPC 이동·렌더링·지형·내비게이션 전체를 자동으로 최적화하는 기능은 아닙니다.

## 6. 동작 범위와 자주 확인할 문제

| 증상 또는 상황 | 확인할 내용 |
| --- | --- |
| 액터 검색 결과가 없음 | 새 C++ 기능이 포함된 에디터 빌드인지 확인합니다. |
| `BuildArea_Main`이 이미 있음 | 기존 액터를 사용합니다. 같은 관리자를 다시 추가하지 않습니다. |
| Play가 블루프린트 컴파일 오류로 진행되지 않음 | `Test_Main`의 기존 `TryStartInteraction`·`BadCast` 오류를 담당 개발자가 수정해야 합니다. 건설 관리자 개수와는 별도 문제입니다. |
| Boundary Status가 준비 완료가 아님 | 지역이 없거나, ID·경계 설정에 오류가 있는지 확인합니다. 오류 상태에서는 정상 통합으로 간주하지 않습니다. |
| Source Region IDs가 31개가 아님 | `Test_Main`과 필요한 지역들이 열려 있는지 확인합니다. 다른 레벨은 지역 수가 다를 수 있습니다. |
| 경계를 가로지르는 배치가 거부됨 | 맞닿은 선인지 실제 빈틈인지 먼저 확인합니다. 시설 본체 외에 관람 공간·최대 대기열이 바깥이나 금지 영역을 침범했을 수도 있습니다. |
| 넓은 빈 공간인데도 설치가 안 됨 | 지면·경사·보호통로·시설 규칙 등 화면에 표시되는 실패 이유를 확인합니다. |
| 매우 큰 시설이 많거나 넓은 영역을 한꺼번에 검사함 | 가까운 후보만 추리는 효과가 작아질 수 있습니다. 큰 대상은 별도 목록이나 저장된 대상 전체를 검사하는 방식으로 처리합니다. |
| 개발용 스크립트로 시설 액터를 직접 이동함 | 일반 건설 명령을 건너뛰면 검색 목록이 실제 위치와 어긋날 수 있습니다. 시설 배치·이동 API를 사용해야 합니다. |
| 개발 중 지역 경계를 직접 수정함 | 경계 재계산이 필요합니다. 런타임 변경은 담당 개발자가 시스템 갱신 경로까지 확인해야 합니다. |

공간 해시는 위에서 내려다본 **XY 위치**로 후보를 찾습니다. 높이·지면·시설의 정확한 겹침 판정을 대신하지 않습니다. 검색 후보가 많아지는 경우에도 필요한 검사를 생략해서 속도를 올리는 방식은 사용하지 않습니다.

통합 관리자 없이 기존 방식을 사용하는 레벨은 기존 건설 규칙을 따릅니다. 다만 통합 모드에서 경계를 가로질러 배치한 시설이 생긴 뒤 관리자를 제거하면 기존 규칙으로는 배치·저장 복원이 거부될 수 있으므로, 이를 단순한 되돌리기 버튼처럼 사용하지 마세요.
