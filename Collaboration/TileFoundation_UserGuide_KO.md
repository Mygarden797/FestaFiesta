# 울퉁불퉁한 땅에 타일을 놓는 방법

기준: 2026-10-07, FestaFiesta / FF_ZoneSystem.

**타일은 건축이 허용된 구역 안에서 울퉁불퉁한 땅의 가장 높은 부분 위에 수평으로 설치됩니다.** 타일 위에는 평평한 바닥을 기준으로 건축물을 놓을 수 있습니다. 타일이 건축 허용 구역을 넓히거나 금지 구역을 해제하지는 않습니다.

## 1. 어떤 것이 달라졌나요?

| 대상 | 허용 경사 기본값 | 아래 지면의 허용 높이 차 기본값 | 설치 높이 |
| --- | --- | --- | --- |
| 타일 `Tile` | 89도 | 2000cm | 타일 아래에서 확인한 지면 최고점 |
| 길 `Road`와 일반 건축물 | 15도 | 80cm | 기존 지면 검사 규칙 유지 |

타일의 기준을 일반 건축물과 따로 관리합니다. 타일을 선택하면 주변 배치 격자에도 타일의 지형 기준이 적용됩니다. 격자는 주변 지면 상태를 안내하므로, 표시된 한 칸만 보고 큰 타일 전체의 설치를 보장할 수는 없습니다. 최종 설치는 타일 전체 크기로 검사합니다.

건축 구역, 시설 종류 제한, `NoBuild` 금지 영역, 보호 통로, 다른 시설의 점유, 비용과 설치 한도는 계속 적용됩니다. 타일과 다른 타일·길이 서로 겹쳐지는 것도 허용하지 않습니다.

## 2. 높이는 어떻게 정하나요?

책상 위에 울퉁불퉁한 물체가 놓여 있다고 생각해 보세요. 그 위에 평평한 판을 내려놓으면 가장 높은 부분에서 멈춥니다. 타일도 이 원리로 높이를 정합니다.

1. 타일이 차지하는 바닥 범위 안쪽과 가장자리에 여러 검사 지점을 잡습니다. 이 지점들을 ‘표본’이라고 부릅니다.
2. 각 지점에서 실제 충돌용 지면을 찾고 경사와 높이 차를 확인합니다.
3. 타일 바닥 크기의 얇은 판을 위에서 아래로 내려 추가 검사합니다. 표본 사이의 돌출부까지 확인해 지면의 최고 높이를 찾습니다.
4. 타일 바닥을 그 높이에 맞추고, 타일 자체는 기울이지 않습니다. 위쪽 평면은 타일 두께만큼 더 높은 곳에 생깁니다.

예를 들어 타일 아래 땅의 높이가 **100cm, 130cm, 160cm**이고 추가 검사에서도 더 높은 지면이 없다면, 타일 바닥은 **160cm**에 놓입니다. 타일 두께가 **20cm**라면 건축물이 올라가는 평평한 윗면은 **180cm**입니다. 100cm인 낮은 땅과 타일 사이에는 빈 공간이 남을 수 있습니다.

검사는 화면에 보이는 그림이 아니라 **물리 충돌용 모양**을 기준으로 합니다. 보이는 산의 모양과 충돌용 모양이 다르면 결과도 달라집니다. 벽이나 장식물을 지면으로 잘못 취급하지 않도록, 지면인지 불분명한 돌출부는 설치를 거절합니다.

## 3. 설치할 수 있는 범위

타일도 건축 가능한 영역 안에 놓아야 합니다. 통합 건설 영역이 있는 맵에서는 실제 구역들을 합친 범위를 사용하며, 그 사이의 빈틈과 구멍은 허용되지 않습니다. 타일을 깔았다는 이유로 구역 밖이나 금지 구역에 건축할 수 있게 되지는 않습니다.

타일의 모든 **검사 지점**에서 지면을 찾아야 합니다. 일반 시설의 `Require Every Ground Sample`을 꺼도 타일에는 이 조건을 유지합니다. 표본 사이의 아주 작은 구멍까지 모두 증명하는 방식은 아니므로, 레벨 제작자는 바닥의 충돌 모양도 확인해야 합니다.

기본 지면 검색 범위는 구역의 기준 높이에서 **위 1000cm, 아래 1000cm**입니다. 마우스나 미리보기의 높이를 기준으로 따라가는 범위가 아닙니다. 예를 들어 구역 기준 높이가 0cm이면 약 -1000~1000cm 안에서 지면을 찾습니다. 타일의 높이 차 허용값이 2000cm여도 이 검색 범위 밖의 땅까지 자동으로 찾지는 않습니다.

`Enable Ground Checks`는 지면 검사를 통째로 생략하는 개발용 예외입니다. 끄면 최고점 확인과 지면 존재 보장도 생략되므로 실제 맵과 배포 설정에서는 켜 둡니다.

## 4. 메시로 만든 지면이 거절될 때

Unreal의 **Landscape** 지형은 지면으로 인식합니다. 하나의 연속된 메시가 타일 전체를 받치는 경우에도 기존 표본 정보로 지면을 판별합니다. 다만 메시 하나에 바닥과 벽이 함께 들어 있거나, 표본 사이에서 갑자기 높은 돌출부가 나타나면 장애물과 구별하기 어려워 거절할 수 있습니다.

여러 조각의 메시로 만든 실제 지면이나 조각한 지형에는 제작자가 **`FFZS_TileGround` 태그**로 지면임을 명시할 수 있습니다. 태그는 이름표이며, 건축 허가를 주는 기능은 아닙니다.

1. 레벨에서 실제 바닥 메시가 있는 액터를 선택합니다.
2. Components에서 **지면 역할을 하는 메시 컴포넌트**를 선택합니다.
3. Details에서 `Component Tags`를 찾아 항목을 추가하고 `FFZS_TileGround`를 정확히 입력합니다.
4. 여러 지면 조각이 있으면 필요한 지면 컴포넌트에 각각 적용합니다.
5. 지면에 충돌 모양이 있고 `Visibility` 검사에 `Block`으로 응답하는지 확인한 뒤, Play에서 다시 배치합니다.

액터 전체가 지면만으로 구성되었다면 `Actor Tags`에 같은 태그를 넣어도 됩니다. **같은 액터 안에 벽·기둥·장식물이 있으면 지면 컴포넌트에만 태그를 넣으세요.** 하나의 메시 안에 벽과 바닥이 붙어 있다면 지면 메시를 분리하는 편이 안전합니다. 태그를 벽에 붙이면 게임이 그 벽 꼭대기를 타일을 받치는 땅으로 해석할 수 있습니다.

태그가 있어도 지면 누락, 높이 차, 경사, 건축 구역, 금지 구역과 기존 점유 검사는 유지됩니다. 설치를 강제로 통과시키기 위해 주변 모든 액터에 붙이지 마세요.

## 5. 타일 위 건축물과 이동

설치된 타일에는 **`TileSupportSurface`라는 평평한 충돌용 바닥**이 생깁니다. 이 바닥은 타일 데이터의 가로·세로 크기와 두께를 따릅니다. 타일의 그림용 메시가 늦게 로드되거나 충돌 모양이 울퉁불퉁해도 건축물의 지면 검사와 플레이어의 바닥 충돌은 이 평면을 사용할 수 있습니다.

타일 위 건축물은 여전히 자기 바닥 전체를 검사합니다. 건물이 타일 밖으로 돌출되거나 서로 높이가 다른 타일에 걸치면, 건물 쪽 경사·높이 차 등 일반 설치 조건 때문에 거절될 수 있습니다.

타일은 **한 장씩 각자의 지면 최고점**으로 높이를 정합니다. 옆 타일과 높이를 자동으로 맞추지 않으므로 경계에 단차가 생길 수 있습니다. 시설을 받치고 있는 타일을 바로 철거하는 기존 제한도 유지됩니다. 먼저 위 시설을 적절히 이동하거나 철거해야 합니다.

새 최고점 계산은 설치·이동·크기 변경 때 적용합니다. **기존 세이브를 불러오는 것만으로 이미 설치된 타일의 높이를 자동 변경하지는 않습니다.** 이전에 놓은 타일에도 새 높이를 적용하려면 위 시설을 먼저 옮긴 뒤 타일을 다시 배치합니다. 새로 설치한 타일의 높이는 저장·불러오기 후에도 유지됩니다.

이번 기능에는 다음 작업이 포함되지 않습니다.

- 원래 지형을 깎거나 평평하게 만드는 작업
- 타일 아래 빈 공간을 흙이나 기초 메시로 채우는 작업
- 여러 타일을 하나의 높이로 자동 정렬하거나 경사로를 만드는 작업
- 손님용 이동 지도인 NavMesh를 자동으로 넓히는 작업

따라서 설치가 가능해져도 손님이 시설까지 찾아오는지, 플레이어가 타일 사이의 단차를 넘을 수 있는지는 실제 맵에서 별도로 확인합니다.

## 6. 기획자가 값을 조정하는 방법

Unreal Editor의 **Edit → Project Settings → Game → FF Zone System**에서 조정합니다. 타일 전용 항목은 **Placement → Tile**에 있습니다.

| 설정 이름 | 기본값 | 바꾸면 달라지는 것 |
| --- | --- | --- |
| `Tile Maximum Ground Slope (Degrees)` / `MaxTileGroundSlopeDegrees` | 89도 | 타일 아래 검사 지점에서 허용할 최대 경사 |
| `Tile Maximum Ground Height Difference (cm)` / `MaxTileGroundHeightVarianceCm` | 2000cm | 타일 아래 최고·최저 지면 높이 차의 상한 |
| `MaxGroundSlopeDegrees` | 15도 | 길과 일반 건축물의 경사 기준 |
| `MaxGroundHeightVarianceCm` | 80cm | 길과 일반 건축물의 높이 차 기준 |
| `GroundTraceAboveCm` / `GroundTraceBelowCm` | 각각 1000cm | 구역 기준 높이의 위·아래 지면 검색 거리 |
| `GroundSampleSpacingCm` | 100cm | 지면 검사 지점의 기본 간격. 줄이면 검사가 촘촘해지고 비용이 증가함 |

프로젝트의 공유 설정은 **`Config/DefaultGame.ini`**에서 관리합니다.

```ini
[/Script/FF_ZoneSystem.FFZSDeveloperSettings]
MaxGroundSlopeDegrees=15.000000
MaxGroundHeightVarianceCm=80.000000
MaxTileGroundSlopeDegrees=89.000000
MaxTileGroundHeightVarianceCm=2000.000000
GroundTraceAboveCm=1000.000000
GroundTraceBelowCm=1000.000000
bEnableGroundChecks=True
```

이 기능을 처음 반영할 때는 C++ 변경이 있으므로 에디터를 종료하고 **Editor 빌드를 다시 만든 뒤 재시작**해야 합니다. 이후 허용 수치만 바꾸는 경우에는 C++ 재컴파일이 필요하지 않습니다. INI를 직접 바꿨다면 에디터를 다시 열어 실제 로드된 값을 확인하세요. 다른 사람에게 실행 파일로 전달하려면 변경 코드와 설정을 포함한 새 패키지가 필요합니다.

플러그인의 `DefaultFF_ZoneSystem.ini`는 출하 기준 기록입니다. 이 파일만 수정해도 프로젝트의 `DefaultGame.ini`가 바뀌는 것은 아닙니다.

## 7. 잘 안 될 때 확인할 것

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 타일도 경사 때문에 거절됨 | 시설 분류가 실제로 `Tile`인지, 타일 전용 설정이 로드되었는지 확인합니다. 이름만 ‘타일’인 `Road`는 일반 기준을 사용합니다. |
| 땅이 보이는데 지면이 없다고 나옴 | 충돌용 바닥과 `Visibility: Block` 응답, 구역 기준 높이의 검색 범위, 타일 가장자리의 지면 유무를 확인합니다. |
| 평평한 메시 경계나 돌출된 지형에서 거절됨 | 실제 지면을 여러 메시로 나누었는지 확인합니다. 실제 지면에만 `FFZS_TileGround` 컴포넌트 태그를 적용합니다. |
| 격자는 보이는데 설치가 안 됨 | 타일 전체가 건축 영역 안에 있는지, 금지 영역·다른 시설·장애물과 겹치는지, 화면 실패 사유를 확인합니다. |
| 타일이 높이 떠 보임 | 아래에서 가장 높은 지형과 실제 충돌 모양을 확인합니다. 낮은 쪽의 빈 공간은 자동으로 메워지지 않습니다. |
| 타일 위 건축물이 거절됨 | 건물 전체가 같은 높이의 지지면에 올라가는지와 건물의 일반 경사·높이 차 기준을 확인합니다. |
| 설치했지만 손님이 오지 않음 | 시설 운영 상태와 손님 이동 경로·NavMesh를 별도로 확인합니다. |
| 설정을 바꿔도 차이가 없음 | 프로젝트 INI, 실행 중 에디터 재시작 여부, 실제 실행한 빌드가 최신인지 확인합니다. |

## 8. 변경 후 플레이 확인 순서

아래는 레벨 제작자가 실제 맵에서 수행할 확인 목록입니다. 작성 자체가 검증 완료를 의미하지는 않습니다.

1. 허용 구역 안의 가파른 지면에서 같은 크기의 길과 타일을 비교합니다. 일반 기준을 넘는 지면에서도 타일 전용 기준 안이면 타일이 수평으로 놓여야 합니다.
2. 타일을 회전시키고, 높은 지형이 타일 중앙·가장자리·모서리에 오도록 움직입니다. 높은 지형이 타일을 뚫고 올라오지 않는지 확인합니다.
3. 타일 일부가 구역 밖, 구역 사이 구멍, `NoBuild`, 기존 타일·길·시설에 걸치면 설치가 거절되는지 확인합니다.
4. 타일 아래에 지면이 없는 검사 지점이 생기면 거절되는지 확인합니다. 벽과 장식물을 지면으로 인식시키지 않았는지도 확인합니다.
5. 메시 지면에서는 태그가 필요한 조각에만 적용한 뒤, 실제 벽은 계속 설치를 막는지 확인합니다.
6. 타일 위에 일반 건축물을 놓고 바닥 높이를 확인합니다. 그 타일의 철거가 제한되는지 확인합니다.
7. 옆 타일의 단차, 플레이어의 걸음, 손님의 접근 경로를 확인합니다. 저장 후 불러온 상태에서도 같은 바닥과 높이를 유지하는지 확인합니다.

| `Plugins/FF_ZoneSystem/Source/FF_ZoneSystem/Private/FF_FFZSBuildGridSurface.cpp` | 선택한 시설의 지면 기준에 맞는 격자 안내와 검사 결과 재사용 |
| `Plugins/FF_ZoneSystem/Source/FF_ZoneSystemTests/Private/FF_FFZSRoadTerrainPlacementTests.cpp` | 타일 높이·제한·타일 위 건축과 기존 길 동작의 자동 검사 |
| `Plugins/FF_ZoneSystem/Source/FF_ZoneSystemTests/Private/FF_FFZSBuildGridSurfaceTests.cpp` | 타일·길을 바꿔 선택했을 때 격자와 장애물 높이 판단의 자동 검사 |

새 설치 기능에서도 분류를 받는 `ResolveGroundValidationSettings(Category)`를 사용하면 타일 기준과 일반 기준이 어긋나지 않습니다. 분류 없는 기존 호출은 일반 시설 기준을 유지합니다. 최고점 계산, 타일의 평면, 화면 격자는 각각 맡은 파일에서 관리하며 같은 숫자를 여러 곳에 임의로 복사하지 않습니다.

## 10. 검증 기록

2026-10-07, Unreal Engine 5.7.4 / Windows Development Editor에서 확인했습니다.

| 검사 범위 | 결과 |
| --- | --- |
| Editor C++ 빌드 | 성공 |
| 타일·길·배치 격자·바닥 충돌·지면 설정 | **37개 모두 통과**. 아래 전체 검사에 포함된 결과입니다. |
| `FF_ZoneSystem` 전체 | 149개 중 **147개 통과**, 관람객 면적 검사 2개 실패. 통과 항목 중 1개는 경고가 있습니다. |
| 건설 모드 `FestaFiesta.Building.BuildMode` 별도 검사 | 19개 모두 통과. 이 중 3개는 시험용 입력 객체 관련 경고가 있습니다. |

타일 관련 자동 검사에는 높은 지면 위 수평 배치, 경사·높이 차 설정 분리, 지면 누락, 구역 밖·금지 구역·기존 점유 거절, 표본 사이 지형 돌출부, 작은 타일 아래 기둥, 메시 지면 태그, 타일 위 건축, 이동·철거 제한, 저장·복원, 실제 길·타일 메시가 포함됩니다. 타일의 그림용 메시가 없어도 정확한 크기의 평평한 바닥을 제공하는지도 확인했습니다.

전체 검사에서 실패한 항목은 `FF_ZoneSystem.Audience.CapacityAutoFit`와 `FF_ZoneSystem.Audience.CapacityPropertyEditsAndUndo`입니다. 관람객 영역 한도에 각각 610m², 1174m²가 기록되기를 기대하지만 실제 값은 0입니다. 여기서 0은 ‘공통 한도 사용’을 뜻합니다. 현재 공통 한도 2000m²로 충분하면 별도 한도를 만들지 않는 코드와 검사 기대값이 맞지 않는 것을 확인했습니다. 해당 관람객 코드와 검사는 이번 타일 작업에서 수정하지 않았습니다. 변경 전 버전을 따로 실행해 재현한 결과는 아니며, 전체 검사 완료로 표시하려면 이 두 항목을 별도로 정리해야 합니다.

전체 검사의 경고 1개는 스냅샷 시험 환경의 `GameInstance is invalid`이며, 별도 건설 모드 검사의 경고는 시험용 LocalPlayer에 PlayerInput이 없다는 EnhancedInput 경고입니다. 해당 검사들의 결과는 통과입니다.

개발자가 전체 검사를 다시 실행할 때는 프로젝트 폴더의 PowerShell에서 다음 명령을 사용합니다.

```powershell
& '.\Tools\Build\Run-AutomationTests.ps1' -TestFilter @('FF_ZoneSystem') -OutputRoot 'Artifacts\Validation\TileFoundation-Review' -SkipDataValidation
```

최종 전체 결과는 `Artifacts/Validation/TileFoundation-20261007-Complete/FF_ZoneSystem/Report/index.json`, 별도 건설 모드 결과는 `Artifacts/Validation/TileFoundation-20261007-Verified/FestaFiesta.Building.BuildMode/Report/index.json`에 있습니다. 이 경로는 로컬 검증 산출물이며 저장소에 배포하는 사용자 문서는 아닙니다.

자동 검사는 분리된 시험 지형에서 규칙을 확인합니다. **실제 전체 맵의 수동 플레이, 에셋 전체 데이터 검사와 새 게임 패키지 제작은 이번 검증에 포함하지 않았습니다.** 배포 전에는 8절의 플레이 확인을 수행합니다.

건축 가능 범위 편집은 [시설 설치 가능 지역 안내](../Tools/ZoneSystem/FACILITY_PLACEMENT_GUIDE_KO.md), 일반 시설의 15도·80cm 기준은 [시설 설치 지형 기준 안내](FacilityGroundPlacement_UserGuide_KO.md)를 참고하세요.
