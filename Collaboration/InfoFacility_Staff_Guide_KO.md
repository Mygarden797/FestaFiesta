# 안내 시설(Info) 스태프 설정·배정·출동 가이드

이 문서는 코드를 수정하지 않고 시설별 스태프 정원을 설정하고, 게임에서 고용·배정·출동을 확인하는 방법을 설명합니다.

## 1. 먼저 알아둘 네 가지 숫자

| 항목 | 의미 | 증가하는 때 |
| --- | --- | --- |
| 보유 인원 | 실제로 함께 일하는 스태프 수 | 축제의 초기 인원 제공 또는 고용 버튼 사용 |
| 보유 가능 최대 | 추가로 고용할 수 있는 범위를 정하는 전체 한도 | 정원이 있는 안내 시설 설치 |
| 시설 배정 인원 | 특정 안내 시설을 출발지로 사용하는 스태프 수 | 그 시설의 `+ 배정` 버튼 사용 |
| 출동 중 | 현장 이동·사건 대응·시설 복귀 중인 스태프 수 | 사건 아이콘을 눌러 출동에 성공 |

**시설을 설치해도 사람이 생기거나 자동으로 배정되지 않습니다.** 먼저 필요한 만큼 고용하고, 안내 시설에 배정해야 출동할 수 있습니다. 축제 시작 시 제공되는 기본 인원도 안내 시설 배정이 필요합니다.

> **2026-10-07부터 메인안내소 1곳은 필수 시설입니다.** 메인안내소(`Info_GeneralInfo_General`)를 설치하고 **스태프를 1명 이상 배정해야** `확정하고 Day 1 시작`·`개장하기`가 열립니다. 플레이어가 배정 단계를 놓치지 않게 하려는 조건이며, 자세한 내용은 아래 「필수 안내소와 배정 조건」을 참고하세요.

예를 들어 보유 인원이 1명(기본 제공 인원), 현재 보유 가능 최대가 7명일 때 정원 3명인 안내 시설을 설치하면 **보유 1명 / 최대 10명**이 됩니다. 이 시설에 1명을 배정하면 **시설 배정 1 / 3명**이 되며, 보유 인원은 계속 1명입니다. 1명을 고용해야 보유 인원이 2명으로 늘어납니다.

## 2. 시설마다 정원 바꾸기

1. 언리얼 에디터에서 **콘텐츠 브라우저**를 엽니다.
2. `Content/FestaFiesta/Building/FF_Data_Building/Info` 폴더를 엽니다.
3. 바꿀 시설의 `PDA_FFZS_...` 데이터 에셋을 엽니다. 예: `PDA_FFZS_Info_GeneralInfo_General`.
4. 시설의 `Category`가 **Info**인지 확인합니다.
5. **Facility Staff → Staff Capacity**에 그 시설 **한 곳**에 배정할 최대 인원을 입력합니다. 검색 칸에 `Staff Capacity`를 입력해도 됩니다. 기본 상세 화면을 사용하는 경우에는 **Spec → Staff** 아래에 표시됩니다.
6. 저장하고 플레이를 시작해 해당 시설을 새로 설치합니다.

| Staff Capacity | 결과 |
| --- | --- |
| 0 | 이 안내 시설은 스태프 자리를 제공하지 않음 |
| 2 | 한 곳당 배정 자리 2개와 추가 고용 한도 2명 제공 |
| 5 | 한 곳당 배정 자리 5개와 추가 고용 한도 5명 제공 |

현재 기본값은 **2명**입니다. 같은 에셋의 시설을 두 곳 설치하면 각 시설이 자기 정원을 가지며, 전체 한도에는 두 시설 정원의 합이 더해집니다. `Info`가 아닌 시설은 스태프 정원을 제공하지 않습니다.

**이미 설치한 시설에는 설치 당시 값이 저장됩니다.** 데이터 에셋을 바꿔도 기존 시설이나 저장 게임의 정원을 일괄 덮어쓰지 않습니다. 새 값 확인은 새로 설치한 시설에서 진행하세요.

## 3. 축제 전체의 기본 인원·가격 설정

현재 축제에서 사용하는 **Festival Definition** 데이터 에셋을 열면 다음 값을 바꿀 수 있습니다.

| 설정 | 뜻 |
| --- | --- |
| Initial Staff Count | 시작할 때 실제 제공되는 기본 인원. 2026-10-09부터 기본값 **1명**(메인안내소 필수 배정만 채움, 이전 6명). 사건 대응 인력은 고용으로 확보 |
| Max Hired Staff Count | 안내 시설 보너스를 제외한 기본 추가 고용 한도 |
| Staff Hire Cost Gold | 스태프 1명을 한 번 고용하는 가격 |

계산 방법은 다음과 같습니다.

```text
보유 가능 최대 = 초기 기본 인원 + 기본 추가 고용 한도 + 설치한 Info 시설 정원의 합
남은 고용 자리 = 기본 추가 고용 한도 + Info 시설 정원 합 - 이미 고용한 인원
```

시설을 지은 만큼만 추가 고용 한도가 생기게 하려면 **Max Hired Staff Count를 0**으로 설정하세요. 초기 기본 인원을 없애려면 **Initial Staff Count도 0**으로 설정합니다. 두 항목은 서로 다른 설정입니다.

## 4. 게임에서 사용하는 순서

1. 셋업 또는 개장 준비 단계에서 안내 시설을 설치합니다.
2. 스태프 고용 패널에서 현재 인원과 보유 가능 최대가 따로 표시되는지 확인합니다.
3. 인원이 더 필요하면 원하는 수를 선택해 **고용**합니다. 잔액과 남은 고용 자리가 필요합니다.
4. 설치한 안내 시설을 선택하고 **기본 · 조합 · 운영 · 스태프** 중 **스태프** 탭을 엽니다. 이 탭에서 배정 인원과 정원을 확인합니다. 스태프 배정을 지원하지 않는 시설은 스태프 탭을 숨기며, 배정 인원이 0명인 안내 시설은 계속 표시합니다. 점검 화면의 배정 부족 안내 오른쪽 **스태프 배정 →** 버튼으로도 해당 안내소의 스태프 탭으로 바로 이동합니다.
5. **+ 배정**을 누르면 미배정 상태로 대기 중인 스태프 1명이 그 시설에 배정됩니다.
6. **- 해제**를 누르면 그 시설에서 대기 중인 스태프 1명이 미배정 상태가 됩니다. 해제는 해고가 아니므로 보유 인원과 돈은 그대로입니다.
7. 다른 시설로 옮기려면 기존 시설에서 해제한 뒤 새 시설에서 배정합니다.
8. 라이브 중 사건 아이콘을 클릭하면 필요한 인원이 배정된 안내 시설에서 출발합니다.

시설 배정은 라이브 중에도 조절할 수 있습니다. 다만 **이미 출동한 스태프는 복귀하기 전까지 해제하거나 다른 사건에 중복 출동시킬 수 없습니다.** 고용은 기존과 같이 셋업·개장 준비에서만 가능합니다.

### 필수 안내소와 배정 조건

축제 기본 필수 시설은 **선셋 메인공연장 1개**와 **메인안내소 1개**입니다. 메인안내소는 설치에 더해 **스태프 1명 이상 배정**까지 해야 조건이 풀립니다. 다른 안내 시설에 배정한 인원은 대신 세지 않으며, 같은 메인안내소를 여러 곳 지었다면 배정 인원을 합쳐서 봅니다. 출동 중인 인원도 소속이므로 배정으로 셉니다.

플레이어에게는 다음 순서로 보입니다.

| 상태 | 화면 안내 |
| --- | --- |
| 설치 전 | 카탈로그 `안내` 탭 느낌표와 카드 `필수 · 1개 설치` 배지. 카드 툴팁에 `설치 후 스태프 배정 필요` |
| 설치 후 미배정 | `메인안내소: 스태프를 1명 더 배정해야 합니다. (배정 0/1)` 안내. 점검의 안내 문구 오른쪽 **스태프 배정 →** 버튼을 누르면 해당 안내소의 **스태프** 탭과 `+ 배정` 버튼으로 이동 |
| 대기 스태프 없음 | 같은 자리에 `인력` 탭에서 고용하거나 다른 안내 시설에서 `- 해제`하라는 안내 |
| 시설 선택 시 | **스태프** 탭에 `! 필수 배정` 줄이 `+ 배정` 버튼 바로 위에 표시 |
| 배정 완료 | 점검 패널 `✓ 설치·배정 완료 (스태프 1명)`, 진행 버튼 활성 |

점검 패널의 인력 줄에는 보유 인원과 함께 `· 배정 N명`이 표시됩니다. 카탈로그의 `필수 · 1일차 시작 전 설치` 범례는 설치가 남았을 때만 보이고, 배정만 남은 상태는 하단 바 사유가 안내합니다.

조건을 바꾸려면 Festival Definition의 **Festival|Setup → Required Setup Facilities**에서 행마다 **Minimum Assigned Staff**를 조정합니다. `0`이면 설치만 요구합니다. 배정을 요구하는 행은 **Staff Capacity가 1 이상인 Info 시설**이어야 하고, 월드 설치 상한이 있으면 `상한 × 정원`을 넘을 수 없습니다. 어기면 데이터 검증 오류가 나고 필수 시설 줄에 설정 확인 안내가 뜹니다.

라이브 스태프 패널은 보유/최대, 미배정, 출동 인원을 보여줍니다. 대기 인원에는 미배정도 포함되므로, 대기 숫자가 있어도 안내 시설에 배정하지 않았다면 출동하지 않습니다.

## 5. 사건 출동과 복귀

- 필요한 인원 수가 충족되고 이동 경로가 있어야 출동합니다. 인원이 부족하면 일부만 출발하지 않습니다.
- 출발지는 소속 안내 시설의 **Exit 앵커 0번**입니다. Exit가 없으면 **Entry 앵커 0번**을 사용합니다.
- 가능한 배정 인원 중 사건 현장과 가까운 출발지의 인원을 우선 선택합니다.
- 사건 현장에 필요한 인원이 모두 도착하면 해결합니다. 움직이는 사건 대상은 이동 경로를 다시 계산하며 따라갑니다. (10/14 기준: 선택지에 작업량(`Work Amount`)이 있으면 전원 도착 뒤 `작업량 ÷ 능력치 합` 축제 분 동안 일한 뒤 해결합니다. 능력치 합은 숙련도 높은 순으로 최소 인원까지 레벨 그대로, 넘는 인원은 절반입니다.)
- 해결 후에는 이동했던 경로를 되짚어 시설로 복귀합니다. 돌아오는 동안도 출동 중으로 집계합니다.
- 출동이 시작되면 사건 아이콘의 툴팁에 **스태프 출동 중** 안내가 표시됩니다. 출동하지 못하면 배정과 이동 경로를 확인하라는 안내가 표시됩니다.

시설 출입구에서 사건 위치까지 **NavMesh(캐릭터가 걸을 수 있는 영역)**가 연결되어 있어야 합니다. 에디터 뷰포트에서 `P` 키로 이동 가능 영역을 표시하고, 안내 시설의 출입구가 건물 내부나 벽 안에 묻혀 있지 않은지 확인하세요. 출입구 좌표는 시설 데이터 에셋의 **Entry / Service / Exit Anchors**에서 설정합니다.

### 사건별 필요한 인원

`Content/FestaFiesta/Data/Incident`의 사건 데이터 에셋을 열어 **Incident → Staff → Required Staff**를 설정합니다.

- `1`: 아이콘을 클릭하면 1명 출동. 현재 기본값입니다.
- `2` 이상: 그 수만큼 출동 가능해야 진행.
- `0`: 스태프 이동 없이 처리하는 단순 알림.

별도 선택지를 사용하는 사건은 선택지의 **Cost Staff**를 사용합니다. 일반 사건 아이콘 클릭은 **Required Staff**를 사용합니다.
(10/14 기준: 선택지는 **Cost Staff**가 아니라 **Option → Staff → Min Staff**를 씁니다. 플레이어가 상세 패널에서 최소 인원 이상, 그때 출동 가능한 인원 이하로 보낼 수를 고릅니다. **Cost Staff**와 **Cost Gold**는 지금 출동 경로에서 쓰이지 않습니다.)

화면 알림처럼 실제 현장 위치가 없는 **Screenspace** 사건은 **Required Staff를 0**으로 설정합니다. 선택지를 사용한다면 해당 선택지의 **Cost Staff도 0**이어야 합니다. (10/14 기준: 선택지의 Min Staff는 최소 1이라 선택지를 고르면 항상 1명 이상 출동을 시도합니다. 스태프 없이 처리하려면 선택지 없이 Required Staff를 0으로 둡니다.) 구역을 대상으로 하는 **Zone** 사건은 그 구역의 첫 **Entry / Exit 앵커**를 현장으로 사용하며, 앵커가 없으면 구역 액터 위치를 사용합니다.

### 스태프 외형·이동 속도

**편집 → 프로젝트 세팅 → Game → FestaFiesta Incident → Staff Response**에서 변경합니다.

| 설정 | 사용 방법 |
| --- | --- |
| Staff Responder Class | 스태프 외형으로 쓸 `AFF_BaseCrowd` 계열 블루프린트를 선택 |
| Staff Travel Speed | 이동 속도(cm/초). 기본값 300은 초당 3m |

외형 클래스를 비워도 기본 표시용 원기둥으로 출동과 복귀를 확인할 수 있습니다. 실제 직원 모습이 필요하면 프로젝트의 직원용 캐릭터 블루프린트를 지정하세요.

## 6. 철거와 저장

안내 시설을 철거하면 그 시설이 제공하던 정원이 전체 한도에서 빠지고, 소속 스태프는 미배정 상태가 됩니다. **기존 스태프를 자동 해고하지 않습니다.** 철거로 보유 인원이 최대보다 많아지면 추가 고용이 잠기며, 다시 시설을 설치해 한도를 늘릴 수 있습니다.

스태프 명단과 소속 시설은 저장됩니다. 불러올 때 존재하지 않는 시설에 대한 배정은 정리됩니다. 이동 중인 캐릭터와 출동 예약은 저장하지 않으며, 불러오기에서 기존 이동을 취소하고 사용 가능한 상태로 정리합니다.

## 7. 빠르게 확인하는 체크리스트

1. 정원 2명인 안내 시설을 설치하고, **보유 인원은 그대로 / 최대만 +2**인지 확인합니다.
2. 추가 고용하고, 보유 인원과 잔액이 함께 바뀌는지 확인합니다.
3. 시설의 `+ 배정`으로 2명까지 배정하고, 정원이 차면 버튼이 비활성화되는지 확인합니다.
4. `- 해제` 후 보유 인원이 줄지 않는지 확인합니다.
5. 1명 필요한 사건을 클릭하고, 시설 출입구에서 현장으로 이동한 뒤 복귀하는지 확인합니다.
6. 이동·복귀 중 해당 스태프를 다른 사건에 중복 사용하거나 해제할 수 없는지 확인합니다.
7. 미배정 상태 또는 경로가 끊긴 상태에서 사건이 바로 해결되지 않는지 확인합니다.
8. 시설을 철거하고, 최대만 줄고 기존 인원은 유지되는지 확인합니다.
9. 배정한 상태로 저장 후 불러와 같은 시설 배정이 유지되는지 확인합니다.
10. 메인안내소를 설치만 한 상태에서 Day 1 시작이 막히고 `+ 배정` 안내가 보이는지, 1명 배정하면 바로 풀리는지 확인합니다.
11. 메인안내소의 스태프를 모두 `- 해제`하면 다시 막히는지 확인합니다.

| 증상 | 확인할 곳 |
| --- | --- |
| Staff Capacity 항목이 안 보임 | 해당 시설의 Category가 Info인지 확인 |
| 설치했는데 사람이 안 늘어남 | 정상 동작. 설치 후 고용 버튼 사용 |
| + 배정이 비활성화됨 | 시설 빈자리와 미배정 대기 인원 확인 |
| - 해제가 비활성화됨 | 배정 인원이 없거나 모두 출동 중인지 확인 |
| 사건을 눌러도 출발하지 않음 | 필요한 인원, 시설 배정, 출입구, NavMesh 연결 확인 |
| 숫자를 바꿨는데 기존 시설은 그대로 | 새 시설을 설치해 확인. 설치 당시 값은 저장됨 |
| 철거 후 보유가 최대보다 큼 | 기존 고용 인원은 보호됨. 정원을 다시 확보하면 추가 고용 가능 |
| 메인안내소를 지었는데 Day 1 시작이 막힘 | 정상 동작. 메인안내소를 선택해 `+ 배정`으로 1명 이상 배정 |
| `+ 배정`이 비활성이라 필수 배정을 못 함 | 대기 스태프가 없음. 인력 탭에서 고용하거나 다른 안내 시설에서 `- 해제` |

## 8. 화면을 꾸미거나 개발자가 이어 작업할 때

시설 정보 WBP는 `Content/FestaFiesta/Building/FF_WBP_Building/Facility/WBP_FF_FacilityInfoPanel`입니다. 기존 화면에는 실행 시 스태프 영역 하나가 추가됩니다. 디자이너가 직접 배치하려면 아래 이름의 위젯을 만들어 **Is Variable**을 켜고 저장합니다. 이름과 종류를 맞추면 직접 만든 영역을 우선 사용합니다.

| 이름 | 위젯 종류 |
| --- | --- |
| Panel_StaffSection | 영역을 감싸는 Vertical Box 등 컨테이너 |
| Text_StaffSummary | Common Text Block |
| Button_AssignStaff | Button |
| Button_UnassignStaff | Button |

네 위젯을 한 영역으로 함께 추가하고, 두 버튼의 글자는 각각 `+ 배정`, `- 해제`로 넣으세요. 동작 연결용 블루프린트를 따로 만들 필요는 없습니다. 기존 위젯 이름을 바꾸거나 기존 조명·시설 정보 영역을 지울 필요도 없습니다.

개발 구조는 다음처럼 역할을 분리합니다.

| 담당 | 역할 |
| --- | --- |
| 시설 데이터의 Staff Capacity | 시설별 정원 설정과 저장 |
| Festival Progression | 실제 스태프 명단, 고용 비용, 동적 고용 한도 |
| Staff Facility Subsystem | 배정·해제·정원·중복 출동 방지의 공통 규칙 |
| Staff Dispatch Subsystem | 시설 출발, 이동, 사건 처리, 복귀 |
| Required Facilities Subsystem | 필수 안내소의 설치·배정 인원 판정과 안내 문구(배정 변경 시 갱신 신호) |
| ViewModel / Facility Info | 게임 데이터를 읽어 화면에 표시하고 사용자 요청 전달 |

정원과 고용 인원을 따로 관리하고, UI가 배정 규칙을 직접 만들지 않도록 구성했습니다. 정원 변경과 배정·출동 상태는 변경 이벤트로 전달하며, 시설 레지스트리 캐시를 이용해 매 프레임 전체 시설을 검색하지 않습니다.
