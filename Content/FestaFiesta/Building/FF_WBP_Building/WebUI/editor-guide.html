건축 카탈로그 WebUI 편집 안내

시설 카드는 HTML·CSS로 편집하고, 검색·분류·게임 상태는 기존 UMG와 연결합니다. 동기화하면 HTML, 실제 시설 썸네일, 프로젝트 NEXON 폰트가 카탈로그 위젯에 함께 저장됩니다.

웹 표시 범위는 시설 카드 목록입니다. 상단 도구·검색·즐겨찾기 필터·매출 순위·조합 도감·조작 안내는 UMG에서 유지됩니다. 게임패드 입력과 웹 로딩 실패 시에는 기존 UMG 카드가 표시됩니다. 별도 웹 서버 없이 위젯에 저장된 화면을 사용합니다.

저장 대상: 카탈로그 위젯 1개

편집과 적용

  1. 이 폴더의 catalog-ribbon.html을 편집합니다. 색상·간격·모서리·글자 크기는 파일 상단의 CSS에서 조정합니다.
  2. Unreal에서 PIE를 종료합니다. 현재 프로젝트에 FF_BuildCatalogWebView의 네이티브 편집 도우미가 빌드되어 있어야 합니다.
  3. Unreal의 Tools → Execute Python Script에서 이 폴더의 sync_to_umg.py를 실행합니다. 썸네일을 렌더링하므로 렌더링이 활성화된 에디터에서 실행합니다.
  4. Saved/BuildingWebUI20261008/latest-sync.json에서 status: PASS를 확인합니다. 실행 중에는 동기화 대상 파일 편집을 잠시 기다립니다.
  5. PIE에서 건축 카탈로그를 열어 1920×1080과 1280×720의 글자·카드·스크롤·선택·즐겨찾기를 확인합니다.

HTML을 일반 브라우저에서 열면 게임 데이터가 연결되지 않아 대기 상태가 표시됩니다. 실제 시설 목록과 동작 확인은 PIE에서 진행합니다.

현재 카드 규격

아래 수치는 UMG의 논리 좌표에 맞춘 CSS 크기입니다. 화면 크기에 따른 배율은 WebUI가 자동으로 계산합니다.

요소현재 규격CSS 위치
시설 카드184 × 210 px · 모서리 12 px.card
가로 카드 간격10 px#ribbon의 gap
썸네일 프레임162 × 104 px · 왼쪽 10 px · 위 9 px.thumb · object-fit:contain
시설 이름162 × 48 px · 최대 2줄 · 글자 21.333 px.name · 줄 높이 24 px
가격162 × 28 px · 글자 26.667 px.price
즐겨찾기 버튼44 × 44 px.favorite
임베딩 썸네일긴 변 최대 256 pxsync_to_umg.py 상단의 THUMBNAIL_MAX_DIMENSION

CSS 크기를 바꾸면 규격표도 함께 갱신합니다. 카드 전체 크기를 바꿀 때는 .card, .select, 선택 상태, 리본 높이와 진단용 metrics() 수치를 함께 맞춥니다. 주변 UMG 영역은 별도로 크기를 확인합니다.

폰트와 배율

기존 NEXON_Lv2_Gothic_OTF_Font에서 읽은 폰트를 FFBuildingFont로 포함합니다. 원본 폰트 에셋은 수정하지 않습니다. UMG의 글자 크기 16은 CSS 약 21.333 px, UMG 20은 CSS 약 26.667 px에 해당합니다.

리본 배율은 window.innerWidth / snapshot.logicalWidth로 계산합니다. 카드의 CSS 크기는 논리 크기로 유지하고, 720p용 별도 크기나 고정 배율을 추가하지 않습니다.

현재 시설 데이터 사용

동기화 스크립트는 실행할 때마다 FF_Data_Building의 현재 시설 정의를 읽습니다. 카탈로그 노출이 활성화된 시설의 실제 CatalogThumbnail을 렌더링하며, 시설 ID나 파일 이름을 추측하지 않습니다. 시설 데이터와 원본 이미지에는 저장 작업을 하지 않습니다.

썸네일이 비어 있는 시설은 결과 보고서의 missing_optional_thumbnails에 기록되고 웹 카드에서 자리 표시자를 사용합니다. 기존 썸네일이 있는데 렌더링에 실패하면 동기화를 실패로 처리하여 불완전한 결과를 저장하지 않습니다.

적용 범위와 복구

저장되는 에셋은 Catalog/WBP_FF_PrepPanelBuild 하나입니다. 기존 검색·필터·빈 상태·TileView를 보존하고, Web_CatalogRibbon에 웹 문서와 데이터를 반영합니다. 같은 입력으로 다시 실행하면 위젯을 중복 생성하지 않고, 변경이 없을 때 저장을 생략합니다.

실행별 Saved/BuildingWebUI20261008/sync-…/Backup에 원본 카탈로그가 보관됩니다. 모든 Content와 프로젝트 구현 입력의 전후 해시를 비교하여 다른 에셋의 변경을 확인합니다. 실패 결과에는 원인과 카탈로그 복구 여부가 기록됩니다.

웹 화면의 시설 선택과 즐겨찾기는 기존 게임 상태를 통해 처리합니다. CSS를 편집할 때 window.ffBuilding.render(snapshot), 시설 ID, 네이티브 연결 및 콘텐츠 보안 정책은 유지합니다.
