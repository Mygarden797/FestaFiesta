# 길과 시설을 드래그로 계속 설치하기

> Road/Tile 분리 후에도 드래그 설정은 각 데이터 에셋에서 편집합니다. Road는 시설 설치가 불가능한 길이고 Tile은 시설을 올릴 수 있는 바닥입니다. 두 카테고리 모두 아래 조작을 사용합니다.

시설을 고른 뒤 왼쪽 마우스 버튼을 누른 채 움직이면 같은 시설이 이동 경로를 따라 설치됩니다. 길처럼 여러 개를 이어 놓는 시설에 사용할 수 있습니다. 어떤 시설에 이 기능을 사용할지는 각 시설의 **데이터 에셋**에서 정합니다.

데이터 에셋은 시설의 설정표입니다. 모래길, 나무 데크길처럼 시설 종류마다 한 개씩 있고, 설치 크기·이름·그림·배치 방식 등을 보관합니다. 기능을 켜고 끄는 작업에는 C++ 코드를 수정할 필요가 없습니다.

## 1. 게임에서 사용하는 방법

1. 건설 메뉴에서 설치할 길이나 시설을 선택합니다.
2. 건축할 수 있는 바닥에 마우스를 올립니다.
3. 필요한 방향으로 먼저 회전합니다. `Q/E`는 일정 각도로, `Shift+Q/E`는 누르는 동안 부드럽게 회전합니다.
4. 왼쪽 마우스 버튼을 누릅니다. 시작 위치에 첫 시설이 설치됩니다.
5. 버튼을 누른 상태로 마우스를 이동합니다. 지나가는 방향으로 시설이 이어집니다.
6. 버튼을 놓으면 설치가 끝납니다. 다른 위치에서 다시 누르면 새 구간을 시작합니다.

**짧게 좌클릭하면 한 개가 설치됩니다. 왼쪽 버튼을 꾹 누른 채 이동하면 연속으로 설치됩니다.** 연속 설치 체크가 꺼져 있어도 짧은 클릭 설치는 사용할 수 있습니다. 같은 자리에 가만히 누르고 있을 때는 중복 설치하거나 비용을 반복 차감하지 않습니다. `Enter` 또는 화면의 `배치 확정` 버튼도 한 개를 설치합니다. 우클릭하면 시설 목록으로 돌아갑니다.

이미 깔린 길 위에서 누른 뒤 빈 공간으로 끌어도 이어서 설치할 수 있습니다. 첫 위치가 겹치면 그 위치는 건너뜁니다. 돈 부족이나 설치 개수 제한으로 시작이 막혔다면 조건을 해결한 뒤 버튼을 놓고 다시 눌러야 합니다.

드래그 도중 방향을 회전하면 현재 구간을 끝냅니다. 새 방향을 정한 뒤 버튼을 놓고 다시 누르면 됩니다. 기존 시설을 옮기는 모드에서는 한 개의 이동만 처리합니다.

### 설치된 시설의 정보 확인하기

준비 화면이나 시설 목록이 열린 상태에서 **이미 설치된 시설을 좌클릭하면 시설 정보가 열립니다.** 다른 시설을 클릭하면 그 시설의 정보로 바뀌고, 빈 바닥을 클릭하면 선택이 해제됩니다. 준비 화면에서는 건축 메뉴를 먼저 열 필요가 없습니다. 새 시설의 배치 미리보기가 떠 있다면 우클릭으로 시설 목록으로 돌아간 뒤 설치된 시설을 클릭합니다. 배치·이동 중 좌클릭은 해당 작업을 확정하는 용도로 사용합니다.

## 2. 시설별로 켜고 끄기

1. 언리얼 에디터의 **콘텐츠 브라우저**를 엽니다.
2. 길은 `Content > FestaFiesta > Building > FF_Data_Building > Road`, 타일은 같은 위치의 `Tile` 폴더에서 찾습니다.（10/14 기준 정정: 예전 경로 `Zone > Data > FacilityDefinitions`는 저장소에 없습니다. 실제 PDA는 `Content/FestaFiesta/Building/FF_Data_Building/Road`·`Tile`에 있고, `Config/DefaultGame.ini`의 Asset Manager 검색 경로도 `/Game/FestaFiesta/Building/FF_Data_Building`입니다.）
3. 원하는 시설 데이터 에셋을 더블클릭합니다. 예를 들어 모래길은 `PDA_FFZS_Road_Surface_Sand`입니다.
4. 최상위 **Placement** 항목을 펼칩니다.
5. **Enable Drag Placement**를 체크합니다. 찾기 어렵다면 상세 정보 검색창에 `Enable Drag Placement`를 입력합니다.
6. 저장하고, 게임에서 해당 시설을 다시 선택해 확인합니다.

이 체크박스는 **Facility Specification 안에 있지 않습니다.** 시설 데이터 에셋 자체의 `Placement` 항목에 있습니다.

| 설정 | 게임에서의 동작 |
|---|---|
| 켜짐 | 왼쪽 버튼을 누른 채 이동하면 같은 시설을 계속 설치 |
| 꺼짐 | 클릭 한 번에 시설 한 개 설치 |

새 일반 시설의 기본값은 꺼짐입니다. 길 외의 시설도 필요하면 켤 수 있습니다. 설정을 바꾸어도 이미 설치한 시설이 복제·이동되지는 않으며, 기존 저장 데이터의 시설 사양도 바뀌지 않습니다.

| 길 이름 | 데이터 에셋 이름 |
|---|---|
| 모래길 | `PDA_FFZS_Road_Surface_Sand` |
| 아스팔트길 | `PDA_FFZS_Road_Surface_Asphalt` |
| 나무 데크길 | `PDA_FFZS_Road_Surface_Wood` |
| 석재 타일길 | `PDA_FFZS_Road_Surface_Stone` |
| 헤링본 벽돌길 | `PDA_FFZS_Road_Surface_Herringbone` |
| 콘크리트길 | `PDA_FFZS_Road_Surface_Concrete` |

Tile PDA 이름은 위 표의 `Road`를 `Tile`로 바꾼 `PDA_FFZS_Tile_Surface_<종류>`입니다. 분리 시 기존 길의 작성된 크기와 드래그 설정을 복사합니다. 설치 크기는 각 PDA의 현재 값을 확인합니다. 상부 시설 설치는 Road에서 차단하고 Tile에서 허용하며, 이전 `길 위 시설 설치 허용` 플래그는 더 이상 편집 옵션이 아닙니다.

### 새 길 종류를 만들어 사용하기

1. 위 Road 폴더에서 기존 길 데이터 에셋을 우클릭하고 **Duplicate(복제)** 합니다. 원본을 남기고 복사본에서 작업합니다.
2. 복사본 파일 이름을 예를 들어 `PDA_FFZS_Road_Surface_MyRoad`로 정합니다.
3. 복사본을 열고 `Facility Specification`의 **Facility Definition Id**도 `Road_Surface_MyRoad`처럼 아직 사용하지 않는 값으로 바꿉니다. 파일 이름만 바꾸면 내부 ID가 중복되므로 이 단계가 필요합니다.
4. 표시 이름을 정하고, 카테고리는 **Road**, `Presentation > Show in Build Catalog`는 켜 둡니다. `Placement > Enable Drag Placement`도 켭니다. 시설을 올릴 바닥이 필요하면 Tile 폴더의 PDA를 복제하고 파일 이름·내부 ID·카테고리를 모두 **Tile** 기준으로 맞춥니다.
5. 외형을 바꾸려면 `Visual Mesh`를 원하는 메시로 변경하고 카탈로그 썸네일도 맞춥니다. 첫 확인은 복제한 외형과 설치 크기를 유지한 채 해도 됩니다.
6. 설치비는 복제한 `Install Cost Key`가 가리키는 기존 비용을 사용합니다. 새 가격이 필요하면 비용 표 `DT_FacilityCosts`에 사용할 행을 만들고 그 행 이름을 연결합니다.
7. 저장한 뒤 콘텐츠 브라우저에서 해당 에셋의 **Validate Assets(데이터 검증)**를 실행합니다. 오류가 있으면 먼저 해결합니다.
8. 실행 중인 게임을 종료하고 다시 Play하여 카탈로그에서 새 이름을 찾습니다. 짧은 직선부터 드래그해 확인합니다.

일반 시설은 같은 방식으로 **자기 카테고리와 대기열 설정을 유지한 채** 드래그만 켤 수 있습니다. 길처럼 만들기 위해 일반 시설의 카테고리를 Road로 바꾸면 서비스·대기열 의미가 달라지므로 별개의 제작 작업으로 다뤄야 합니다.

## 3. 설치 간격과 크기를 이해하기

설치 간격은 **각 데이터 에셋에 현재 저장된 바닥 크기**를 사용합니다. 별도로 간격 값을 입력하지 않습니다. 예를 들어 바닥 크기가 가로 400cm, 세로 400cm인 시설은 기본적으로 4m씩 이어집니다. 실제 길 6종은 제작자가 편집한 크기를 유지하므로 모두 4m 간격이라고 가정하면 안 됩니다. 직사각형 시설은 가로·세로 크기를 따로 사용하며, 회전하면 간격 방향도 함께 회전합니다.

`Ctrl/Alt`로 하는 정밀 위치 조정은 첫 시설의 시작 위치를 잡는 데 사용합니다. 드래그가 시작된 뒤에는 시설 크기가 연속 설치 간격의 기준이 됩니다. 마우스를 사선으로 움직이면 타일이 옆면으로 연결되는 계단 형태로 이어집니다.

0·90·180·270도에서는 시설 크기 그대로 이어집니다. 45도처럼 비스듬히 회전하면 게임의 1cm 좌표 반올림으로 서로 겹치지 않도록 약 1.42cm의 간격 보정을 자동 적용합니다. 실제 틈은 반올림에 따라 최대 약 2.83cm까지 생길 수 있습니다. 틈 없이 바르게 연결된 길을 만들려면 직각 방향을 사용합니다.

겉으로 보이는 3D 모델의 크기와 설치 판정용 바닥 크기는 구분됩니다. 모델만 크게 바꾸었다고 설치 간격이 자동으로 커지지는 않습니다. 시설 크기를 바꾸는 작업을 했다면 데이터 에셋의 바닥 크기도 실제 의도와 맞는지 확인합니다.

일반 시설은 대기열이나 관람 공간이 필요할 수 있습니다. 이런 시설은 드래그 기능을 켜도 모든 자리에 촘촘하게 설치되지는 않습니다. 실제 점유·지면 등 배치 조건에 막히는 자리는 설치하지 않고 다음 위치를 확인합니다. 시설 둘레에 추가 안전 여유 거리를 두지는 않습니다.

드래그 기능은 상부 시설 설치 정책을 바꾸지 않습니다. **Road 위에는 시설을 설치할 수 없고 Tile 위에는 시설을 설치할 수 있습니다.** Tile을 먼저 설치한 뒤 시설을 올리며, Road/Tile끼리 중복 설치할 수는 없습니다.

## 4. 설치가 멈추거나 일부 자리가 비는 이유

각 시설은 한 개씩 실제 설치 검사를 받고, 성공한 시설에 대해서만 설치비가 나갑니다. 마우스를 같은 자리에서 움직이거나 방금 그린 구간을 되짚어도 같은 드래그 안에서 같은 위치를 반복 구매하지 않습니다.

| 상황 | 동작과 이어서 작업하는 방법 |
|---|---|
| 다른 시설·금지 구역·지형 조건에 막힘 | 해당 위치는 건너뜁니다. 원인을 해결한 뒤 버튼을 놓고 다시 시작하면 그 자리를 다시 시도할 수 있습니다. |
| 돈이 부족하거나 설치 개수 한도에 도달 | 현재 드래그를 종료합니다. 조건을 해결한 뒤 새로 눌러 시작합니다. 돈이 나중에 들어와도 자동으로 설치를 재개하지 않습니다. |
| 버튼을 놓음 | 즉시 끝납니다. 아직 처리하지 않은 뒷부분도 취소됩니다. |
| 메뉴나 도구 패널 위로 이동 | 현재 드래그를 끝냅니다. 바닥으로 돌아와 새로 눌러 시작합니다. |
| 게임 창 밖으로 이동하거나 다른 프로그램으로 전환 | 현재 드래그를 끝냅니다. 게임으로 돌아온 뒤 새로 눌러 시작합니다. |
| 일시정지, 시설 종류 변경, 회전, 목록 복귀 | 현재 드래그를 끝냅니다. 이미 성공한 시설은 유지됩니다. |
| 너무 빠르게 오래 그려 처리 한도를 넘음 | 안내를 표시하고 끝냅니다. 짧은 구간으로 나누어 이어 놓습니다. |

처리량을 제한하므로 아주 긴 거리를 빠르게 움직이면 설치가 마우스를 조금 늦게 따라올 수 있습니다. 이때 버튼을 바로 놓으면 아직 설치하지 않은 끝부분은 남겨 두지 않고 취소합니다. 길이 따라온 것을 확인하거나 구간을 나누어 작업하면 됩니다.

드래그 전체를 한 번에 확정하는 방식은 아닙니다. 이미 설치에 성공한 시설은 각각 독립된 시설이므로 중간에 멈춰도 자동으로 되돌리지 않습니다.

## 5. 직접 설정을 바꾼 뒤 확인하기

다음 순서로 짧게 확인하면 설정이 의도대로 적용됐는지 알 수 있습니다.

1. 체크를 켠 시설을 선택하고 빈 공간을 짧게 좌클릭합니다. 한 개가 설치되는지 확인한 뒤, 다른 빈 곳에서는 꾹 누른 채 이동해 여러 개가 이어지는지 확인합니다.
2. 같은 구간을 다시 지나갑니다. 시설 수와 지출이 늘지 않는지 확인합니다.
3. 버튼을 놓고 마우스만 움직입니다. 더 설치되지 않는지 확인합니다.
4. 드래그 중 도구 패널로 이동한 뒤 바닥으로 돌아옵니다. 새로 누르기 전에는 설치가 재개되지 않아야 합니다.
5. 장애물이 있는 곳을 지나갑니다. 겹치는 자리에 시설이 생기지 않는지 확인합니다.
6. 체크를 끄고 시설을 다시 선택합니다. 버튼을 누른 채 움직여도 한 개만 설치되는지 확인합니다.

`Enable Drag Placement` 항목이 아예 없다면 새로운 C++ 코드가 에디터에 반영되지 않은 상태일 수 있습니다. 에디터를 종료하고 프로젝트를 빌드한 뒤 다시 엽니다. 이미 항목이 보이는 상태에서 체크만 변경하는 작업은 C++ 재빌드가 필요하지 않습니다.

## 6. 개발자가 유지보수할 때 볼 내용

입력 기능은 `FF_BuildModeSubsystem`이 관리하고, 실제 설치는 기존 `FF_ZoneSystem`의 설치 명령을 사용합니다. 드래그 경로 계산, 플레이어 입력, 설치 판정을 나누어 관리하므로 배치 규칙이나 비용 처리를 별도로 복제하지 않습니다.

좌클릭을 처음 누르는 순간은 기존 `CommitPlacement` 경로로 처리합니다. 버튼이 계속 눌려 있고 데이터 에셋이 연속 설치를 허용할 때 후속 경로를 시작합니다. 첫 위치는 이미 처리한 위치로 기록하여 설치·차감을 반복하지 않습니다. 실제 버튼·패널과 포인터 입력을 소비하지 않는 전체 화면 HUD를 구분하므로, 장식용 HUD가 떠 있다는 이유로 바닥 클릭을 막지 않습니다.

성능을 위해 1cm마다 설치를 시도하지 않고 시설 크기의 간격으로만 후보를 만듭니다. 이동 중 건너뛴 타일을 보간하고, 같은 위치는 한 드래그에서 한 번만 검사합니다. 프레임당 처리 개수와 시간을 제한하며, 대기 중인 마우스 경로와 방문한 위치 기록에도 상한이 있습니다. 설치 개수만큼 미리보기 액터를 새로 만드는 구조는 아닙니다.

현재 구현은 프레임당 최대 8칸을 처리하며 명령 사이에서 2ms 시간 예산을 확인합니다. 명령 한 개는 도중에 잘라낼 수 없으므로 2ms는 절대 보장이 아닌 분할 기준입니다. 한 드래그의 방문 기록은 4,096칸, 대기 경로는 128개 지점까지 보관합니다. 같은 축을 따라 앞으로 이어지는 입력은 끝점으로 합쳐 빠른 직선 드래그의 대기열 낭비를 줄이고, 꺾임과 되짚기는 그대로 보존합니다.

드래그 중 커서 미리보기 위치는 매 입력 프레임에 반영합니다. 전체 설치 가능 검사는 0.08초 주기를 유지하며, 새 위치를 아직 검사하지 않았을 때는 이전 위치의 초록·빨강 판정을 옮겨 표시하지 않고 중립색으로 보여 줍니다. 위치와 월드가 그대로면 전체 검사는 0.5초 간격으로 제한합니다. 도로 지면 검사는 주변 시설을 우선 조회하고, 도감 조합과 무관한 길 설치는 도감 전체 재계산을 생략합니다.

### 기존 길 에셋에 처음 적용하기

프로젝트를 빌드한 뒤 작업 중인 에디터를 종료하고 프로젝트 폴더의 PowerShell에서 순서대로 실행합니다.

```powershell
& Tools/RoadFacilities/Run-RoadEditor.ps1 -Script Tools/RoadFacilities/enable_drag_placement.py -Label road_drag_enable -SuccessPattern ROAD_DRAG_MIGRATION_PASS
& Tools/RoadFacilities/Run-RoadEditor.ps1 -Script Tools/RoadFacilities/verify_drag_placement.py -Label road_drag_verify -SuccessPattern ROAD_DRAG_VERIFY_PASS
```

첫 명령은 여섯 데이터 에셋을 모두 확인한 다음 설정을 적용합니다. 저장 전에 패키지를 백업하고 실패하면 복원합니다. 한 번 적용한 기록을 남기므로 같은 명령을 다시 실행해도 제작자가 나중에 끈 설정을 강제로 켜지 않습니다. 이미 적용한 길의 값을 다시 바꾸려면 에디터에서 체크박스를 직접 편집합니다.

두 번째 명령은 과거 드래그 기능 최초 납품 때 사용한 확인이며, 이후 작성한 설정이나 Road/Tile 분리로 Spec이 바뀌면 이전 보고서와 다를 수 있습니다. Road/Tile 분리 후 12종의 현재 저장값은 `README.md`의 `split_road_tiles.py` → `verify_road_tiles.py` 절차로 확인합니다. `verify_roads.py`는 이 새 검증과 원본 메시 검사를 함께 실행합니다.

새 길을 임포트하는 `import_roads.py`는 처음 생성하는 데이터 에셋에만 드래그를 켭니다. 기존 에셋을 다시 임포트할 때는 제작자가 정한 체크 값을 보존합니다.
