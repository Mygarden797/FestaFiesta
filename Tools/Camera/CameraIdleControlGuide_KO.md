# 관찰 카메라 대기 고정 가이드

문서 기준: 2026-09-28 · FestaFiesta · Unreal Engine 5.7

## 1. 무엇이 달라지나요?

축제장을 내려다보는 관찰 카메라가 **사용자의 조작이 끝나면 마지막 구도를 유지**하도록 바뀝니다. 구도란 화면에서 보고 있는 위치, 바라보는 각도, 확대 정도를 말합니다.

이전에는 바닥 높이와 이동 목표를 계속 따라갔습니다. 그래서 조작을 끝내도 남은 이동이 이어지거나 바닥 높이 보정 때문에 구도가 달라질 수 있었습니다. 이제 카메라는 “조작 중”, “요청한 짧은 전환을 마무리하는 중”, “대기 중”을 구분합니다. 대기 중에는 지면 높이를 따라 화면을 움직이지 않습니다.

| 상황 | 이전 | 변경 후 |
| --- | --- | --- |
| 이동·회전 키에서 손을 뗌 | 남은 목표까지 조금 더 움직일 수 있음 | 현재 위치와 각도에서 멈춤 |
| 아무 조작 없이 기다림 | 바닥 높이 보정이 계속 실행됨 | 위치·각도·확대 정도 유지 |
| 마우스 휠을 한 칸 돌림 | 확대와 각도 변화가 부드럽게 진행됨 | 요청한 확대와 각도 변화를 마친 뒤 고정 |
| 초기 구도 복원·일정 각도 회전·특정 위치 보기 | 목표 구도를 향해 이동 | 요청한 전환을 마친 뒤 고정 |
| 커서만 화면 가장자리에 둠 | 계속 이동할 수 있음 | 움직이지 않음. 기본 설정에서는 마우스 휠 버튼을 누르고 있어야 이동 |
| 높은 지형 쪽으로 이동 | 지면 높이에 맞춰 보정 | 이동하는 동안 필요한 보정 수행 |
| 특정 대상을 계속 따라보기 | 대상 이동에 따라 카메라도 이동 | 명시적으로 켠 추적 기능은 계속 동작 |

**휠을 놓은 바로 그 순간 모든 움직임이 끊기는 방식은 아닙니다.** 휠 한 칸은 “이 정도 확대해 주세요”라는 한 번의 요청이므로, 그 요청으로 시작한 짧은 전환까지 마친 후 멈춥니다. 반면 키를 누르는 동안 이동하거나 회전하는 조작은 손을 떼면 멈춥니다.

## 2. 확대하면 시야가 바뀌는 기능은 유지됩니다

가까이 확대하면 시설과 사람을 조금 더 옆에서 바라보고, 멀리 축소하면 위에서 내려다보는 기존 변화가 유지됩니다. 이 각도 변화는 확대 정도에 연결되어 있습니다.

커서 쪽으로 확대하는 기능도 유지됩니다. 예를 들어 화면 오른쪽의 시설에 커서를 두고 확대하면 그쪽을 중심으로 더 가까이 볼 수 있습니다. 커서 방향 확대 설정이 꺼져 있거나 기준점을 구하지 못하면 화면 중앙을 기준으로 확대합니다.

기술적으로 커서의 기준점은 실제 시설 지붕이 아니라 현재 초점 높이의 가상 수평면입니다. 따라서 “지붕의 정확한 한 점이 화면에서 한 픽셀도 움직이지 않는다”는 의미는 아닙니다.

## 3. 멈추지 않는 것처럼 보일 때

- **휠 확대·구도 복원 직후:** 사용자가 요청한 짧은 전환이 마무리 중인지 확인합니다. 전환이 끝난 뒤에는 계속 움직이지 않아야 합니다.
- **대상 따라보기 중:** 추적은 대상을 계속 보라는 별도 요청입니다. 추적을 끝내거나 직접 이동하면 일반 관찰 상태로 돌아갑니다.
- **다른 캐릭터 시점·피날레 연출:** 이 문서의 대기 고정은 축제 관찰 카메라에 적용됩니다. 캐릭터 자체의 시점이나 연출 카메라는 각 기능의 규칙을 따릅니다.
- **지형이 바뀐 뒤 다시 조작:** 대기 중 멈췄던 높이 보정을 다시 수행하므로 화면 높이가 움직일 수 있습니다. 대기 중에 자동으로 따라가는 것은 아닙니다.
- **에디터에서 조작이 안 됨:** 게임 화면 대신 다른 패널에 입력 초점이 있을 수 있습니다. 게임 화면을 다시 클릭한 뒤 조작합니다.

화면 가장자리로 이동하려면 **마우스 휠 버튼을 누른 채 커서를 화면 위쪽이나 좌우 가장자리로 가져갑니다.** 버튼에서 손을 떼면 멈춥니다. 화면 아래쪽의 기존 UI 보호 구간은 그대로 유지됩니다. 프로젝트 담당자가 활성화 키를 변경한 경우 해당 설정을 따릅니다.

게임을 시작할 때는 한 번 초기 구도를 잡고 지면 높이를 맞춥니다. 이것은 플레이 중 대기 상태에서 자동으로 화면이 움직이는 것과 구분합니다.

## 4. 비전공자가 확인하는 방법

게임의 관찰 시점에서 아래 순서대로 확인합니다. “가만히 둔다”는 모든 이동·회전 키와 마우스 버튼에서 손을 뗀 상태를 뜻합니다.

| 순서 | 해볼 일 | 정상 결과 |
| --- | --- | --- |
| 1 | 이동 키를 눌렀다가 놓고 5초 기다리기 | 손을 뗀 뒤 화면이 밀리지 않음 |
| 2 | 회전 키를 눌렀다가 놓고 5초 기다리기 | 손을 뗀 뒤 화면이 더 돌지 않음 |
| 3 | 화면 한쪽 시설에 커서를 두고 휠 한 칸 확대 | 확대하며 각도가 바뀌고, 짧은 전환 뒤 멈춤 |
| 4 | 같은 상태에서 5초 기다리기 | 위치·각도·확대 정도가 유지됨 |
| 5 | 휠을 반대로 돌려 축소 | 기존처럼 더 위에서 바라보는 구도로 전환됨 |
| 6 | 초기 구도 복원 실행 | 처음 구도로 돌아간 뒤 멈춤 |
| 7 | 이동하다가 메뉴를 열거나 다른 창으로 전환 | 보이지 않는 동안 관찰 카메라가 계속 이동하지 않음 |
| 8 | 다시 게임으로 돌아와 이동 | 이전에 남아 있던 목표로 갑자기 끌려가지 않음 |
| 9 | 시설 배치 중 이동·확대와 시설 회전 확인 | 이동·확대가 가능하고 시설 회전 입력이 카메라를 함께 돌리지 않음 |
| 10 | 버튼을 누르지 않고 커서만 위·좌우 가장자리에 두기 | 화면이 움직이지 않음 |
| 11 | 휠 버튼을 누른 채 가장자리에 두었다가 버튼 놓기 | 누르는 동안만 이동하고 놓으면 멈춤 |
| 12 | 확대하면서 이동 키를 눌렀다가 먼저 놓기 | 키 이동은 멈추고 요청한 확대·각도 전환은 마무리됨 |

높낮이가 있는 맵에서도 1~5번을 반복합니다. 특히 경사에서 멈췄다가 다시 움직일 때 구도가 갑자기 튀지 않는지 확인합니다.

## 5. 기존 카메라 담당자에게 전달할 내용

아래 내용은 인계할 수 있도록 정리한 메모입니다. 별도 메신저로 발송한 것은 아닙니다.

> 관찰 카메라의 기본 정책을 대기 중 구도 고정으로 변경했습니다. 연속 이동·회전은 입력 종료 시 현재 표시 상태에서 멈추고, 휠 확대·스냅 회전·구도 복원·포커스 이동은 요청한 전환을 마친 뒤 대기로 돌아갑니다. 대기 중 지면 추종은 중단하지만, 조작 중 지면 보정과 줌에 따른 피치 변화, 커서 방향 확대, Zone 이동 경계는 유지합니다. 가장자리 이동은 기본적으로 휠 버튼을 누르는 동안만 동작하도록 바뀌었습니다. 명시적 대상 추적은 별도 기능으로 유지됩니다. 기존 블루프린트가 매 프레임 이동·포커스 API를 호출하거나 SpringArm의 자체 지연 기능을 켠 경우 대기 고정 정책과 충돌할 수 있으므로 함께 확인해 주세요.

여기서 보간은 현재 값에서 목표 값으로 조금씩 가까워져 부드럽게 움직이게 하는 계산입니다.

### 새 상태와 연결 지점

`AFF_OverviewCameraPawn::GetMotionState()`로 현재 동작을 확인할 수 있습니다. 상태는 Pawn Tick에서 갱신되므로 입력 함수를 호출한 즉시가 아니라 해당 프레임의 갱신 이후 값을 기준으로 진단합니다.

| `EFF_OverviewCameraMotionState` | 의미 |
| --- | --- |
| `Idle` | 표시 구도를 고정한 대기 상태 |
| `DirectInput` | 키 이동·키 회전·버튼을 누른 가장자리 이동 처리 중 |
| `Transition` | 한 번 요청한 확대·스냅·포커스·복원 전환을 마무리 중 |
| `Following` | `SetFollowTarget`으로 명시적으로 요청한 대상 추적 중 |

외부 UI·연출 코드가 관찰 카메라의 움직임을 취소해야 한다면 `StopCameraMotion()`을 사용합니다. 이 함수는 쌓인 입력, 진행 중 전환, 대상 추적을 함께 취소하고 현재 표시 구도를 유지합니다. UI를 닫아도 취소한 추적이 자동으로 재시작되는 정책은 아니므로, 제품 요구사항상 재추적이 필요하면 다시 명시적으로 요청합니다.

Controller는 모달 UI 활성화, 관찰 시점 이탈·복귀, 연출 진입·종료, 눌린 키 초기화(`FlushPressedKeys`), 게임 화면 포커스 상실 시 공통 정지 경로를 호출합니다. `InactiveViewport` 입력 차단 사유가 추가되었으며 기존 enum 값이 바뀌지 않도록 끝에 추가했습니다. PIE에서 다른 에디터 패널을 클릭하면 관찰 조작이 멈추는 것도 의도한 동작입니다.

Rig의 `HoldChannels`, `SnapChannelsToTarget`, `HasReachedTarget`은 위치·회전·줌 항목을 따로 종료하기 위한 계산 함수입니다. 이동 키를 놓았다고 동시에 진행하던 휠 확대까지 취소하지 않도록 항목을 나눕니다. 기존 입력 함수의 이름과 호출 방식은 유지합니다.

C++ Rig의 `Zoom`과 `ZoomTowards`는 실제 확대 거리가 바뀌었는지를 `bool`로 반환하도록 변경했습니다. 최소·최대 거리에서 더 확대·축소하려는 입력으로 불필요한 전환을 시작하지 않기 위한 값입니다. 기존 호출부가 반환값을 사용하지 않아도 호출할 수 있으며, Pawn의 블루프린트 입력 함수 시그니처는 유지합니다.

일회성 전환은 요청 시 얻은 지면 높이를 저장하고 그 높이를 향해 보정합니다. 전환 중 바닥을 매번 새로 추적해 목표가 계속 바뀌지 않게 합니다. 키 이동과 명시적 대상 추적 중에는 새 위치의 지면을 계속 확인합니다. 잔여 차이가 위치·거리 0.1cm, 각도 0.01도 이내이면 해당 항목을 목표에 정확히 맞추고 전환을 끝냅니다.

초기 배치 때 한 번 지면과 경계를 정리합니다. 로딩이 늦어 Zone 경계가 그 이후에 준비되면 다음 카메라 조작에서 적용하며, 대기 화면을 움직여 뒤늦게 경계에 맞추지 않습니다.

개발용 콘솔 명령 `FF.Camera.RefreshBounds`는 명시적인 경계 갱신 요청입니다. 다음 Tick에서 전환을 시작해 경계를 적용한 뒤 다시 대기하므로, 이 명령 직후의 움직임은 일반 대기 중 자동 보정과 구분합니다.

### 유지해야 할 규칙

1. 대기 상태에서는 지면 추종이나 잔여 보간 때문에 표시 구도가 바뀌지 않아야 합니다.
2. 정지할 때 표시 상태와 남은 목표를 함께 정리합니다. 화면만 멈추고 과거 목표를 남겨두면 다음 입력에서 튈 수 있습니다.
3. 휠·스냅·복원·포커스처럼 한 번의 요청으로 시작한 전환에는 완료 조건이 있어야 합니다. 목표에 끝없이 가까워지는 상태로 남기지 않습니다.
4. 커서 확대와 줌 피치 계산을 별도 블루프린트 Tick에서 다시 구현하지 않습니다. 기존 Rig의 계산 경로를 사용합니다.
5. 입력 차단이나 시점 전환으로 관찰 조작을 끝낼 때는 공통 정지 경로를 사용합니다. 키 입력 변수만 지우고 진행 중 전환을 남기지 않습니다.
6. 대상 추적은 명시적 기능입니다. 일반 대기 고정과 구분하고 종료 시 남은 추적 목표도 정리합니다.

### 블루프린트와 설정 확인

블루프린트는 에디터에서 노드를 연결해 만드는 게임 로직입니다. C++의 기본값을 바꿔도 블루프린트나 레벨에 따로 저장해 둔 값은 그대로 남을 수 있습니다. 실제로 사용하는 카메라 클래스와 레벨 인스턴스의 값을 확인해야 합니다.

이번에는 에디터에 노출되는 enum·함수·속성이 추가되었습니다. 인계받은 코드는 **에디터를 닫고 Editor 타깃을 정상 빌드한 뒤 에디터를 다시 열어** 적용합니다. Live Coding만으로 반영됐다고 판단하지 않습니다. 아래 검증 스크립트에도 Editor 빌드 단계가 포함되어 있습니다.

- `bFollowGroundHeight`: 지면 높이 보정 사용 여부입니다. 켜져 있어도 대기 중에 계속 추종한다는 뜻은 아닙니다.
- `GroundFollowSpeed`, `GroundMaxClimbSpeed`: 조작 중 높이 보정의 속도에 관련됩니다. 멈춤 여부를 해결하려고 이 값을 0으로 만드는 방식은 사용하지 않습니다.
- `PitchAtMinZoom`, `PitchAtMaxZoom`, `PitchSaturationArmLength`: 확대에 따른 시야 각도를 결정하는 기존 설정입니다.
- `bZoomToCursor`, `ZoomToCursorStrength`: 커서 방향 확대의 사용 여부와 강도입니다.
- `InterpSpeed`, `ZoomInterpSpeed`: 전환 속도입니다. 대기 고정 정책을 대신하는 설정은 아닙니다.
- Controller의 `EdgeScrollActivationKey`: 가장자리 이동을 허용하는 키이며 기본값은 `MiddleMouseButton`입니다. 키를 미지정하면 가장자리 이동이 꺼집니다. 기존의 `bEnableEdgeScroll`, 속도, 여백, 하단 보호 구간 설정도 계속 적용됩니다. 키 설정 UI에서 자동 재지정되는 액션으로 새로 등록한 것은 아니므로 담당자가 Controller 기본값을 확인합니다.
- `CameraBoom`의 `bEnableCameraLag`, `bEnableCameraRotationLag`는 꺼 둡니다. Rig 외에 별도 지연을 추가하면 Rig가 멈춰도 화면은 더 움직일 수 있습니다.
- `CameraBoom`의 `bDoCollisionTest`와 회전 상속 설정을 임의로 켜거나, 블루프린트 Tick에서 Transform·SpringArm 길이를 직접 바꾸지 않습니다. 카메라 상태의 주인이 둘이 되면 고정 정책을 보장할 수 없습니다.
- `FocusOnLocation`, `InitializeOverview`, `ResetView`를 어디서 호출하는지 확인합니다. 매 프레임 호출하면 매번 새 명령이 들어오는 것이므로 일반 대기로 보지 않습니다. `SetFollowTarget`을 호출하는 경로도 확인해 의도치 않은 추적이 남지 않게 합니다.

이번 변경은 카메라가 모든 지형·건물 충돌을 피하도록 만드는 기능은 아닙니다. 대기 중 바닥이 움직이거나 솟아도 구도 고정을 우선하므로, 동적으로 변하는 지형을 사용하는 맵은 해당 장면을 따로 확인합니다.

## 6. 개발자 검증 실행 방법

프로젝트 루트에서 PowerShell로 실행합니다. 아래 스크립트는 Development Editor를 빌드한 뒤 카메라 자동화 테스트를 실행합니다. 엔진 경로는 PC 환경에 맞게 바꿉니다.

```powershell
& ./Tools/Build/Run-AutomationTests.ps1 `
  -EngineRoot 'C:\Unreal\UE_5.7' `
  -TestFilter 'FestaFiesta.Camera' `
  -SkipDataValidation `
  -OutputRoot './Artifacts/Validation/CameraIdleControl'
```

이 명령의 `-SkipDataValidation`은 이번 카메라 코드의 집중 검사를 위한 선택입니다. 프로젝트 전체 데이터·패키지 검증 완료를 뜻하지 않습니다. 자동화 실행은 화면 렌더링 없는 방식이므로 실제 마우스 조작과 시야 전환의 감각은 4장의 수동 확인이 필요합니다.
